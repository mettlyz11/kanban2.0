### 3.3 加速比趋势分析

```
加速比曲线拟合公式 (Amdahl定律)：
S(N) = 1 / (f_serial + (1-f_serial)/N)

其中 f_serial 为串行部分比例：
- M1 (小体系): f_serial ≈ 0.156
- M2 (中体系): f_serial ≈ 0.054
- M3 (大体系): f_serial ≈ 0.030
```

**关键发现：**
- 小体系 (M1) 在超过8核后加速比趋于饱和，受限于问题规模小导致通信开销占比过高
- 中等体系 (M2) 可有效扩展到24核，效率保持在60%以上
- 大体系 (M3) 具有良好的可扩展性，48核时仍保持69%的并行效率
- 所有体系在超过32核后，并行效率均开始显著下降

## 4. CPU/内存/IO资源监控与瓶颈定位

### 4.1 监控工具与配置

使用 `perf` 和 `dstat` 进行实时监控：

```bash
# 监控脚本 monitor.sh
#!/bin/bash
OUTDIR="/lustre/scratch/benchmark/monitor_$(date +%Y%m%d_%H%M%S)"
mkdir -p $OUTDIR

# CPU使用率监控 (每5秒采样)
dstat -c -C 0,1,2,3,4,5,6,7 --output $OUTDIR/cpu_util.csv 5 &

# 内存监控
dstat -m --output $OUTDIR/memory.csv 5 &

# 磁盘I/O监控
dstat -d --output $OUTDIR/disk_io.csv 5 &

# NUMA感知监控
numastat -p $(pgrep orca) > $OUTDIR/numa_stats.txt 2>&1

# 采集MPI通信事件
mpiP -o $OUTDIR/mpip_report.txt &
```
