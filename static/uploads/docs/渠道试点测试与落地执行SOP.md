## 1. 试点阶段目标与预算分配策略

### 1.1 阶段目标分解

**核心目标**：在30天内完成3个候选渠道（A：社交媒体信息流广告，B：垂直行业KOL合作，C：搜索引擎SEM）的小规模测试，获取至少200个有效转化样本，确定最优渠道组合。

**量化里程碑**：
- 第1-7天：完成渠道对接与测试素材准备，各渠道启动投放
- 第8-21天：稳定运行期，每日追踪关键指标
- 第22-28天：数据汇总与统计分析
- 第29-30天：决策闸门评审与最终定稿

### 1.2 预算分配策略

**总预算**：¥150,000（含测试与应急储备）

| 渠道 | 测试预算 | 占比 | 单用户成本上限 | 预期转化数 |
|------|----------|------|----------------|------------|
| 渠道A：信息流广告 | ¥60,000 | 40% | ¥300/转化 | ≥200 |
| 渠道B：KOL合作 | ¥50,000 | 33% | ¥500/转化 | ≥100 |
| 渠道C：SEM | ¥30,000 | 20% | ¥200/转化 | ≥150 |
| 应急储备金 | ¥10,000 | 7% | - | - |

**预算分配规则**：
- 每日预算上限：渠道A ¥2,000/天，渠道B ¥1,500/天（按KOL档期），渠道C ¥1,000/天
- 预算调整触发条件：若某渠道连续3天ROI低于阈值的80%，启动预算再分配
- 扩量标准：渠道ROI达到阈值的120%且单日转化数≥20，次日预算上浮50%

### 1.3 测试设计原则

采用**A/B测试框架**，每个渠道设置2-3个变量组：
- 渠道A：3组素材创意（A1：功能型，A2：情感型，A3：利益型）
- 渠道B：2个KOL（B1：行业专家型，B2：生活场景型）
- 渠道C：3组关键词策略（C1：品牌词，C2：通用词，C3：长尾词）

## 3. 核心KPI埋点方案与数据看板配置指南

### 3.1 埋点方案设计

#### 3.1.1 埋点事件定义

**通用事件**（所有渠道通用）：

| 事件ID | 事件名称 | 触发条件 | 参数 |
|--------|----------|----------|------|
| page_view | 页面浏览 | 落地页加载完成 | page_id, utm_source, utm_medium, utm_campaign |
| form_start | 表单开始填写 | 用户点击第一个输入框 | form_id, page_id |
| form_submit | 表单提交 | 用户点击提交按钮 | form_id, page_id, submit_success |
| lead_qualified | 有效线索 | 客服初筛通过 | lead_id, source_channel |
| deal_closed | 成交 | 合同签署/支付完成 | deal_id, amount, source_channel |

**渠道特定事件**：

| 渠道 | 事件ID | 事件名称 | 触发条件 |
|------|--------|----------|----------|
| A | ad_impression | 广告曝光 | 信息流广告展示 |
| A | ad_click | 广告点击 | 用户点击广告素材 |
| B | kol_content_view | KOL内容浏览 | 用户观看KOL内容≥3秒 |
| B | kol_link_click | KOL链接点击 | 用户点击KOL内容中的链接 |
| C | search_query | 搜索查询 | 用户发起搜索 |
| C | ad_impression_sem | SEM广告展示 | 搜索广告展示 |

#### 3.1.2 埋点代码示例（JavaScript + Google Tag Manager）

```javascript
// 通用埋点函数
function trackEvent(eventId, eventParams) {
  // 检查GTM是否加载
  if (typeof dataLayer !== 'undefined') {
    dataLayer.push({
      'event': eventId,
      'eventCategory': '渠道测试',
      'eventLabel': eventParams.utm_source || 'unknown',
      'eventValue': eventParams.value || 0,
      ...eventParams
    });
  } else {
    // 降级方案：使用Beacon API
    const payload = {
      event_id: eventId,
      timestamp: new Date().toISOString(),
      page_url: window.location.href,
      user_agent: navigator.userAgent,
      ...eventParams
    };
    navigator.sendBeacon('/api/track', JSON.stringify(payload));
  }
}

// 页面浏览事件
document.addEventListener('DOMContentLoaded', function() {
  const urlParams = new URLSearchParams(window.location.search);
  trackEvent('page_view', {
    utm_source: urlParams.get('utm_source'),
    utm_medium: urlParams.get('utm_medium'),
    utm_campaign: urlParams.get('utm_campaign'),
    page_id: document.querySelector('meta[name="page-id"]')?.content || 'default'
  });
});

// 表单提交事件
document.querySelectorAll('form').forEach(form => {
  form.addEventListener('submit', function(e) {
    trackEvent('form_submit', {
      form_id: this.id,
      submit_success: true,
      utm_source: new URLSearchParams(window.location.search).get('utm_source')
    });
  });
});
```

#### 3.2.2 看板技术配置

**工具选择**：Metabase + MySQL 数据库

**SQL查询示例**（渠道A效果汇总）：

```sql
SELECT 
  DATE(ad_impression.timestamp) AS report_date,
  COUNT(DISTINCT ad_impression.user_id) AS unique_impressions,
  COUNT(DISTINCT ad_click.user_id) AS unique_clicks,
  COUNT(DISTINCT ad_click.user_id) / NULLIF(COUNT(DISTINCT ad_impression.user_id), 0) AS ctr,
  COUNT(DISTINCT form_submit.user_id) AS form_submits,
  COUNT(DISTINCT form_submit.user_id) / NULLIF(COUNT(DISTINCT ad_click.user_id), 0) AS cvr,
  SUM(ad_spend.cost) AS total_cost,
  SUM(ad_spend.cost) / NULLIF(COUNT(DISTINCT form_submit.user_id), 0) AS cpa,
  SUM(revenue.amount) AS total_revenue,
  SUM(revenue.amount) / NULLIF(SUM(ad_spend.cost), 0) AS roi
FROM ad_impression
LEFT JOIN ad_click ON ad_impression.session_id = ad_click.session_id
LEFT JOIN form_submit ON ad_click.session_id = form_submit.session_id
LEFT JOIN ad_spend ON ad_impression.date = ad_spend.date
LEFT JOIN revenue ON form_submit.lead_id = revenue.lead_id
WHERE ad_impression.channel = 'A'
  AND ad_impression.timestamp >= NOW() - INTERVAL 7 DAY
GROUP BY report_date
ORDER BY report_date;
```

**看板刷新频率**：
- 实时指标（曝光、点击、消耗）：每5分钟刷新
- 转化类指标（表单提交、有效线索）：每30分钟刷新
- 财务类指标（ROI、CPA）：每日凌晨自动计算

## 4. 决策闸门设计（Go/No-Go/Pivot判定标准）

### 4.1 决策框架

采用**三阶决策模型**，每个渠道独立评估：

#### 4.1.1 第一阶：数据有效性检查（D28上午）

| 检查项 | 通过标准 | 不通过处理 |
|--------|----------|------------|
| 测试样本量 | 每个变量组≥30个有效转化 | 延长测试期3天，若仍不足则标记为No-Go |
| 数据完整性 | 埋点数据缺失率<5% | 数据修复后重新计算 |
| 统计显著性 | 渠道间差异p值<0.05 | 进行贝叶斯分析，使用后验概率决策 |
| 异常数据排除 | 无系统级异常（如服务器宕机） | 剔除异常时段数据后重新分析 |

#### 4.1.2 第二阶：核心指标评估（D28下午）

**渠道A评估矩阵**：

| 指标 | 权重 | Go标准 | No-Go标准 | Pivot标准 |
|------|------|--------|------------|-----------|
| ROI | 40% | ≥1.8x | <1.0x | 1.0x-1.79x |
| 单用户成本 | 25% | ≤¥250 | >¥400 | ¥251-¥400 |
| 转化率 | 20% | ≥5.5% | <3.0% | 3.0%-5.4% |
| 可扩展性 | 15% | 日预算可提升≥3倍 | 日预算提升<1.5倍 | 1.5倍-2.9倍 |

**渠道B评估矩阵**：

| 指标 | 权重 | Go标准 | No-Go标准 | Pivot标准 |
|------|------|--------|------------|-----------|
| ROI | 40% | ≥1.5x | <0.8x | 0.8x-1.49x |
| 单用户成本 | 25% | ≤¥400 | >¥600 | ¥401-¥600 |
| 内容质量分 | 20% | KOL互动率≥5% | 互动率<2% | 2%-4.9% |
| 品牌安全性 | 15% | 无负面舆情 | 出现1次以上负面 | 有潜在风险 |

**渠道C评估矩阵**：

#### 4.1.3 第三阶：组合优化决策（D29）

**决策规则**：

| 组合情况 | 最终决策 | 行动方案 |
|----------|----------|----------|
| 2个及以上Go | 扩量 | 将总预算的70%分配给Go渠道，30%继续优化Pivot渠道 |
| 1个Go + 1个Pivot | 混合策略 | Go渠道扩量至60%预算，Pivot渠道投入20%预算优化，剩余20%探索新渠道 |
| 1个Go + 2个No-Go | 集中资源 | Go渠道获得80%预算，20%预算用于快速验证2个备选渠道 |
| 3个Pivot | 延期决策 | 延长测试期7天，调整变量组设计 |
| 2个及以上No-Go | 策略调整 | 停止测试，启动渠道选型重评估流程 |
