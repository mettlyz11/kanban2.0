# 权责矩阵表：人员岗位职责文档 [04291819]

## 1. 矩阵使用规范与RACI定义说明

### 1.1 目的与适用范围
本权责矩阵表旨在将组织内各岗位的文本化职责转化为可量化、可追溯的结构化协作工具。适用于公司所有跨部门、跨岗位的核心业务流程，涵盖产品研发、市场销售、供应链管理、财务风控及人力资源五大业务域。所有在册正式员工、项目制人员及外包服务商均须遵守本矩阵所定义的权责分配。

### 1.2 RACI角色定义标准

| 角色代码 | 英文全称 | 中文定义 | 核心权责说明 |
|---------|---------|---------|------------|
| R | Responsible | 执行人 | 实际完成工作任务，对过程质量直接负责。每个活动必须有且仅有一个R，可多人协作但由R协调。 |
| A | Accountable | 审批人/最终责任人 | 对任务结果承担最终责任，拥有否决权和签字权。每个活动有且仅有一个A，通常为R的上级管理者。 |
| C | Consulted | 咨询人 | 在决策或执行前必须征询意见的岗位，提供专业建议。C的意见需被记录但可不必然采纳。 |
| I | Informed | 知情人 | 任务完成后必须被告知结果的岗位，无需主动参与过程。I仅接收信息，不承担决策责任。 |

### 1.3 矩阵使用规范

- **唯一性规则**：每个活动节点必须且只能有一个A角色，R角色可以有一个或多个，但需指定主R。
- **升级机制**：当A角色无法在约定时限（T+2工作日）内做出决策时，自动升级至A的上级管理者，原A降为C角色。
- **争议仲裁**：跨部门RACI冲突时，由流程归属部门的A角色发起仲裁会议，CEO办公室担任最终仲裁方。
- **动态调整**：本矩阵每季度由运营管理部组织评审，调整需经管理层会议2/3以上成员同意方可生效。

### 1.4 绩效关联规则
每个R角色的绩效工资中30%与该活动的关键绩效指标（KPI）挂钩；A角色承担连带责任，若R的KPI未达标，A的绩效系数扣减0.1。具体权重配置详见第五章节。

### 3.7 跨部门关键协作节点说明

1. **PRD-01需求评审**：PM为A/R角色，但必须获得MKT和SAL的C角色输入，若MKT/SAL未在5个工作日内提供书面意见，视为自动放弃C角色权利。
2. **MKT-05合同签订与回款**：SAL为A角色，但FIN为R角色负责收款操作。若合同金额超过50万元，需CFO承担C角色进行财务风险审核。
3. **SCM-03采购合同签订**：SCM为A角色，但FIN必须作为R角色审核付款条款。若合同金额超过20万元，需CFO承担C角色。
4. **FIN-01预算编制**：FIN为A/R角色，但CEO和CFO同时担任A角色，意味着任何预算调整必须获得CEO和CFO的双重签字批准。
