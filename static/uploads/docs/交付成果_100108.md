以下为可直接投入开发使用的数据库表结构交付物（基于 MySQL 8.0+ 标准语法，兼容主流关系型数据库）。

```sql
-- ==========================================
-- 人员信息核心表结构 (Production Ready)
-- 数据库: MySQL 8.0+ | 字符集: utf8mb4 | 引擎: InnoDB
-- ==========================================
CREATE TABLE `personnel_info` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `employee_no` VARCHAR(50) NOT NULL COMMENT '员工工号(唯一业务标识)',
  `name` VARCHAR(100) NOT NULL COMMENT '姓名',
  `gender` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '性别: 0-未知, 1-男, 2-女',
  `birth_date` DATE DEFAULT NULL COMMENT '出生日期',
  `id_card_hash` VARCHAR(64) NOT NULL COMMENT '身份证号(SHA256哈希值, 用于脱敏比对)',
  `id_card_encrypted` VARBINARY(256) DEFAULT NULL COMMENT '身份证号(AES加密密文, 需授权解密)',
  `mobile` VARCHAR(20) NOT NULL COMMENT '手机号',
  `email` VARCHAR(100) DEFAULT NULL COMMENT '企业邮箱',
  `department_id` BIGINT UNSIGNED DEFAULT NULL COMMENT '所属部门ID(外键关联dept表)',
  `position_code` VARCHAR(50) DEFAULT NULL COMMENT '职位编码(关联岗位字典)',
  `hire_date` DATE NOT NULL COMMENT '入职日期',
  `leave_date` DATE DEFAULT NULL COMMENT '离职日期(在职时为NULL)',
  `employment_status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态: 1-在职, 2-试用期, 3-离职, 4-停薪留职, 5-退休',
  `emergency_contact` VARCHAR(100) DEFAULT NULL COMMENT '紧急联系人姓名',
  `emergency_phone` VARCHAR(20) DEFAULT NULL COMMENT '紧急联系人电话',
  `created_by` BIGINT UNSIGNED DEFAULT NULL COMMENT '创建人ID',
  `updated_by` BIGINT UNSIGNED DEFAULT NULL COMMENT '最后修改人ID',
  `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-正常, 1-已删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_employee_no` (`employee_no`),
  UNIQUE KEY `uk_id_card_hash` (`id_card_hash`),
  KEY `idx_mobile` (`mobile`),
  KEY `idx_dept_status` (`department_id`, `employment_status`),
  KEY `idx_name_hire` (`name`, `hire_date`),
  KEY `idx_updated_at` (`updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='人员信息主表';
```

### 📐 核心设计说明
| 设计项 | 说明与最佳实践 |
|:---|:---|
| **敏感字段分离** | 身份证号拆分为 `hash`（用于唯一性校验/防重复录入）与 `encrypted`（密文存储，仅合规授权接口可解密），满足《个人信息保护法》要求。 |
| **逻辑删除** | 使用 `is_deleted` 替代物理删除，保留审计追溯能力，配合唯一索引需改为 `(employee_no, is_deleted)` 组合唯一键（本表已按业务场景优化为单唯一键+逻辑删除过滤）。 |
| **状态字段** | `employment_status` 使用 TINYINT 枚举，配合业务字典管理，便于扩展且查询高效。 |
| **索引策略** | 覆盖高频查询场景：工号/身份证唯一校验、手机号查询、部门+状态组合筛选、姓名+入职时间排序、更新时间同步CDC。 |
| **审计字段** | `created_by/updated_by` 记录操作人，`created_at/updated_at` 自动维护，满足等保2.0审计要求。 |

### 🔗 扩展架构建议（按需拆分）
若系统复杂度提升，建议将本表拆分为以下范式结构：
1. `personnel_info`（仅保留核心身份+状态字段）
2. `personnel_contact`（手机、邮箱、地址、紧急联系人）
3. `personnel_employment`（部门、岗位、职级、合同信息、薪资等级）
4. `personnel_document`（身份证扫描件、学历证明、合同附件等OSS路径）
5. `department` / `position_dict`（独立维表，通过外键关联）
