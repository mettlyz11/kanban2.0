## 🔴 最高优先级 - 安全红线

### 1. 子代理执行后必须更新数据库状态 (2026-04-21)
**根本原因：** 子代理执行了任务，但忘记更新数据库 → 任务永远卡在 `in_progress` → 调度器不断启动新子代理处理同一任务。

**执行标准（必须严格遵守）：**
任务完成后必须使用以下SQL更新数据库：
```python
python3 -c "
import pymysql
conn = pymysql.connect(host='...', user='kanban', password='...', database='kanban', charset='utf8mb4')
c = conn.cursor()
c.execute('UPDATE tasks SET status=%s, execution_log=%s, result_summary=%s, task_summary=%s, updated_at=NOW() WHERE id=%s',
    ('completed', execution_log_text, result_summary_text, task_summary_text, task_id))
conn.commit()
conn.close()
"
```

**自检清单（每项都必须满足）：**
- [ ] 是否真正执行了任务要求的工作？
- [ ] execution_log 是否详细记录了执行过程？(≥200字)
- [ ] result_summary 是否总结了核心成果？(≥50字)
- [ ] 两项都满足？→ 才能标记 completed
- [ ] 产出文件是否已保存到正确路径？
- [ ] 数据库是否已更新为 completed？

**此规则永久生效，永不遗忘。**

## 🧠 任务执行与数据库管理

### 2. Research 驱动原则 (2026-04-18)
**核心原则：**
- ✅ 能用 Research 的地方 → 必须用 Research
- ✅ 不管 Research 是否有结果 → 都要 Research
- ✅ Research 后 → 用 High Thinking 模式思考
- ❌ 仅凭内置知识做决策
- ❌ 跳过 Research 直接设计
- ❌ 认为"这个我知道"就不 Research

**必须 Research 的场景：**
- Superpowers Brainstorm → 搜索类似问题的解决方案
- 产生新任务 → 搜索任务的最佳实践
- 分析项目目标 → 搜索行业标准和方案
- 拆解人生目标 → 搜索实现路径
- 技术选型 → 搜索技术对比
- 碰到问题 → 搜索解决方案
- 评估成果 → 搜索评估标准

**执行流程：**
```
遇到问题/需要决策
    ↓
🔍 Research（Tavily Search）
    ↓
🧠 High Thinking 分析 Research 结果
    ↓
💡 生成方案/决策
    ↓
✅ 执行
```

### 3. V4.2 LLM深度推理驱动任务生成原则 (2026-04-19)
**核心原则：** LLM + 深度推理 + Tavily Search 优先，不惜时间/金钱，只追求任务生成质量。

**V4.2 7步 LLM 深度推理流程：**
```
pending < 10 → spawn LLM 任务生成子代理
    ↓
Step 1: LLM 深度目标差距分析（T1-T7 全量，分析阶段/瓶颈/缺失行动）
Step 2: LLM 构建精准 Research 查询（不用模板，针对差距生成）
Step 3: Tavily 深度搜索（每个查询 max-results=10）
Step 4: LLM 深度分析 Research 结果（提取关键发现+行动建议）
Step 5: LLM 生成具体任务（5-10个，包含详细上下文）
Step 6: LLM 语义去重（多维度 Jaccard：标题40%+描述30%+类别20%+目标10%）
Step 7: LLM 优先级评估（5个调整因子：时间敏感/阻塞影响/目标进度/Research驱动/战略价值）
    ↓
写入看板数据库（status='pending', task_type='auto_generated_v4.2'）
```

### 12. 任务分级与人机耦合 (2026-04-22)
**核心理念：** 自我驱动系统与用户的工作、生活、学习、创业深度耦合。用户是教授、创始人、区委委员——工作本质是**通过人来完成事情**。

**三种 execution_mode：**
- `auto`：子代理自动执行（代码部署、数据收集、报告生成、分析研究等）
- `user_action`：需要用户本人亲自执行（回复邮件、参加会议、跟人沟通、签约、路演等），执行完后反馈给系统
- `review_needed`：需要用户审核后子代理才执行（对外发邮件草稿、重要决策方案等）

**关键规则：**
1. 调度器**不会**自动 spawn 子代理执行 `user_action` 或 `review_needed` 任务
2. `user_action` 任务出现在审核板上等待用户执行，完成后用户反馈
3. `review_needed` 任务子代理先生成方案 → 用户审核 → 批准后子代理执行
4. 用户反馈后 → 系统更新任务状态 → 可能触发后续任务
5. 任务生成时必须根据任务性质设置正确的 `execution_mode`

## 📊 商业与客户管理

### 13. T2商业变现多渠道原则 (2026-04-23)
**核心理念：** 所有商业变现机会必须同时考虑三条路径，避免单一渠道风险。

**三条并行路径：**
1. **软件授权**：主收入来源（MatCloud/MatAuto/MatLab三大产品线）
2. **专家咨询**：轻资产快速变现（500元/30分钟 ~ 20万元/年分层报价）
3. **知识付费**：市场验证+流量入口（99元短课+社群模式）

**执行标准：**
- 任何新商业机会都要评估是否符合三条路径之一
- 优先选择边际成本低、可规模化的变现方式
- 每月复盘三条路径的进展，动态调整投入比例

### 14. 客户分级A/B/C管理原则 (2026-04-23)
**核心理念：** 目标客户必须按价值和潜力分级管理，资源投入与价值匹配。

**分级标准：**
| 级别 | 占比 | 定义 | 资源投入 | 跟进策略 |
|------|------|------|---------|---------|
| **A类（标杆）** | 25% | 行业头部、有战略示范意义 | 80% | 战略级深度跟进，高层对接 |
| **B类（高潜）** | 35% | 预算充足、需求明确、决策链短 | 15% | 重点跟进，定期回访 |
| **C类（常规）** | 40% | 有潜在需求，但短期转化难度大 | 5% | 常规维护，信息推送 |

**执行标准：**
- 所有客户必须在入池时完成分级
- 每季度重新评估一次分级，动态调整
- A类客户必须建立专属跟进档案和里程碑计划

## 📎 文件与附件管理

### 15. 附件上传强制原则 (2026-04-23)
**核心理念：** 所有任务产出文件必须插入attachments表，附件管理是任务完成的必要环节。

**执行标准（必须严格遵守）：**
1. **每个文件独立INSERT**：每个产出文件必须单独执行INSERT到attachments表
2. **包含文件大小统计**：使用`os.path.getsize()`获取文件大小并记录
3. **验收标准强制检查**：任务验收标准必须包含附件上传检查项
4. **定期审计机制**：建立自动检查脚本，每日审计附件完整性

**必须上传附件的场景：**
- 任何有产出的任务（报告、文档、表格、代码、PPT等）
- 任务要求2篇报告 → INSERT 2次
- 任务要求4个交付物 → INSERT 4次
- 一个都不能少！

**附件上传SQL示例：**
```python
import os
from lib.db_connector import get_db_connection
conn = get_db_connection()
c = conn.cursor()
file_path = '/Users/mettlyz/.openclaw/workspace/output/task-1234/文件名.md'
file_size = os.path.getsize(file_path)
c.execute('''INSERT INTO attachments 
    (entity_type, entity_id, filename, url, size, file_type) 
    VALUES (%s, %s, %s, %s, %s, %s)''',
    ('task', 1234, '文件名.md', 
     f'output/task-1234/文件名.md', 
     file_size, 'md'))
conn.commit()
conn.close()
print(f'✅ 附件已上传: 文件名.md')
```

**自检清单（每项都必须满足）：**
- [ ] 产出文件是否已保存到正确路径？
- [ ] 每个文件是否已独立INSERT到attachments表？
- [ ] 文件大小是否已正确统计？
- [ ] 数据库是否已提交事务？

**此规则永久生效，永不遗忘。**
