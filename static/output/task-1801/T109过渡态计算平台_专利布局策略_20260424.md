## 一、战略定位与目标

### 1.1 战略定位

**"技术护城河构建者"** - 通过系统化的专利布局，将T109平台的技术优势转化为受法律保护的商业壁垒，确立在过渡态计算这一细分赛道的领导地位。

### 1.2 核心目标

| 目标维度 | 2026年底目标 | 2027年底目标 | 衡量指标 |
|----------|-------------|-------------|----------|
| **专利数量** | 15件申请 | 22件全部申请 | 发明专利申请数 |
| **专利质量** | 8件进入实审 | 5件获得授权 | 授权率≥70% |
| **地域覆盖** | 中国全部 | PCT 8件，美欧5件 | 国际专利申请数 |
| **壁垒构建** | 核心算法保护完成 | 四级专利体系建成 | 核心技术专利覆盖率 |
| **商业价值** | 完成FTO分析 | 可用于融资/许可/诉讼 | 专利评估价值≥5000万 |

### 1.3 布局原则

1. **质量优先，数量为辅** - 每件专利都要有明确的商业目的，不为凑数而申请
2. **核心先行，外围跟进** - 先保护平台基石，再覆盖应用场景
3. **产品-专利同步** - 专利申请与产品迭代同频，技术实现即专利保护
4. **攻防兼备** - 既要保护自己，也要防止被对手卡脖子
5. **国内打底，国际跟进** - 先拿中国优先权，再选择性进入国际市场

### 2.2 权利要求撰写策略

**每件专利都采用"金字塔型"权利要求布局：**

```
                ┌──────────────┐
                │  权利要求1   │  ◄── 最核心、最宽泛的独立权利要求
                │  (必侵权)    │      保护范围最大，撰写难度最高
                └──────────────┘
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   ┌──────────┐  ┌──────────┐  ┌──────────┐
   │权利要求2-5│  │权利要求6-10│ │权利要求11-15│ ◄── 从属权利要求
   │ (方法类)  │  │ (系统类)  │  │ (细节优化) │      层层递进，逐步缩小
   └──────────┘  └──────────┘  └──────────┘           保护范围，形成防
                                                       御纵深
```

**撰写要求：**
- 权利要求1必须是"不可规避的核心"，竞争对手只要做同类产品必然侵权
- 方法权利要求与系统（装置）权利要求并重
- 每个核心概念至少有3层从属权利要求，形成防御纵深
- 同时覆盖"算法"、"系统"、"存储介质"三种主题，防止主题规避

### 5.2 专利工作流程标准化

**技术创新 → 专利保护 闭环流程：**

```
  1. 技术创新点识别
     │  研发中产生的新算法、新功能
     ▼
  2. 专利性初审（专利工程师）
     │ 新颖性/创造性/实用性初步判断
     ▼
  3. 专利委员会立项审批
     │  决定是否申请、优先级、预算
     ▼
  4. 技术交底书撰写（发明人）
     │  详细技术方案、对比现有技术
     ▼
  5. 专利代理人撰写申请文件
     │  2-3轮沟通修改，权利要求精心设计
     ▼
  6. 提交专利申请
     │  获得申请日和申请号
     ▼
  7. 审查意见答复
     │  与审查员沟通，争取授权
     ▼
  8. 获得授权 ←──────────┐
     │                    │  监控年费、维持有效性
     ▼                    │
  9. 专利运营            │
     许可、转让、诉讼、融资
```

## 六、风险防控机制

### 6.1 专利侵权风险防控

**FTO（自由实施）定期审查机制：**

| 审查频率 | 审查内容 | 输出物 |
|----------|----------|--------|
| 每季度 | 主要竞争对手新申请专利监控 | 竞争对手专利预警报告 |
| 每半年 | T109核心功能的侵权风险评估 | FTO分析报告 |
| 产品重大更新前 | 更新功能的专利风险排查 | 专利风险排查清单 |

**高风险专利应对策略库：**

| 风险等级 | 应对策略 | 具体措施 |
|----------|----------|----------|
| 🔴 极高 | 技术规避 | 重新设计技术方案，绕开权利要求 |
| 🟠 高 | 专利挑战 | 寻找现有技术，提出无效宣告请求 |
| 🟡 中 | 交叉许可 | 用我方专利与对手进行交叉许可谈判 |
| 🟢 低 | 专利收购 | 收购目标专利或其所在的专利组合 |

### 6.2 专利质量风险防控

**专利质量三道把关：**
1. **发明人把关** - 技术方案的准确性和完整性
2. **专利工程师把关** - 专利性判断和权利要求设计
3. **外部专家把关** - 重要专利请资深专利律师再审

**质量KPI：**
- 权利要求平均数量≥15项
- 独立权利要求数量≥3项（方法/系统/介质）
- 说明书实施例数量≥5个
- 审查意见答复次数≤2次即授权

### 6.3 保密风险防控

**技术秘密与专利保护的平衡：**

| 技术类型 | 保护方式选择 | 决策因素 |
|----------|--------------|----------|
| 核心算法，易反向工程 | 专利保护 | 技术方案公开后仍能保持优势 |
| 内部工程优化，难破解 | 技术秘密 | 竞争对手难以通过产品反推 |
| 数据处理细节 | 混合保护 | 核心流程申请专利，参数作为秘密 |

**保密措施：**
- 所有发明人签署保密协议
- 专利提交前技术方案不得公开（论文、演讲、开源）
- 核心专利在提交前进行"防泄密审查"

## 九、应急预案

### 9.1 竞争对手发起专利诉讼

**应对流程：**
1. 立即启动FTO分析，评估侵权风险
2. 同时启动对方专利无效分析
3. 准备技术规避方案
4. 启动公关预案

### 9.2 核心专利被驳回

**应对措施：**
1. 分析驳回理由，考虑分案申请
2. 同时准备延续申请（Continuation）
3. 调整技术方案，补充创新点再申请

### 9.3 技术方案提前泄露

**应对措施：**
1. 评估是否影响新颖性
2. 如未超过6个月，立即提交专利申请
3. 如已超过，调整技术方案后再申请
