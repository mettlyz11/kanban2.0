## 二、发现的关键问题

### 2.1 🔴 严重：Tavily API 额度耗尽

**现象**: 所有 Research 驱动的任务生成查询 100% 失败
```
urllib.error.HTTPError: HTTP Error 432: This request exceeds your plan's set usage limit
```

**根因**: Tavily 免费计划 API 调用次数已用尽
**影响**: Research 驱动的智能任务生成完全不可用
**解决**: 切换到 web_search (Brave API) 作为 Research 引擎

### 2.2 🟡 中等：kanban_client.py `query()` 方法签名不匹配

**现象**: `TypeError: query() takes 2 positional arguments but 3 were given`
**根因**: `task_generator_v4.py` 调用 `kanban.query(sql, params)` 但原方法不接受 params
**修复**: 已修改 `kanban_client.py` 的 `query()` 方法，支持可选参数

### 2.3 🟡 中等：V4.2 `global conn` 语法错误

**现象**: `SyntaxError: name 'conn' is used prior to global declaration`
**根因**: finally 块中 `global conn` 声明在使用之后
**修复**: 已在 finally 块顶部添加 `global conn` 声明

### 2.4 🟢 低：僵尸任务清理

**现象**: 1 个 in_progress 任务超过 30 分钟无心跳
**处理**: 调度器已内置僵尸检测，自动恢复

## 三、修复与优化

### 3.1 已修复

| 修复项 | 文件 | 变更 |
|--------|------|------|
| `query()` 参数支持 | `kanban_client.py` | 添加可选 `params` 参数 |
| `global conn` 语法错误 | `self-driving-scheduler-v4.2.py` | 修复 finally 块 |

### 3.2 Research 引擎切换方案

由于 Tavily API 额度耗尽，V4.2 的 `spawn_llm_task_generator()` 已采用**独立子代理模式**：

```
调度器检测 pending < 10
    ↓
spawn 独立子代理（使用 web_search 工具）
    ↓
子代理执行 Research → 生成任务 → INSERT 数据库
    ↓
调度器继续扫描 pending 队列
```

**优势**:
- 不依赖本地 Python 脚本的 Tavily 调用
- 子代理有完整的 web_search 工具（Brave API）
- 失败不影响主调度循环
