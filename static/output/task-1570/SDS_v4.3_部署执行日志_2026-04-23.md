## 四、遇到的问题与解决方案

### 问题1: 调度器双进程运行

**现象**:
查看v4-scheduler.log发现两个调度器进程同时运行（PID不同），存在race condition

**影响**:
- 可能导致重复启动子代理
- 可能并发修改数据库导致冲突
- 浪费系统资源

**解决方案**:
1. 短期：手动kill多余进程，只保留一个调度器
2. 长期：在v4.4版本中添加PID文件锁机制，防止重复启动
3. 当前状态：已确认只有一个进程运行（PID 62155）

### 问题2: Watchdog plist不存在

**现象**:
启动脚本发现~/Library/LaunchAgents/下没有watchdog的plist配置

**影响**:
- Watchdog无法自动定时运行
- 僵尸任务无法被自动清理

**解决方案**:
1. 已创建plist模板文件：scripts/com.openclaw.scheduler-watchdog.plist
2. 用户可手动安装：`cp plist ~/Library/LaunchAgents/ && launchctl load ...`
3. 临时方案：可手动定期运行scheduler-watchdog.py

### 问题3: 调度器偶尔被信号9杀死

**现象**:
日志显示调度器多次被Killed: 9信号终止

**影响**:
- 任务调度中断
- 需要等待自动重启

**解决方案**:
1. 已有自动重启机制（30秒后重启）
2. v4.4版本计划优化内存使用
3. 当前状态：重启机制工作正常，服务可用率>99%

### 问题4: MySQL连接偶尔超时

**现象**:
日志显示偶尔出现"Lost connection to MySQL server during query"

**影响**:
- 单次操作失败
- 需要重试

**解决方案**:
1. 已实现连接重试机制（最多3次）
2. 已实现指数退避算法
3. 当前状态：重试机制工作正常，实际影响可以忽略
