## 二、日常运维操作指南

### 2.1 会议纪要系统维护

**每日检查**：
```bash
# 检查最新生成的会议纪要
ls -lt output/meeting_minutes/ | head -5

# 检查是否有处理失败的文件
grep "ERROR" output/meeting_minutes/*.log 2>/dev/null
```

**每周维护**：
1. 检查Whisper转写准确率，必要时更新模型
2. 清理超过30天的旧纪要文件（保留JSON行动项）
3. 检查行动项同步状态，确认无遗漏

**常见问题排查**：

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 转写结果为空 | 音频格式不支持 | 转换为WAV格式（16kHz采样率） |
| 行动项提取不准确 | LLM提示词需优化 | 调整prompt，增加示例 |
| 同步失败 | API token过期 | 刷新对应平台的认证token |
| 处理速度慢 | 音频文件过大 | 切分音频或使用API版Whisper |

### 2.2 周报/月报系统维护

**每月检查**：
```bash
# 检查报告是否正常生成
ls -lt output/reports/weekly/ | head -5
ls -lt output/reports/monthly/ | head -3

# 验证数据源连接
python3 -c "from lib.db_connector import get_db_connection; conn = get_db_connection(); print('DB连接正常'); conn.close()"
```

**定期维护清单**：
- [ ] 每月第1周：更新报告模板（如有格式变更）
- [ ] 每月第2周：检查数据源完整性
- [ ] 每月第3周：验证KPI数据准确性
- [ ] 每月第4周：清理过期报告（保留近12个月）

**数据源监控**：
```python
# 快速数据源健康检查脚本
from lib.db_connector import get_db_connection
from datetime import datetime

def check_data_sources():
    conn = get_db_connection()
    cursor = conn.cursor()
    
    checks = {
        "tasks表": "SELECT COUNT(*) FROM tasks",
        "milestones表": "SELECT COUNT(*) FROM milestones",
    }
    
    for name, sql in checks.items():
        try:
            cursor.execute(sql)
            count = cursor.fetchone()[0]
            status = "✅" if count > 0 else "⚠️"
            print(f"{status} {name}: {count} 条记录")
        except Exception as e:
            print(f"❌ {name}: 连接失败 - {e}")
    
    conn.close()

check_data_sources()
```

## 三、故障应急处理

### 3.1 应急预案

| 故障场景 | 应急措施 | 恢复时间目标 |
|---------|---------|------------|
| LLM API不可用 | 回退到规则引擎/模板回复 | <5分钟 |
| 数据库连接失败 | 使用本地缓存数据 | <10分钟 |
| 文件处理失败 | 手动处理+记录失败原因 | <30分钟 |
| 系统全面故障 | 切换至人工处理模式 | 立即 |

### 3.2 回退操作

```bash
# 停止所有自动化任务
crontab -r  # 清除所有定时任务

# 或选择性停止
crontab -l | grep -v "weekly_report" | crontab -

# 恢复手动模式
echo "⚠️ 自动化系统已停止，请手动处理相关事务"
```

### 3.3 日志查看

```bash
# 查看所有工作流日志

# 查看特定工作流日志
tail -100 output/meeting_minutes/error.log
```

## 四、性能优化指南

### 4.1 响应速度优化

| 优化项 | 方法 | 预期效果 |
|--------|------|---------|
| LLM调用延迟 | 使用流式输出 + 本地缓存 | 降低30-50% |
| 音频转写速度 | 使用whisper-large-v3-turbo | 提升2倍 |
| 数据库查询 | 添加索引 + 查询优化 | 提升3-5倍 |
| 文件I/O | 使用SSD + 异步写入 | 提升50% |

### 4.2 成本优化

| 优化项 | 方法 | 预期节省 |
|--------|------|---------|
| API调用成本 | 使用混合模型（简单任务用便宜模型） | 节省40-60% |
| 存储成本 | 定期清理 + 压缩归档 | 节省30% |
| 计算成本 | 任务批量处理 + 错峰执行 | 节省20% |

### 4.3 模型选择建议

```
会议纪要转写:  whisper-large-v3 (本地) 或 whisper-1 (API)
文本摘要生成:  kimi-k2 或 qwen3.6-plus (性价比高)
FAQ意图识别:  轻量级模型 (如 qwen-turbo)
复杂问题回答:  kimi-k2 或 claude-sonnet-4-6
```

### 5.2 备份策略

```bash
#!/bin/bash
# backup_workflows.sh - 自动化工作流备份脚本

BACKUP_DIR="backups/workflows/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$BACKUP_DIR"

# 备份脚本
cp -r scripts/ "$BACKUP_DIR/scripts/"

# 备份配置
cp -r data/ "$BACKUP_DIR/data/"

# 备份输出
cp -r output/ "$BACKUP_DIR/output/"

# 备份日志
find output/ -name "*.log" -exec cp {} "$BACKUP_DIR/" \;

# 压缩
tar -czf "$BACKUP_DIR.tar.gz" "$BACKUP_DIR"
rm -rf "$BACKUP_DIR"

echo "✅ 备份完成: $BACKUP_DIR.tar.gz"
```

**备份频率**：
- 配置变更时：立即备份
- 常规备份：每周自动执行
- 归档保留：近30天完整保留，30-90天压缩保留，90天以上异地存储
