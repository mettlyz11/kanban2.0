## 二、优先级算法校准：「权重-优先级动态对齐公式」

### 2.1 新优先级计算公式

```
执行优先级 = 基础优先级 × 0.5 + 目标权重归一化系数 × 0.5

其中:
- 基础优先级: 任务原始优先级 (1-10)
- 目标权重归一化系数 = 目标权重 / 10 × 10 = 目标权重 (T1/T2=10, T3=9, ..., T7=4)
```

### 2.2 T1/T2 任务重新定级示例

| 任务 | 基础P | 目标权重 | 新执行P | 调整动作 |
|------|-------|---------|--------|---------|
| A轮融资FA对接 | 2 | 10 | **6.0 → 9.0** | 立即提升 |
| DFT平台定价表 | 3 | 10 | **6.5 → 8.5** | 立即提升 |
| 核心产品MVP落地 | 2 | 10 | **6.0 → 8.0** | 立即提升 |
| Tavily Research系统 | 9 | 10 | 9.5 | 维持 |
| 战略复盘任务#N | 9 | 10 | 9.5 | **冻结，不再新建** |
| 知识大脑用户手册 | 4 | 10 | 7.0 | 外包/AI生成 |
| 定期检查任务 | 9 | 10 | 9.5 | **自动化或降级** |

### 2.3 自动化执行脚本

**每日晨间自动执行（建议加入cron）**:

```python
# priority_recalibration.py
# 每日 08:30 自动刷新任务优先级

def recalc_priority(base_priority, goal_code):
    weights = {'T1': 10, 'T2': 10, 'T3': 9, 'T4': 8, 'T5': 7, 'T6': 6, 'T7': 5}
    weight = weights.get(goal_code, 5)
    return round(base_priority * 0.5 + weight * 0.5, 1)

# 对T1/T2 Pending任务批量更新
# UPDATE tasks SET priority = recalc(...) WHERE ...
```

## 四、「阻塞问题48小时清零」响应机制

### 4.1 机制设计

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  发现阻塞    │────▶│  24h内响应   │────▶│  48h内清零   │
│  (任何任务)  │     │  (明确方案)  │     │  (解决/升级) │
└─────────────┘     └─────────────┘     └──────┬──────┘
       │                                        │
       │         ┌──────────────────────────────┘
       │         ▼
       │    ┌─────────────┐
       └───▶│  升级至刘宇宙 │
            │  教授决策     │
            └─────────────┘
```

### 4.2 执行细则

1. **阻塞发现**: 任何任务超过48小时无进展，自动标记为"blocked"
2. **24h响应**: Dudu AI在每日heartbeat中检查blocked任务，输出阻塞原因分析
3. **48h清零**: 
   - 技术阻塞 → 提供替代方案或降级方案
   - 依赖阻塞 → 主动联系依赖方，明确交付时间
   - 决策阻塞 → 提交决策建议书，等待刘教授15分钟内批复
   - 资源阻塞 → 启动外包/自动化/委托流程
4. **升级规则**: 48小时内无法清零的阻塞，自动升级至刘宇宙教授决策

### 4.3 工具支持

- **看板标签**: 增加 `blocked` 状态标签
- **Heartbeat检查**: 每日检查blocked任务清单
- **自动化提醒**: blocked任务超48小时自动发送提醒
