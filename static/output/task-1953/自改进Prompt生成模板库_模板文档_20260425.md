# 自改进 Prompt 生成模板库

## 1. 用途
该模板库用于在子代理执行失败、部分完成、低置信度输出后，自动生成下一轮优化 prompt。核心目标不是简单“重试一次”，而是把失败原因转化为结构化补救策略，从而形成可复用的自反馈闭环。

## 2. 通用变量
以下占位符在所有模板中通用：
- `{{task_goal}}`：任务目标
- `{{original_prompt}}`：原始 prompt
- `{{failure_label}}`：失败分类标签
- `{{root_cause}}`：根因分析
- `{{evidence}}`：失败证据
- `{{missing_context}}`：缺失的上下文/资料
- `{{tool_errors}}`：工具报错摘要
- `{{desired_output}}`：理想输出格式
- `{{constraints}}`：约束条件
- `{{previous_output_summary}}`：上一轮输出摘要

## 3. 总控模板
### 模板 A：失败后重试总模板
```text
你正在对一个先前执行失败或结果不稳定的任务进行二次执行。

任务目标：{{task_goal}}
原始 prompt：{{original_prompt}}
失败类型：{{failure_label}}
根因分析：{{root_cause}}
关键证据：{{evidence}}
上一轮输出摘要：{{previous_output_summary}}

请遵循以下规则重新执行：
1. 先明确列出你需要验证的事实、文件、工具或上下文。
2. 如果上下文不足，先补检索/补读取，不要直接生成最终答案。
3. 如果工具报错，先检查路径、参数、权限、schema，再执行。
4. 任何结论都必须说明依据；无法确认时直接写“无法确认”。
5. 最终输出按以下格式提供：
   - 已验证事实
   - 关键步骤
   - 最终结果
   - 风险/未确认项

输出要求：{{desired_output}}
额外约束：{{constraints}}
```

## 4. 幻觉型模板
### 模板 B：证据约束型修复
```text
你上一轮失败的主要原因是：在证据不足时给出了看似确定的结论。

请重新执行任务：{{task_goal}}
要求：
1. 先列出所有待确认事实。
2. 每条事实都必须绑定来源（memory、文件、数据库、网页、工具结果）。
3. 如果没有来源，禁止写成确定性结论。
4. 对不确定内容统一使用“待验证/无法确认”。
5. 最终答案必须附“证据映射表”。

失败证据：{{evidence}}
原始 prompt：{{original_prompt}}
目标输出：{{desired_output}}
```

### 模板 C：事实核验后输出
```text
在生成最终结论前，你必须先做事实核验。

任务：{{task_goal}}
请按顺序执行：
- Step 1：提取所有关键断言
- Step 2：逐条验证断言是否有来源支持
- Step 3：删除无法证实的内容
- Step 4：仅基于已证实信息重写答案

若发现证据不足，不要补脑，不要猜测。
```

## 5. 知识缺失型模板
### 模板 D：先补上下文再执行
```text
你上一轮失败是因为知识/上下文不足，不允许直接进入生成。

任务目标：{{task_goal}}
缺失上下文：{{missing_context}}

请严格按照下面流程执行：
1. 先列出完成任务所需的最小信息集合。
2. 使用可用工具读取 memory、相关文档、schema 或历史输出。
3. 只有当信息集合足够时，才开始分析或撰写结果。
4. 若仍缺关键信息，输出“缺口清单”而不是伪造完成。

最终输出结构：
- 已补充上下文
- 仍然缺失的信息
- 基于现有信息可完成的部分
- 建议下一步
```

### 模板 E：检索优先型执行
```text
先检索，后生成。

任务：{{task_goal}}
要求你在回答前至少完成以下动作：
- 读取相关 memory/项目文件
- 查找已有脚本或历史实现
- 如涉及数据库/表结构，必须先验证 schema

如果没有完成上述动作，不要输出最终答案。
```

## 6. 工具使用错误型模板
### 模板 F：工具前检查清单
```text
你上一轮主要失败于工具使用环节。请重新执行任务，但在每一次工具调用前完成检查。

任务：{{task_goal}}
工具错误摘要：{{tool_errors}}

执行规则：
1. 调用文件工具前：先确认路径存在。
2. 调用数据库前：先确认连接方式、表名、字段名、SQL参数。
3. 调用 shell/exec 前：先确认命令可执行、工作目录正确。
4. 若失败，优先修复并重试一次；仍失败则输出阻塞原因。
5. 记录每次调用的目的、输入摘要、结果摘要。

最终输出：
- 工具调用清单
- 已修复问题
- 最终产出
- 遗留风险
```

### 模板 G：写操作谨慎模式
```text
接下来任务包含写文件、数据库更新或外部状态变更，请使用谨慎模式。

要求：
- 写之前先读已有实现或 schema
- 先做 dry-run 或构造最小验证
- 明确说明将写入什么、写到哪里、依赖什么前提
- 若前提不成立，停止写入并报告
```

## 7. 混合型失败模板
### 模板 H：分阶段补救模板
```text
这是一个混合型失败案例，可能同时包含上下文不足、工具错误和事实性不稳。

任务：{{task_goal}}
失败标签：{{failure_label}}
根因：{{root_cause}}

请按三阶段修复：
第一阶段：补上下文（读取文件 / 检索 memory / 查 schema）
第二阶段：校验工具（路径、参数、权限、命令、SQL）
第三阶段：生成结果并附证据

输出结构：
1. 补充到的上下文
2. 工具校验结果
3. 已验证结论
4. 未验证项
5. 最终结果
```

## 8. 复盘总结模板
### 模板 I：自动复盘生成器
```text
请基于本次任务运行轨迹生成复盘结论。

任务：{{task_goal}}
失败标签：{{failure_label}}
根因分析：{{root_cause}}
证据：{{evidence}}

输出：
- 本次失败的直接原因
- 更深层系统性原因
- 下次执行前必须增加的检查项
- 推荐替换/追加的 prompt 约束
- 是否应沉淀为长期规则（是/否，及原因）
```

## 9. 模板选择策略
- `hallucination` → 优先使用 模板 B/C/I
- `knowledge_gap` → 优先使用 模板 D/E/I
- `tool_error` → 优先使用 模板 F/G/I
- `mixed` → 优先使用 模板 A/H/I
- `unknown` → 先用 模板 I 生成人工复核说明，再决定下一轮模板

## 10. 组合使用建议
推荐生成链：
1. 分类器输出 `failure_label`
2. 根据标签选择主模板
3. 再追加一个复盘模板 I
4. 如涉及外部写操作，额外叠加模板 G

## 11. 示例
### 输入
- `task_goal`：更新任务数据库并上传附件
- `failure_label`：tool_error
- `tool_errors`：路径错误、SQL 字段未验证

### 选用模板
主模板：F
补充模板：G + I

### 预期效果
下一轮执行会先检查输出目录、附件路径、attachments 表字段与 tasks 表字段，再执行数据库写入，从而显著降低“命令执行成功但业务更新失败”的问题。
