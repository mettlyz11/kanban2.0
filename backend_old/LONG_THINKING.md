# 🧠 长思考工作原理 (Long Thinking System)

## 核心概念

长思考是一个**自动化系统分析工具**，每天定时运行，像一位"数字助手"一样审视系统状态，发现问题并提出改进建议。

不同于被动的问题响应，长思考主动进行：
- 🔍 **系统性扫描** - 全面检查项目和任务状态
- 🧠 **智能分析** - 识别健康度、积压、失败率等问题
- 📝 **主动生成** - 自动创建改进任务，无需人工干预
- ⚡ **分级处理** - 自动执行 vs 人工审核的智能分流

---

## 工作流程

### 1️⃣ 定时触发
- **执行时间**: 每天 13:00 (下午1点)
- **触发方式**: 通过 Cron 任务调度器
- **执行模式**: 全自动运行，无需人工启动

```
每天 13:00 → 启动长思考引擎 → 执行数据分析 → 生成改进任务
```

### 2️⃣ 数据收集
系统自动收集以下数据：

| 数据类型 | 收集内容 | 用途 |
|---------|---------|------|
| 📁 **项目数据** | 项目状态、进度、里程碑 | 评估项目健康度 |
| ✅ **任务数据** | 待办/进行中/已完成任务 | 发现任务积压 |
| 📊 **执行历史** | 任务执行记录、失败日志 | 分析系统失败率 |
| 🎯 **目标数据** | 总体目标、战略方向 | 对齐改进建议 |
| ⚡ **系统指标** | CPU、内存、错误率 | 监控系统健康 |

### 3️⃣ 智能分析
基于收集的数据，进行多维度分析：

#### 3.1 项目健康度检查
```
健康度评分 = f(进度偏差, 任务完成率, 延期数量)
- 🟢 健康 (80-100分): 正常推进
- 🟡 警告 (60-79分): 需要关注
- 🔴 危险 (<60分): 需要干预
```

#### 3.2 任务积压检测
```
积压指标 = 待办任务数 / 平均每日完成数
- 🟢 正常 (<3天): 无需干预
- 🟡 积压 (3-7天): 建议增加资源
- 🔴 严重 (>7天): 必须处理
```

#### 3.3 系统失败率分析
```
失败率 = 失败任务数 / 总任务数 × 100%
- 🟢 稳定 (<5%): 系统健康
- 🟡 关注 (5-10%): 需要排查
- 🔴 告警 (>10%): 紧急修复
```

### 4️⃣ 生成任务
根据分析结果，自动生成改进任务：

#### 任务分流规则

| 任务类型 | 处理方式 | 原因 |
|---------|---------|------|
| 📝 **常规改进** | 自动创建到任务队列 | 技术性、常规性任务 |
| ⚡ **系统优化** | 自动创建并标记高优先级 | 性能、稳定性相关 |
| 🔧 **代码重构** | 自动创建，分配技术标签 | 代码质量相关 |
| 📊 **数据分析** | 自动创建，关联相关项目 | 分析性任务 |
| 👤 **人工审核** | 创建到审核队列 | 涉及敏感信息或真实世界 |

#### 需要人工审核的情况
以下类型任务需要用户决定，**不自动执行**：

- 💰 **资产相关**: 投资、账户变动、资金操作
- 🛡️ **安全相关**: 密码修改、权限变更、安全策略
- 🏦 **银行相关**: 转账、开户、信用卡操作
- 🆔 **身份相关**: 个人信息修改、认证变更
- 🌍 **真实世界活动**: 线下会议、物理设备操作、人员联系

## 系统集成

### Cron配置
```bash
# 每天13:00执行长思考
crontab -e
0 13 * * * cd /path/to/kanban-react/backend && python3 -c "from long_thinking import run_daily_analysis; run_daily_analysis()"
```

### 代码集成
```python
# 在看板后端集成
from long_thinking import LongThinkingEngine

# 初始化
engine = LongThinkingEngine()

# 手动触发
engine.run_analysis()

# 获取最新报告
report = engine.get_latest_report()
```

### API端点
```
GET /api/long-thinking/status     - 获取长思考状态
GET /api/long-thinking/reports    - 获取历史报告列表
GET /api/long-thinking/latest     - 获取最新报告
POST /api/long-thinking/run       - 手动触发长思考 (管理员)
```

## 配置选项

配置文件: `~/.openclaw/workspace/kanban-react/backend/long_thinking_config.yml`

```yaml
# 定时设置
schedule:
  hour: 13          # 执行小时 (24小时制)
  minute: 0         # 执行分钟
  timezone: "Asia/Shanghai"

# 分析范围
analysis:
  projects: true    # 分析项目
  tasks: true       # 分析任务
  system: true      # 分析系统指标
  history_days: 7   # 查看历史天数

# 阈值设置
thresholds:
  project_health: 70      # 项目健康度警告线
  task_backlog_days: 5    # 任务积压警告天数
  failure_rate: 0.1       # 失败率警告阈值 (10%)

# 任务生成规则
task_generation:
  auto_create: true       # 是否自动创建任务
  auto_execute: true      # 是否自动执行常规任务
  require_review_for:     # 需要人工审核的任务类型
    - "asset"
    - "security"
    - "bank"
    - "identity"
    - "physical"

# 报告设置
report:
  save_to_file: true
  output_dir: "~/.openclaw/workspace/logs/long_thinking/"
  retention_days: 90
```

## 与感知Agent的协作

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   感知Agent     │     │    长思考       │     │   任务调度器    │
│  (实时监控)     │────▶│  (每日分析)     │────▶│  (执行改进)    │
└─────────────────┘     └─────────────────┘     └─────────────────┘
        │                       │                       │
        ▼                       ▼                       ▼
   发现问题事件           生成改进任务           自动执行任务
   (Critical → 立即)     (每日批量生成)          (审核 → 执行)
```

**协作规则**:
- 感知Agent发现**Critical**问题 → 立即触发长思考 → 生成紧急任务
- 长思考每日扫描 → 发现潜在问题 → 生成预防性任务
- 常规任务 → 自动进入任务队列 → 调度器自动执行
- 敏感任务 → 进入审核队列 → 等待人工确认

## 使用场景

### 场景1: 日常系统维护
```
每天13:00
↓
长思考自动运行
↓
发现数据库查询变慢
↓
自动生成优化任务
↓
调度器自动执行SQL优化
↓
问题解决，无需人工干预
```

### 场景2: 项目进度预警
```
每天13:00
↓
长思考分析项目数据
↓
发现P003项目进度落后
↓
生成任务："P003项目风险评估"
↓
同时生成审核任务："是否增加P003资源投入？"
↓
常规任务自动执行，审核任务等待确认
```

### 场景3: 安全敏感操作
```
每天13:00
↓
长思考发现系统安全漏洞
↓
生成审核任务："紧急修复安全漏洞" (涉及安全，需人工确认)
↓
任务进入审核队列
↓
用户收到通知
↓
用户确认后，调度器执行修复
```
