### 风险2：数据质量与完整性风险（下载内容损坏/缺失/污染）

| 属性 | 内容 |
|:---|:---|
| **风险描述** | 下载的PDF损坏、元数据与全文不匹配、版本错误（预印本vs正式出版）、重复下载、或混入非目标内容（如广告、错误链接） |
| **触发条件** | 源网站结构变更、重定向链错误、PDF生成异常、缺乏校验机制、多源合并时的ID冲突 |
| **影响程度** | ██████░░░░ **中高** — 导致下游分析失效，需返工，信任度丧失 |
| **发生概率** | ███████░░░ **中高** — 多源异构数据常见问题 |
| **风险值** | **高优先级** |

**应对措施**

| 类型 | 具体行动 | 负责人 | 完成时限 |
|:---|:---|:---|:---|
| 预防 | 定义数据质量SLA：PDF可打开率≥99.5%，元数据必填字段完整率≥98%，版本准确率≥99% | 数据负责人 | 需求阶段 |
| 预防 | 强制校验流程：PDF下载后执行`pdfinfo`验证+文件头检查（%PDF），元数据Schema校验（JSON Schema） | 技术负责人 | 开发阶段 |
| 缓解 | 实现断点续传与自动重试（3次指数退避），失败任务进入死信队列人工审查 | 开发工程师 | 开发阶段 |
| 缓解 | 建立"黄金样本"测试集（100篇已知正确文献），每次代码变更后自动回归验证 | QA工程师 | 测试阶段 |
| 监控 | 仪表盘实时显示：下载成功率、校验失败率、各源质量评分，异常自动告警 | 运维工程师 | 上线后 |
| 应急 | 保留原始HTTP响应7天，支持问题追溯与重新拉取 | 运维工程师 | 上线后 |
