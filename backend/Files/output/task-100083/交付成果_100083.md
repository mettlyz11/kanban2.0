# 客户成功标准化SOP手册

## 一、客户生命周期全流程图

```
线索确认 → 签约成交 →  onboarding（0-30天） → 价值实现（31-90天） → 持续运营（91天+） → 续约/增购/流失预警
    ↑___________________________________________↓___________________________________________|
```

---

## 二、分阶段SOP详情

### 阶段1：签约交接（T+0，销售→CSM）

| 执行项 | 负责人 | 完成标准 | 交付物 |
|:---|:---|:---|:---|
| 客户信息同步 | 销售 | 24h内完成交接会 | 《客户交接单》 |
| 系统建档 | CSM | 48h内CRM录入完成 | 客户档案+健康度基线 |
| 启动会预约 | CSM | 签约后3个工作日内 | 会议邀请（含决策人+使用人） |

**关键动作清单：**
- [ ] 确认客户KP（关键人）：决策人、使用负责人、IT对接人
- [ ] 明确客户核心诉求（必须量化：如"提升审批效率50%"）
- [ ] 识别风险标签：定制化需求/预算紧张/竞品在用/决策链复杂

---

### 阶段2：Onboarding实施（Day 1-30）

**Week 1：系统部署+数据初始化**

| 动作 | 时限 | 验收标准 |
|:---|:---|:---|
| 环境配置 | Day 1-3 | 客户可登录，基础模块可用 |
| 历史数据迁移 | Day 3-7 | 数据完整性校验通过 |
| 管理员培训 | Day 5-7 | 客户侧管理员通过功能测试 |

**Week 2-3：核心用户培训**

```
培训分层设计：
├── 决策层（1小时）：ROI看板、管理报表
├── 管理员（4小时）：配置、权限、流程设计
└── 终端用户（2小时）：日常操作、高频场景
```

**Week 4：首月价值验证**

| 必做动作 | 工具/模板 |
|:---|:---|
|  usage数据埋点检查 | 产品后台+BI看板 |
|  客户满意度快速调研 | 《首月NPS问卷》（3题版） |
|  风险客户升级预警 | 健康度评分<60分→自动触发经理介入 |

**本阶段交付物：**
- 《上线验收确认书》（客户签字）
- 《首月价值报告》（含使用数据vs.客户目标对比）

---

### 阶段3：价值深化（Day 31-90）

**核心目标：让客户说出"这确实解决了我的问题"**

| 频次 | 动作 | 内容要点 |
|:---|:---|:---|
| 每周 | 使用数据监控 | 活跃率、核心功能使用深度、异常登录 |
| 双周 | 场景回访 | 针对客户原始诉求，展示数据改善 |
| 第60天 | 中期业务复盘会 | 对比签约时目标，调整Q2使用计划 |
| 第90天 | 价值报告交付 | 量化ROI，案例包装授权沟通 |

**健康度评分卡（自动计算）：**

| 维度 | 权重 | 数据来源 |
|:---|:---|:---|
| 产品使用深度 | 30% | 核心功能使用频次 |
| 登录活跃度 | 25% | DAU/MAU、连续登录天数 |
| 支持 ticket 情绪 | 20% | 最近30天工单满意度 |
| 客户互动响应 | 15% | CSM邮件/会议响应时效 |
| 业务目标达成进度 | 10% | 与客户约定的里程碑完成率 |

**评分结果应用：**
- 80-100分：绿灯 → 季度常规跟进
- 60-79分：黄灯 → 双周主动触达，排查阻塞点
- <60分：红灯 → 48h内升级至客户成功经理+制定挽回计划

---

### 阶段4：持续运营与续约管理（Day 91至续约前90天）

**分层运营机制：**

| 客户分层 | 标准（ARR） | 服务策略 |
|:---|:---|:---|
| 战略客户 | >50万/年 | 专属CSM+月度业务复盘+高管定期互访 |
| 重点客户 | 10-50万/年 | CSM负责+季度价值报告+行业最佳实践分享 |
| 成长客户 | 2-10万/年 | 自动化运营为主+季度健康度人工复核 |
| 基础客户 | <2万/年 | 完全自动化（产品内引导+帮助中心+社群） |

**续约倒计时管理（T-90天启动）：**

```
T-90天：系统标记续约预警，CSM确认续约负责人
T-60天：续约商务初步沟通，识别增购/降级意向
T-30天：正式报价，确认续签条款
T-15天： 合同签署或进入挽回流程
T-7天：   未签约→升级至销售VP+客户成功总监联合介入
```

## 三、关键场景应急SOP

### 场景A：客户投诉升级（24小时闭环）

| 时间节点 | 动作 | 责任人 |
|:---|:---|:---|
| 0-2h | 首次响应，确认问题范围与影响 | 一线CSM |
| 2-4h | 技术/产品介入，给出临时方案 | CSM协调 |
| 4-24h | 根因解决或正式workaround上线 | 技术负责人 |
| 24h内 | 客户书面确认关闭，录入投诉库 | CSM |

### 场景B：关键人离职/变动

**触发条件：** 系统监测到原KP连续14天未登录，或客户主动通知

| 步骤 | 动作 | 目的 |
|:---|:---|:---|
| 1 | 48h内通过原KP+新对接人建立联系 | 防止信息断层 |
| 2 | 重新进行"迷你onboarding"（1小时） | 新KP快速上手 |
| 3 | 同步历史价值实现数据 | 重建新KP对产品的认可 |
| 4 | 评估决策链变化，更新客户画像 | 识别新的反对者/支持者 |

## 四、CSM日常工具包

### 每周必做（建议周一上午完成）

```
□ 健康度评分更新（系统自动）→ 人工复核黄灯/红灯客户
□ 上周工单复盘：高频问题→反馈产品/知识库更新
□ 本周客户会议准备：3个必问问题
    1. 当前使用最大的阻塞点是什么？
    2. 业务目标进度是否符合预期？
    3. 还需要我们支持什么？
```

### 每月必做

```
□ 流失风险客户清单评审会（CSM+销售+产品）
□ 成功案例素材收集（至少1个可对外发布）
□ 产品更新同步：筛选与客户相关的功能，主动推送
```
