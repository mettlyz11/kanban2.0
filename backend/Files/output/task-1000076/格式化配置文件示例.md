# 配置文件包：v3 #18 代码格式化标准

本配置包包含三份核心配置文件：`.editorconfig`、`.prettierrc` 和 `.eslintrc.json`，适用于 JavaScript/TypeScript 项目（支持 React、Vue、Node.js 等常见场景）。所有配置均已调优，可直接复制到项目根目录使用。

---

## 1. .editorconfig 配置内容

### 文件：`.editorconfig`

```ini
# EditorConfig 帮助开发者在不同的编辑器和IDE之间保持一致的编码风格
# 更多信息: https://editorconfig.org/

root = true

# 所有文件通用规则
[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 2

# 特定文件类型的覆盖规则

# Markdown 文件：允许末尾空格（用于表格对齐），不强制末尾换行（可选）
[*.md]
trim_trailing_whitespace = false
insert_final_newline = false

# Makefile 必须使用 Tab 缩进
[Makefile]
indent_style = tab
indent_size = 2

# YAML 文件：使用 2 空格缩进，但保持末尾换行
[*.{yml,yaml}]
indent_size = 2

# JSON 文件：不强制末尾换行（与 prettier 默认一致）
[*.json]
insert_final_newline = false

# Python 文件：使用 4 空格缩进（如果项目中包含 Python）
[*.py]
indent_size = 4

# Shell 脚本：使用 2 空格缩进，文件末尾换行
[*.sh]
indent_size = 2
end_of_line = lf
```

### 配置说明

- **`root = true`**：确保 EditorConfig 只向上搜索到此文件，避免被父目录其他配置覆盖。
- **`[*]`** 规则应用于所有文件类型：UTF-8 编码、LF 换行符、强制文件末尾空行、自动去除行尾空白、2 空格缩进。
- **特殊覆盖**：针对 Markdown 保留行尾空白（用于表格对齐），Makefile 强制 tab，Python 使用 4 空格（当项目包含 Python 脚本时有用），JSON 文件不强制末尾换行（改善与 Prettier 的兼容性）。
- **`insert_final_newline`** 配合 Prettier 的 `endOfLine: "lf"` 可保证换行符一致。
- 所有主流编辑器（VS Code、WebStorm、Vim、Sublime Text 等）均支持 EditorConfig，无需额外插件（部分需要安装插件，如 Sublime 的 EditorConfig 插件）。

## 2. .prettierrc 配置内容

### 文件：`.prettierrc`（JSON 格式）

```json
{
  "printWidth": 120,
  "tabWidth": 2,
  "useTabs": false,
  "semi": true,
  "singleQuote": true,
  "quoteProps": "as-needed",
  "jsxSingleQuote": false,
  "trailingComma": "all",
  "bracketSpacing": true,
  "arrowParens": "always",
  "proseWrap": "preserve",
  "htmlWhitespaceSensitivity": "css",
  "endOfLine": "lf",
  "embeddedLanguageFormatting": "auto",
  "singleAttributePerLine": false,
  "bracketSameLine": false,
  "vueIndentScriptAndStyle": false
}
```

### 配置说明（关键字段）

| 字段 | 值 | 解释 |
|------|----|------|
| `printWidth` | 120 | 每行最大字符数，比默认 80 更宽松，适合宽屏显示器和小型函数。 |
| `tabWidth` | 2 | 缩进宽度，与 `.editorconfig` 保持一致。 |
| `useTabs` | false | 使用空格缩进。 |
| `semi` | true | 语句末尾加分号 (ASI safety)。 |
| `singleQuote` | true | 字符串使用单引号，与行业主流一致（减少 Shift 键次数）。 |
| `trailingComma` | `"all"` | 多行对象、数组、函数参数末尾都加逗号，方便 git diff 行数减少。 |
| `arrowParens` | `"always"` | 箭头函数参数始终包装括号 `(x) => x`。 |
| `endOfLine` | `"lf"` | 强制 Unix 换行符，跨平台兼容。 |
| `printWidth` | 120 | 可根据团队习惯调整，常见为 100~120。 |

- **为什么选择 `singleQuote: true` 而 `jsxSingleQuote: false`？** JSX 语法中双引号更符合 HTML 习惯，且避免与属性值引用冲突。
- **`trailingComma: "all"`** 自 ES2017 起合法，TypeScript 和 Babel 均支持。
- **`proseWrap: "preserve"`** 保留 Markdown 文本实际换行，避免 Prettier 自动换行破坏 markdown 语义。
- **`singleAttributePerLine: false`** 保持单个属性在同一行（除非超过 printWidth），减少文件行数。
- **与 ESLint 配合**：Prettier 与 ESLint 通过 `eslint-config-prettier` 和 `eslint-plugin-prettier` 协作，此配置已考虑兼容性。

## 3. .eslintrc.json 核心规则配置

### 文件：`.eslintrc.json`

```json
{
  "env": {
    "browser": true,
    "es2021": true,
    "node": true
  },
  "extends": [
    "eslint:recommended",
    "plugin:react/recommended",
    "plugin:react-hooks/recommended",
    "plugin:@typescript-eslint/recommended",
    "prettier"
  ],
  "parser": "@typescript-eslint/parser",
  "parserOptions": {
    "ecmaFeatures": {
      "jsx": true
    },
    "ecmaVersion": "latest",
    "sourceType": "module"
  },
  "plugins": ["react", "@typescript-eslint", "react-hooks", "import"],
  "settings": {
    "react": {
      "version": "detect"
    },
    "import/resolver": {
      "node": {
        "extensions": [".js", ".jsx", ".ts", ".tsx"]
      },
      "typescript": {}
    }
  },
  "rules": {
    // -------- 通用最佳实践 --------
    "no-console": ["warn", { "allow": ["warn", "error"] }],
    "no-debugger": "warn",
    "no-unused-vars": "off", // 由 @typescript-eslint 覆盖
    "no-var": "error",
    "prefer-const": "error",
    "prefer-arrow-callback": "error",
    "no-else-return": "error",
    "no-throw-literal": "error",
    "require-await": "warn",
    "eqeqeq": ["error", "always", { "null": "ignore" }],

    // -------- React 相关 --------
    "react/jsx-uses-react": "off",
    "react/react-in-jsx-scope": "off",
    "react/prop-types": "off",
    "react/display-name": "off",
    "react/jsx-key": "error",
    "react/no-unknown-property": "error",
    "react/no-unescaped-entities": "error",
    "react-hooks/rules-of-hooks": "error",
    "react-hooks/exhaustive-deps": "warn",

    // -------- TypeScript 相关 --------
    "@typescript-eslint/no-unused-vars": [
      "error",
      {
        "argsIgnorePattern": "^_",
        "varsIgnorePattern": "^_",
        "ignoreRestSiblings": true
      }
    ],
    "@typescript-eslint/no-explicit-any": "warn",
    "@typescript-eslint/explicit-module-boundary-types": "off",
    "@typescript-eslint/no-non-null-assertion": "warn",
    "@typescript-eslint/consistent-type-imports": [
      "error",
      { "prefer": "type-imports" }
    ],
    "@typescript-eslint/prefer-ts-expect-error": "error",

    // -------- import 排序（结合 Prettier 统一风格） --------
    "import/order": [
      "error",
      {
        "groups": [
          "builtin",
          "external",
          "internal",
          "parent",
          "sibling",
          "index",
          "object",
          "type"
        ],
        "newlines-between": "always",
        "alphabetize": { "order": "asc", "caseInsensitive": true }
      }
    ],
    "import/newline-after-import": ["error", { "count": 1 }],
    "import/no-unused-modules": ["warn", { "unusedExports": true }],

    // -------- 停用 Prettier 冲突规则（通过 extends: prettier 已覆盖） --------
    // 无需额外配置，extends 中的 "prettier" 会自动关闭冲突规则
  },
  "overrides": [
    {
      "files": ["*.ts", "*.tsx"],
      "rules": {
        // TypeScript 文件中不需要检查 prop-types
        "react/prop-types": "off"
      }
    },
    {
      "files": ["*.d.ts"],
      "rules": {
        "@typescript-eslint/no-unused-vars": "off"
      }
    },
    {
      "files": ["*.spec.ts", "*.test.ts", "*.test.tsx", "*.spec.tsx"],
      "env": {
        "jest": true
      },
      "rules": {
        "no-console": "off",
        "max-lines": "off"
      }
    }
  ],
  "globals": {
    "React": "readonly"
  }
}
```

### 核心规则说明

- **环境声明**：`browser`, `node`, `es2021` 同时支持前后端代码。
- **`extends` 顺序**：`eslint:recommended` → 插件推荐 → `prettier`（最后放置，确保关闭所有冲突规则）。
- **`parser`**：使用 `@typescript-eslint/parser` 以支持 TypeScript 语法。
- **`settings.react.version`** 自动检测 React 版本，避免版本警告。
- **`no-console`** 设置为 warn，允许 `console.warn` 和 `console.error` 保留（调试方便）。
- **TypeScript 规则**：
  - `no-unused-vars` 被替换为 TS 版本，且忽略下划线开头的参数/变量（`_error` 常见模式）。
  - `consistent-type-imports` 强制使用 `import type { X }` 替代 `import { X }`，优化类型导入的 Tree-shaking。
  - `prefer-ts-expect-error` 推荐使用 `// @ts-expect-error` 而非 `// @ts-ignore`，保证类型错误未被意外忽略。
- **import 排序**：`import/order` 强制分组排序（builtin / external / internal / parent / sibling / index），每组间空一行，内部按字母升序。可提升可读性。
- **`overrides`**：针对不同类型文件定制规则，如 `.d.ts` 不检查未使用变量，测试文件允许 `console` 等。
- **与 Prettier 的兼容**：`extends: ["prettier"]` 已经关闭了所有与 Prettier 冲突的格式化规则（如 `semi`, `quotes`, `trailing-comma` 等），后续无需手动设置。

## 4. 使用说明和注意事项

### 4.1 安装依赖

在你的项目根目录运行以下命令（如果使用 npm）：

```bash
npm install --save-dev \
  eslint \
  prettier \
  eslint-config-prettier \
  eslint-plugin-prettier \
  @typescript-eslint/parser \
  @typescript-eslint/eslint-plugin \
  eslint-plugin-react \
  eslint-plugin-react-hooks \
  eslint-plugin-import
```

如果使用 Yarn：

```bash
yarn add -D eslint prettier eslint-config-prettier eslint-plugin-prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin eslint-plugin-react eslint-plugin-react-hooks eslint-plugin-import
```

若项目不使用 TypeScript 或 React，可移除对应的插件和扩展。

### 4.2 配置文件放置

将本包提供的三个文件直接放到项目根目录：

- `.editorconfig`
- `.prettierrc`
- `.eslintrc.json`

无需额外改名。

### 4.3 VS Code 用户推荐配置

安装插件：

- **EditorConfig for VS Code** (自动读取 `.editorconfig`)
- **Prettier - Code formatter** (设置默认格式化器)
- **ESLint** (代码检查)

在 VS Code 的 `settings.json` 中添加（或全局设置）：

```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  },
  "eslint.validate": [
    "javascript",
    "javascriptreact",
    "typescript",
    "typescriptreact"
  ]
}
```

### 4.4 集成到 CI/CD（推荐）

在 `package.json` 的 `scripts` 中添加：

```json
{
  "scripts": {
    "lint": "eslint . --ext .js,.jsx,.ts,.tsx --max-warnings 0",
    "format": "prettier --check .",
    "format:fix": "prettier --write ."
  }
}
```

在 pre-commit hook（如 husky + lint-staged）中配置：

```json
// .lintstagedrc.json
{
  "*.{js,jsx,ts,tsx}": ["eslint --fix", "prettier --write"],
  "*.{json,md,yml,yaml}": ["prettier --write"]
}
```

### 4.5 注意事项

1. **Prettier 结尾逗号**：`trailingComma: "all"` 在旧版 Node.js（<12）中可能导致语法错误（函数参数逗号）。若项目需要支持 Node 10 或更低，建议改为 `"es5"`。
2. **ESLint 的 `no-unused-vars`**：规则中关闭了原生版本而启用了 `@typescript-eslint/no-unused-vars`，请确保项目已安装 `@typescript-eslint/eslint-plugin`，否则规则不会生效。
3. **Import 排序**：`import/order` 需要额外解析器支持，若你使用 Babel 而不是 TypeScript 编译，可移除此规则或配置 `import/resolver` 的默认 `node` 选项。
4. **React 17+ 和 JSX 转换**：已通过 `react/jsx-uses-react: "off"` 和 `react/react-in-jsx-scope: "off"` 禁用不必要的导入检查，适用于 React 17 的新 JSX 转换。
5. **编辑器缓存**：修改配置文件后，建议重启编辑器或重新加载窗口（VS Code 按 `Ctrl+Shift+P` 执行 `Developer: Reload Window`）以确保配置生效。
6. **与项目现有配置冲突**：如果项目已有 `.eslintrc` 或 `.prettierrc`，请先备份再替换。若为渐进式迁移，可先用本配置作为基底，再覆盖特定规则。
7. **平台换行符**：Windows 用户若使用 Git，请确保 `core.autocrlf` 设置为 `false` 或 `input`，否则 Prettier 会将 `lf` 强制转换为 `crlf` 导致差异。推荐在项目根目录放置 `.gitattributes` 文件：

```gitattributes
* text=auto eol=lf
```

### 4.6 验证配置生效

运行以下命令测试：

```bash
npx eslint src/App.tsx
npx prettier --check src/App.tsx
```

若无错误输出，说明配置已正确集成。
