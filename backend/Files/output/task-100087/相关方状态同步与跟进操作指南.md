## 一、总则与目标

### 1.1 本SOP的目的
- 统一相关方联系状态的判定标准，消除因主观判断导致的状态偏差。
- 明确状态更新频率、数据维护责任归属及跨角色同步机制。
- 提供可直接复用的沟通模板，降低沟通成本，提升触达效率。
- 建立异常状态的升级与风险报备通道，确保问题不遗漏、不延误。

### 1.2 核心原则
- **标准化**: 所有相关方记录必须使用本SOP定义的状态标签，禁止自创或模糊描述。
- **可追溯**: 每次状态变更需记录变更时间、变更人及变更原因（可关联系统操作日志）。
- **时效性**: 状态更新必须在指定时间窗口内完成（见第三章）。
- **闭环性**: 任何状态变更必须对应一次有效的沟通动作（邮件/即时消息/电话），并留存沟通记录。

## 二、联系状态标签定义与判定标准

以下为五级标准状态标签，每个标签附带详细判定标准。所有相关方记录必须且仅能处于其中一种状态。

### 2.1 状态标签总览

| 状态标签 | 代码 | 颜色标识 | 定义 | 典型判定标准（满足任一即判定） |
|---------|------|---------|------|-------------------------------|
| 已对接 | CON | 🟢 绿色 | 已成功建立联系，双方已确认身份及基本对接范围 | 1. 已通过邮件/IM/电话获得对方明确回复确认身份；<br>2. 已完成初次会议或电话沟通；<br>3. 对方已提供有效联系方式（非自动回复或第三方转达）。 |
| 跟进中 | FOL | 🟡 黄色 | 已建立联系但当前处于沟通进行中，需定期追踪 | 1. 已发送资料或需求，等待对方回复；<br>2. 双方已约定下一行动节点（如会议、截止日期）；<br>3. 正在协调内部资源以回应对方请求。 |
| 待确认 | PEN | 🟠 橙色 | 已发起触达但未收到有效回复，或信息存疑需核实 | 1. 通过邮件/IM发送后超过3个工作日无回复；<br>2. 对方电话接通但表示需转接/稍后联系，且后续无回音；<br>3. 获取的联系方式疑似错误（如邮箱退信、号码空号）。 |
| 已失联 | LOST | 🔴 红色 | 多次尝试触达均失败，且无法通过其他渠道确认对方状态 | 1. 连续3次不同时间点（间隔≥24小时）的触达均无响应；<br>2. 所有已知联系方式均失效（邮件退信、电话停机、IM账号停用）；<br>3. 经内部或第三方（如项目发起人）确认对方已离职/转岗且未交接。 |
| 已闭环 | CLS | ⚪ 灰色 | 对接事项已完结，无需继续维护联系 | 1. 项目已正式结项，且相关方无后续交互需求；<br>2. 双方已书面确认对接完成（如验收单、结算单）；<br>3. 对方明确表示不再参与本项目，且已移交至其他负责人。 |

### 2.2 状态流转规则

- **正向流转**: 待确认 → 已对接 → 跟进中 → 已闭环  
- **逆向流转**: 跟进中 → 待确认（若对方超过7个工作日未响应）  
- **特殊流转**:  
  - 待确认 → 已失联（连续3次触达失败）  
  - 已失联 → 待确认（若通过新渠道重新建立联系）  
  - 已闭环 → 跟进中（若项目重启或产生新的对接需求，需经项目经理审批）

### 2.3 状态变更操作规范

每次状态变更需在项目管理系统中记录以下字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| 相关方ID | 是 | 系统唯一标识 |
| 变更前状态 | 是 | 原状态代码 |
| 变更后状态 | 是 | 新状态代码 |
| 变更时间 | 是 | 精确到分钟 |
| 变更人 | 是 | 执行操作的系统账户 |
| 变更原因 | 是 | 简要描述触发变更的事件（如：收到对方邮件确认） |
| 关联沟通记录ID | 否 | 如有对应邮件/IM记录，填写关联ID以便追溯 |

### 3.3 同步机制

#### 3.3.1 周同步会议
- **时间**: 每周一 10:00-10:30（线上会议，固定腾讯会议号：123-456-789）
- **参会人员**: 项目协调专员、项目经理、相关业务方代表（如有需要）
- **议程**:  
  1. 上周状态变更汇总（5分钟）  
  2. 当前待确认/已失联相关方清单及跟进计划（10分钟）  
  3. 高风险相关方讨论（10分钟）  
  4. 下周维护计划确认（5分钟）  
- **输出**: 周同步会议纪要（模板见附录A），需在会议结束后2小时内共享至项目共享文件夹。

#### 3.3.2 自动通知规则
- 当相关方状态变更为“待确认”超过7天且未触发任何跟进动作时，系统自动发送提醒邮件给项目协调专员及其备份。
- 当相关方状态变更为“已失联”时，系统自动发送通知给项目经理，并创建风险预警工单。
- 每月状态复核完成后，系统自动生成状态分布统计报表并推送至项目组群。

### 3.4 数据质量要求
- 字段完整性：相关方姓名、公司、职位、邮箱、电话、来源项目、首次对接日期为必填项，缺失率不得超过5%。
- 历史记录保留：所有状态变更记录保留至少2年，系统自动归档。
- 冲突解决：若两人同时编辑同一记录，系统以后保存者为准，并记录冲突日志。

## 五、异常状态升级路径与风险报备流程

### 5.1 异常状态定义

以下情况视为异常状态，需立即启动升级或报备：

| 异常类型 | 判定标准 | 示例 |
|---------|---------|------|
| 批量失联 | 同一项目中超过30%的相关方处于“已失联”状态 | 某项目共20个相关方，其中7个已失联 |
| 关键角色失联 | 项目经理、技术负责人、决策审批人等关键角色处于“已失联”状态 | Coco作为客户代表失联 |
| 状态长时间未变 | 某相关方处于“待确认”状态超过14天且无任何跟进记录 | 某供应商对接人待确认已18天 |
| 信息冲突 | 同一相关方在不同记录中的状态不一致（如A记录为“已对接”，B记录为“已失联”） | 系统数据与线下台账矛盾 |

### 5.2 升级路径

#### 5.2.1 一级升级（项目协调专员 → 项目经理）
- **触发条件**: 任何相关方从“待确认”变为“已失联”；或任何相关方在“待确认”状态超过10天。
- **动作**: 项目协调专员填写《异常状态升级单》（模板见附录B），通过邮件发送给项目经理，抄送项目助理。
- **响应时限**: 项目经理需在1个工作日内回复处理意见（如：批准失联状态、指派替代对接人、启动内部排查）。

#### 5.2.2 二级升级（项目经理 → 项目总监）
- **触发条件**: 关键角色失联；或批量失联比例超过30%；或一级升级后3个工作日内无有效进展。
- **动作**: 项目经理填写《风险报备单》（模板见附录C），提交至项目总监，并抄送PMO（项目管理办公室）。
- **响应时限**: 项目总监需在2个工作日内召开专题会议，确定应对方案（如：启动应急沟通渠道、调整项目计划、上报高层协调）。

#### 5.2.3 三级升级（项目总监 → 公司管理层）
- **触发条件**: 二级升级后方案无法执行；或失联导致项目关键路径延误超过2周；或涉及合同违约风险。
- **动作**: 项目总监起草《重大风险报告》，提交公司管理层及法务部。
- **响应时限**: 管理层需在5个工作日内决策，必要时启动危机公关或法律程序。

### 5.3 风险报备流程

#### 5.3.1 报备时机
- 当相关方状态变更为“已失联”时，项目协调专员需在2小时内完成初步风险评估。
- 当评估为“高风险”（即可能影响项目里程碑）时，立即启动正式报备。

#### 5.3.2 报备内容要求
风险报备单必须包含以下信息：

1. **相关方信息**: 姓名、公司、角色、失联天数、最后一次有效联系时间。
2. **影响分析**: 失联对项目范围、进度、成本、质量的具体影响（量化，如：预计延迟X天）。
3. **已采取行动**: 已进行的触达尝试（时间、方式、结果）。
4. **建议方案**: 至少两个备选方案（如：启用备份联系人、调整项目计划、寻找替代供应商）。
5. **升级历史**: 已进行的升级层级及结果。

#### 5.3.3 报备记录与跟踪
- 所有风险报备单需编号管理（格式：RISK-YYYYMMDD-XXX），并存档至项目风险管理文件夹。
- 项目经理需每周跟踪报备事项进展，直至状态变更为“已闭环”或“已对接”。
- PMO每月汇总风险报备数据，形成《项目联系状态风险月报》，供管理层审阅。
