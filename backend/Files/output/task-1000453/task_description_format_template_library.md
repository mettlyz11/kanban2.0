# PDF#503 任务描述格式模板库

## 1. 模板库概述与使用说明

### 1.1 目的与范围
本模板库旨在提供一套标准化、可复用的任务描述格式，适用于组织内部的各类工作场景。通过统一字段定义、填充规范和示例，帮助任务发起人快速生成清晰、完整、可追踪的任务描述，减少沟通成本，提升执行效率。

### 1.2 核心原则
- **完整性**：每个任务描述必须包含关键字段（如标题、描述、优先级、截止日期等），确保接收方无需追问即可执行。
- **一致性**：字段名称、格式、取值规范统一，便于系统解析和跨团队协作。
- **可扩展性**：模板支持按场景定制，同时允许用户在规范基础上补充自定义字段。

### 1.3 使用方式
- **直接选用**：根据任务性质从分场景模板中选取，填入具体内容。
- **改编组合**：对通用模板进行字段增删，适配特殊需求。
- **自动生成**：结合任务管理工具（如Jira、Trello、飞书项目）的预设字段，实现自动填充。

### 1.4 模板结构总览
每个模板由以下部分组成：
- **元信息**：模板编号、适用场景、版本号。
- **字段集合**：包含字段名称、数据类型、是否必填、规范说明。
- **填充示例**：一个典型的填写案例。
- **校验规则**：字段值必须满足的条件（如日期格式、优先级值的枚举）。

## 2. 通用任务描述模板

### 2.1 基本字段定义

| 字段名称 | 数据类型 | 必填 | 默认值 | 规范说明 |
|----------|----------|------|--------|----------|
| 标题 | 字符串（≤80字符） | 是 | 无 | 简短概括任务主体，格式：[动词+对象+约束]，如“修复用户登录页面无法跳转的bug” |
| 描述 | 多行文本（≤2000字符） | 是 | 无 | 详细说明任务背景、目标、验收标准、注意事项。建议使用结构化格式（背景、需求、验收条件） |
| 优先级 | 枚举 | 是 | 中等 | 取值：P0(紧急/严重)、P1(高)、P2(中)、P3(低) |
| 截止日期 | 日期（YYYY-MM-DD） | 是 | 无 | 任务最终完成日期，若有明确的时间点可附加具体时间（HH:mm） |
| 负责人 | 字符串 | 是 | 无 | 执行任务的个人或团队名称 |
| 相关文档/链接 | 数组（URL） | 否 | 无 | 关联的文档、设计稿、API文档等外部资源 |
| 依赖任务 | 数组（任务ID） | 否 | 无 | 本任务依赖的其他任务ID |
| 标签 | 数组（字符串） | 否 | 无 | 用于分类的关键词，如“前端”、“紧急”、“性能优化” |

### 2.3 填充示例

```markdown
# 任务标题：实现用户注册页面的邮箱验证功能

## 1. 背景
当前SaaS平台用户注册流程中，邮箱验证步骤缺失，导致大量无效注册和垃圾帐号。需增加邮箱验证环节以提升注册质量。

## 2. 目标
开发一个邮箱验证模块，用户注册后需点击验证邮件中的链接，激活帐号后方可登录。

## 3. 验收标准
- 用户在注册表填写邮箱，点击“注册”后系统发送验证邮件。
- 邮件包含唯一验证链接，链接有效期为24小时。
- 点击链接后，页面提示“验证成功”，并将用户状态改为“已激活”。
- 若用户尝试在未验证状态下登录，系统提示“请先验证邮箱”。
- 支持重新发送验证邮件（每60秒限一次）。

## 4. 附加信息
- **优先级**: P1
- **截止日期**: 2025-06-30
- **负责人**: 后端开发组
- **相关文档**: [登录注册设计稿](https://example.com/design)
- **依赖任务**: 无
- **标签**: 后端, 安全, 注册

## 5. 备注
需配置邮件服务API密钥，开发环境使用SendGrid测试账号。
```

```markdown
# 任务标题：[修复] 订单详情页：点击“取消订单”按钮后页面无响应

## 1. 业务背景
用户反馈在订单详情页点击取消订单时，页面无任何反应，导致用户无法取消待支付订单。该问题影响约15%的用户操作，须紧急修复。

## 2. 技术要求
- 前端：Vue3 + Element Plus
- 后端API：PUT /api/orders/{orderId}/cancel
- 返回值：200时显示成功提示，400时显示错误原因

## 3. 实现方案
初步定位：前端事件绑定错误，点击按钮触发了其他组件的点击事件，导致请求未发出。需检查对应.vue文件的按钮事件。

## 4. 验收环境
- **开发分支**: hotfix/order-cancel-bug
- **测试数据**: 使用测试订单ID: ORD-20250601-001（状态为待支付）
- **技术约束**: 无

## 5. 验收标准
- [ ] 点击取消后弹出确认对话框
- [ ] 确认后调用接口成功，订单状态变为“已取消”
- [ ] 页面自动刷新显示最新状态
- [ ] 单元测试覆盖取消按钮交互逻辑

## 6. 备注
该bug未导致数据丢失，但影响用户体验，优先级P0。
```

## 4. 字段定义与填充规范

### 4.1 通用字段规范细则

| 字段 | 规范细则 |
|------|----------|
| 标题 | 禁止使用过于泛化的词语（如“修复问题”），必须包含具体对象。英文标题首字母大写，中文标题用动宾结构。 |
| 描述 | 采用**三段式结构**：背景（为什么做）、目标（做什么）、验收标准（怎么做才算好）。避免歧义描述，比如使用“在X条件下，当Y发生时，系统应返回Z结果”。 |
| 优先级 | P0：系统瘫痪、安全漏洞、阻塞主流程；P1：核心功能缺失但可临时绕行；P2：非核心功能改进；P3：低优先级优化或装饰性需求。 |
| 截止日期 | 必须为未来日期；若为长期任务，可设置为最近一次里程碑检查日，并备注“持续至X”。 |
| 负责人 | 支持团队名（如“前端组”）或个人名（如“张三”）。若为多人，使用“&”连接（如“李四&王五”）。 |
| 相关文档 | 使用绝对URL或内部网盘路径。若为设计稿，标注版本号。 |
| 依赖任务 | 使用系统内部ID（如TASK-1234）。若无依赖，留空或写“无”。 |
| 标签 | 从预定义标签库中选取（如：紧急、安全、体验、性能、架构、测试）。若需新增，需同步更新标签库定义。 |
