## 五、关键发现与瓶颈问题总结区

### 总体评估结论：**资源严重不足，系统处于高风险状态。** 当前配置仅勉强满足日常低负载办公需求，无法应对未来6个月的业务增长，且已在多个关键维度表现出严重瓶颈，用户体验堪忧。

### 关键发现：

1.  **内存瓶颈是核心矛盾**：8GB统一内存在45个并发SMB连接下已完全耗尽，被迫使用Swap (420MB) 和压缩内存 (1.1GB)。这是导致一切性能恶化的根源。Swap导致：a) 写操作延迟飙升；b) CPU空闲时间被内存压缩和解压缩任务占用（解释了高上下文切换）；c) SSDS SD寿命加速磨损。

2.  **存储I/O成明显短板**：受限于256GB SSD的颗粒数量及控制器能力，以及Samba进程受内存限制后的缓存效率低下，随机读写性能（IOPS, 延迟）未能达到业务要求。写入延迟是瓶颈的核心，直接影响用户的文件保存体验。

3.  **网络带宽接近饱和**：千兆以太网在发送方向已使用650Mbps，考虑到协议开销和增长预期，已不能满足需求。TCP重传率2.5%是网络已达瓶颈或接口/交换机端异常的明显信号，进一步加剧了传输延迟问题。

4.  **并发处理能力脆弱**：虽然在连接数上表面达标，但内存和存储资源已被耗尽，导致Samba服务本身的请求排队时间高达200ms，用户体验极差。这表明系统已不具备处理下一波负载增长的能力。

### 资源配置调整建议（按优先级排序）：

**优先级1：立即行动 – 缓解最严重瓶颈**

1.  **升级内存容量**：
    - **方案A (首选)**：更换为 **16GB统一内存** 或 **24GB统一内存** 的Macmini（M2/M3系列）。这是最根本的解决方案，可彻底解除内存瓶颈，消除Swap，释放CPU压力，提高文件缓存效率。
    - **方案B (临时措施)**：在当前系统上，限制Samba服务的最大内存使用（如调整`max disk size` 和 `kernel chnages`），强制系统为文件缓存预留更多空间（如使用`vfs_cache_pressure` 参数调整内核行为），但这不能解决根本问题。

2.  **优化网络配置**：
    - **行动**：检查交换机端口，确保无协商问题（半双工等）。将Macmini的网络接口升级至 **2.5GbE** 或 **10GbE**（通过雷雳接口适配器），以解除网络带宽瓶颈，降低重传率。
    - **替代方案**：如果无法升级内部网络，考虑将常用或大的共享文件夹迁移到本地网速更快的设备，或部署WAN优化设备。

**优先级2：中期扩容 – 提升存储性能**

3.  **升级存储I/O**：
    - **行动**：将内部256GB SSD更换为 **1TB或2TB NVMe SSD** (需确认Macmini兼容性) 或通过雷雳接口外接高速NVMe SSD（如三星990 Pro，西数SN850X等）。新SSD能提供更高的IOPS（>10,000）和更低的延迟（<5ms），消除存储瓶颈。
    - **推荐**：使用外接NVMe + 2.5GbE网卡，构成独立高性能存储通道，实现成本效益最大化。

**优先级3：架构优化 – 提升极限并发能力**

4.  **引入分层存储或缓存策略**：
    - **行动**：如果无法更换硬件，可在文件服务器上启用 **L2ARC** (如果使用ZFS) 或使用软件定义缓存软件，将高频访问的热数据缓存到性能更好的存储层。
    - **不建议**：在当前配置下继续增加用户数或文件大小。
