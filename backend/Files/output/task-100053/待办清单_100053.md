### 📋 阶段一：数据采集（人工执行，耗时约2-4小时）
**操作清单：**
1. **硬件与系统基线**
   - 记录Mac mini型号（M1/M2/M3/Intel）、CPU核心数、内存容量、内置SSD容量/读写速度

2. **负载与性能指标**（在业务高峰时段采集，连续运行`top`/`iostat`/`nettop` 15分钟）
   - `top`：CPU使用率（`%CPU`）、内存压力（`Memory Pressure`）、Swap使用量
   - `iostat -d 5`：磁盘读写吞吐量（`KB/t`、`MB/s`）、队列长度（`qlen`）、IOPS
   - `nettop -l 1`：网络吞吐（`in/out MB/s`）、SMB并发连接数

3. **业务需求**

### 🛠 阶段三：调整建议输出（按缺口匹配方案）
**根据阶段二判定结果，直接套用以下决策树生成建议：**
- 🔹 **CPU/内存瓶颈** → 升级至16GB/24GB内存版Mac mini；关闭`mds`/`spotlight`索引共享目录；限制Time Machine本地快照
- 🔹 **磁盘I/O瓶颈** → 内置SSD仅放系统，共享数据迁移至外置NVMe RAID0（Thunderbolt 3/4）；启用`apfs.util -b`优化；关闭Finder预览生成
- 🔹 **网络瓶颈** → 更换2.5GbE/10GbE USB-C网卡；路由器/交换机开启流控；SMB启用`SMB_DIRECT`（若客户端支持）；禁用AFP
- 🔹 **并发/架构瓶颈** → 单机承载>80并发时，拆分为2台Mac mini+DNS轮询；或迁移至TrueNAS/群晖NAS+Mac mini作接入网关
- 🔹 **配置调优**（macOS终端执行）：
  ```bash
  # 提升SMB读写缓存与连接稳定性
  sudo sysctl -w net.smb.fs.kpi.max_threads=16
  sudo sysctl -w vfs.generic.maxvnodes=500000
  # 关闭不必要的网络发现与广播
  sudo defaults write /Library/Preferences/SystemConfiguration/com.apple.smb.server.plist DisableNetBIOS -bool true
  ```
