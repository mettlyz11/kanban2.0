## 4. P0-P2高优事项详细拆解与排期建议

### 4.1 P0 - 紧急修复（本周必须完成）

#### 4.1.1 BKD-02: 会话管理服务数据库连接池泄漏
- **严重程度**: 生产环境P0级故障
- **当前表现**: 服务运行4小时后连接数突破max_connections（200），导致新会话无法建立
- **根因分析**: 会话关闭时未正确调用`connection.close()`，且连接池的`maxIdle`配置为0导致连接不被复用
- **修复方案**:
  ```python
  # 修复前 (错误代码)
  def get_session(session_id):
      conn = pool.get_connection()
      cursor = conn.cursor()
      cursor.execute("SELECT * FROM sessions WHERE id=%s", (session_id,))
      result = cursor.fetchone()
      # 缺少 conn.close() 或 conn.release()
      return result
  
  # 修复后 (正确代码)
  def get_session(session_id):
      conn = None
      try:
          conn = pool.get_connection()
          cursor = conn.cursor()
          cursor.execute("SELECT * FROM sessions WHERE id=%s", (session_id,))
          result = cursor.fetchone()
          return result
      except Exception as e:
          logger.error(f"Session query failed: {e}")
          raise
      finally:
          if conn:
              conn.close()  # 确保连接归还到池
  ```
- **配置更新**: `connection_pool.py`中`maxIdle=20`, `maxActive=50`
- **排期**: 12月16日09:00-12:00修复并部署hotfix；12月16日14:00-16:00观察验证
- **负责人**: 后端团队-张伟

#### 4.1.2 TTS-04: 语速倍率在0.5x-3.0x范围内线性度修复
- **严重程度**: 用户反馈2.0x以上语速失真，实际速度仅提升1.3x
- **根因分析**: 波形拼接算法中`time_stretch_factor`计算错误，对数映射导致非线性
- **修复方案**:
  ```python
  # 修复前 (非线性映射)
  def calculate_stretch_factor(requested_speed):
      return math.log(requested_speed) / math.log(2.0)  # 错误

  # 修复后 (线性映射)
  def calculate_stretch_factor(requested_speed):
      # 0.5x -> 0.5, 1.0x -> 1.0, 3.0x -> 3.0
      return requested_speed  # 直接返回原始倍数
  ```
- **测试验证**: 录制0.5x, 1.0x, 1.5x, 2.0x, 2.5x, 3.0x各10个样本，使用`praat`工具测量实际时长
- **排期**: 12月16日全天开发；12月17日上午测试验证
- **负责人**: TTS团队-李娜
