## 二、量化打分规则与权重分配

### 2.1 评分标准

每个指标采用10分制评分，具体规则如下：

| 分数区间 | 含义 | 描述 |
|----------|------|------|
| 9-10 | 优秀 | 完全满足或超出预期，无改进空间 |
| 7-8 | 良好 | 基本满足要求，存在少量可优化点 |
| 5-6 | 中等 | 满足核心要求，但存在明显不足 |
| 3-4 | 较差 | 部分满足要求，需较大改进 |
| 1-2 | 极差 | 几乎不满足要求，需根本性调整 |
| 0 | 不适用 | 该指标当前无法评估或与项目无关 |

### 2.2 特殊指标评分细则

**反爬机制复杂度（TF-01）评分规则：**
- 等级1（1分）：无任何反爬措施，可直接访问
- 等级2（3分）：基础User-Agent验证
- 等级3（5分）：IP频率限制+简单验证码
- 等级4（7分）：动态渲染+复杂验证码+签名验证
- 等级5（9分）：多层级反爬+设备指纹+行为分析

**法律合规风险（RC-01）评分规则：**
- 等级1（1分）：完全合规，robots.txt明确允许
- 等级2（3分）：基本合规，存在少量灰色地带
- 等级3（5分）：中等风险，需谨慎处理
- 等级4（7分）：高风险，建议咨询法务
- 等级5（9分）：极高风险，建议放弃

### 2.4 综合得分计算公式

```
综合得分 = Σ(每个指标得分 × 该指标最终权重)
```

## 三、风险阈值与优先级判定逻辑

### 3.1 风险等级划分

| 风险等级 | 综合得分范围 | 描述 |
|----------|--------------|------|
| 低风险 | ≥7.5分 | 项目条件优越，建议优先推进 |
| 中风险 | 5.0-7.4分 | 项目条件一般，需关注特定风险点 |
| 高风险 | 2.5-4.9分 | 项目条件较差，建议谨慎评估 |
| 极高风险 | <2.5分 | 项目条件恶劣，建议暂停或放弃 |

### 3.2 一票否决条件

出现以下任一情况时，项目自动进入"暂停"状态：

1. **法律合规风险（RC-01）≥8分**：存在严重法律风险
2. **IP封禁风险（RC-02）≥80%**：目标网站封禁概率极高
3. **人力投入预估（RI-01）> 团队可用工时（RI-04）× 4**：资源缺口超过4倍
4. **竞品进度（MT-01）≥9分**：竞品已上线且领先优势明显

### 3.3 优先级判定矩阵

| 综合得分 | 风险等级 | 一票否决 | 建议决策 |
|----------|----------|----------|----------|
| ≥7.5 | 低风险 | 否 | **继续并优先**：立即启动资源分配 |
| ≥7.5 | 低风险 | 是 | **有条件继续**：解决否决项后优先 |
| 5.0-7.4 | 中风险 | 否 | **继续但谨慎**：制定风险应对计划 |
| 5.0-7.4 | 中风险 | 是 | **暂停**：优先解决否决项 |
| 2.5-4.9 | 高风险 | 否 | **评估后决定**：需管理层决策 |
| 2.5-4.9 | 高风险 | 是 | **暂停**：重新规划项目方向 |
| <2.5 | 极高风险 | 否 | **建议暂停**：寻找替代方案 |
| <2.5 | 极高风险 | 是 | **立即停止**：项目终止 |

### 3.4 动态调整规则

- **每两周重新评估一次**：所有指标需更新最新数据
- **触发阈值时即时评估**：当任一指标变化超过30%时
- **环境重大变化时重新评估**：如目标网站改版、政策变化等
