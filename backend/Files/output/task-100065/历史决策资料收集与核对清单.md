## 二、关键决策识别标准

### 2.1 决策阈值定义

以下情况**必须**被识别为决策并录入日志：

| 决策类型 | 识别阈值 | 示例 |
|----------|----------|------|
| 方案选择 | 在两个或多个备选方案中做出选择 | 选用A型睡眠监测手环而非B型 |
| 范围变更 | 项目范围增加/减少≥5%工作量 | 新增"睡眠环境噪音检测"模块 |
| 资源调配 | 涉及≥2人/周的工时调整，或≥5万元预算变更 | 从数据组调拨1名工程师支援算法组2周 |
| 风险应对 | 选择实施某一风险缓解措施 | 决定采购备用服务器防止数据丢失 |
| 里程碑调整 | 项目关键节点日期变更≥3天 | 将用户测试截止日从1月20日延至1月25日 |
| 技术选型 | 涉及核心模块的技术栈变更 | 将数据库从MySQL切换为PostgreSQL |
| 外部合作 | 引入新的供应商、顾问或合作伙伴 | 与XX睡眠研究所签订合作协议 |

### 2.2 日常沟通与执行动作排除规则

以下情况**不得**视为决策，不纳入日志：

| 排除类别 | 具体内容 | 示例 |
|----------|----------|------|
| 日常任务分配 | 常规工作指派，不涉及方向性选择 | "张三负责整理用户反馈" |
| 进度汇报 | 仅陈述完成情况，无选择/批准 | "上周完成了数据分析" |
| 信息同步 | 仅传递信息，无决策点 | "用户反馈报告已上传共享" |
| 非正式讨论 | 未形成结论的头脑风暴或闲聊 | "也许可以考虑用蓝牙连接"（无人跟进） |
| 执行细节 | 不影响项目目标的实现方式 | "报告用12号字体还是14号字体" |
| 系统自动通知 | 机器人消息、自动告警 | "Jira任务SLP-123状态变更为进行中" |
| 重复确认 | 对已做决策的再次确认 | "我们之前决定用手环，对吧？" |

### 2.3 模糊情况处理规则

当决策识别存在争议时，遵循以下规则：

1. **时间维度**：若该事项后续导致了≥2项任务的产生或变更，则视为决策
2. **成本维度**：若该事项涉及≥5000元的直接或间接成本，则视为决策
3. **影响维度**：若该事项影响到≥3个干系人的工作内容，则视为决策
4. **升级原则**：若仍无法判定，提交项目经理（李总）在24小时内裁定

## 四、干系人交叉核对流程

### 4.1 核对流程总图

```
[初稿生成] → [初稿分发] → [干系人核对] → [反馈收集] → [修正] → [二次核对] → [签字确认] → [归档]
   2天           0.5天         3天            1天          1天        1天          0.5天        0.5天
```

### 4.2 各阶段详细要求

#### 4.2.1 初稿生成（责任人：各数据源负责人）
- 按第一部分收集范围提取原始数据
- 按第三部分字段映射表填入日志
- 生成Excel文件，命名规则：`SLP_DEC_draft_<数据源>_<日期>.xlsx`
- 提交至：`\\slp-proj-01\archive\decisions\draft`

#### 4.2.2 初稿分发（责任人：项目助理）
- 汇总所有数据源初稿，去重合并
- 按决策时间排序，生成完整草稿
- 通过邮件分发给以下干系人：
  - 项目经理：李总
  - 技术负责人：张博士
  - 产品负责人：王芳
  - 质量经理：赵刚
  - 各小组组长（如有涉及）

#### 4.2.3 干系人核对（责任人：各干系人）
- 核对内容：
  - 决策是否真实发生（是否存在虚假记录）
  - 决策描述是否准确（是否存在曲解或遗漏）
  - 决策日期是否正确（是否存在时间错误）
  - 决策者是否完整（是否存在遗漏决策参与人）
  - 决策影响是否量化（是否存在模糊表述）
- 核对方式：
  - 在Excel中使用"批注"功能标注问题
  - 或填写《决策核对反馈表》（模板见附录B）
- 时限：收到邮件后3个工作日内反馈

#### 4.2.4 反馈收集与修正（责任人：项目助理）
- 汇总所有干系人反馈
- 对标注的问题逐条处理：
  - 信息错误：查找原始数据源修正
  - 信息缺失：标记为"待确认"（见第五部分）
  - 争议问题：提交项目经理裁定
- 修正后生成V2版本

#### 4.2.5 二次核对（责任人：涉及修正的干系人）
- 仅针对修正部分进行核对
- 时限：1个工作日

#### 4.2.6 签字确认（责任人：项目经理、质量经理）
- 打印最终版决策日志（或使用电子签名）
- 项目经理和质量经理共同签字
- 签署日期为最终确认日期
- 扫描件归档至：`\\slp-proj-01\archive\decisions\final`

### 4.3 核对节点时限汇总

| 节点 | 责任人 | 时限 | 超时处理 |
|------|--------|------|----------|
| 初稿生成 | 数据源负责人 | 2个工作日 | 项目助理每日跟踪，超时上报项目经理 |
| 初稿分发 | 项目助理 | 0.5个工作日 | 无 |

## 五、信息缺失处理预案

### 5.1 信息缺失等级定义

| 等级 | 定义 | 处理优先级 | 示例 |
|------|------|------------|------|
| L1-轻微缺失 | 非必填字段缺失 | 低 | 缺少"关联任务"字段 |
| L2-中度缺失 | 必填字段缺失，但可通过其他数据源推断 | 中 | 缺少"决策依据"但会议录音可查 |
| L3-严重缺失 | 必填字段缺失，且无法从任何数据源获取 | 高 | 缺少"决策者"且无任何记录 |
| L4-无法验证 | 记录存在但无法确认真实性 | 最高 | 仅有一条Slack消息声称决策，无其他佐证 |

### 5.2 缺失处理流程

```
[发现缺失] → [等级判定] → [L1/L2: 自行补全] → [补全后标记] → [归档]
                   ↓
              [L3/L4: 启动访谈] → [访谈记录] → [补录] → [特殊标记] → [归档]
```

### 5.3 关键人访谈提纲

当无法从现有数据源获取信息时，启动访谈流程。以下为标准化访谈提纲：

#### 5.3.1 访谈准备
- 确定访谈对象（决策相关干系人）
- 准备缺失信息列表
- 预约30分钟访谈时间
- 准备录音设备（需征得同意）

#### 5.3.2 访谈问题模板

**背景确认**：
1. 请问您在睡眠质量提升项目中担任什么角色？
2. 您还记得在[时间段]期间参与过哪些重要的项目决策吗？

**决策细节追问**：
3. 关于[决策标题/描述]，您是否记得当时讨论的具体背景？
4. 这个决策是由谁提出的？最终由谁拍板？
5. 当时考虑了哪些备选方案？为什么最终选择了这个方案？
6. 这个决策对项目有什么影响？比如进度、成本、范围等？

**时间确认**：
7. 您
