## 1. 维护角色与职责分工

### 1.1 角色矩阵

| 角色名称 | 人员配置 | 职责范围 | 任期要求 |
|----------|----------|----------|----------|
| 记录人 | 项目组成员（轮值制，每月轮换） | 负责决策记录的即时录入与初步格式校验 | 至少参与项目2个月以上 |
| 审核人 | 项目副经理或指定资深成员 | 负责决策记录的准确性审核与完整性确认 | 具备项目决策参与资格 |
| 归档管理员 | 项目管理办公室（PMO）指定人员 | 负责决策日志的版本控制、存储管理与权限分配 | 固定人员，不轮换 |
| 决策委员会 | 项目经理、技术负责人、业务负责人、质量负责人 | 负责重大决策的审批、变更审批与争议裁决 | 项目全周期 |

### 1.2 具体职责说明

#### 1.2.1 记录人职责
- 在决策发生后的规定时限内完成记录录入
- 确保决策内容、背景、参与人员、时间等关键信息完整
- 对录入内容进行初步格式校验，确保符合规范要求
- 轮换交接时，需完成至少3次交接培训，并提供交接确认单

#### 1.2.2 审核人职责
- 在记录人提交后24小时内完成审核
- 核对决策内容的准确性，必要时与参与人员确认
- 检查附件完整性，确保关联文档已正确上传
- 对不符合规范的记录提出修改意见并退回

#### 1.2.3 归档管理员职责
- 维护决策日志的版本控制体系
- 定期（每周五下午）检查日志完整性
- 管理权限分配与调整
- 处理版本冲突与恢复请求
- 每月生成权限使用报告

#### 1.2.4 决策委员会职责
- 审批重大决策（涉及预算超过5万元、影响项目关键路径、变更核心算法）
- 审核决策变更申请
- 处理决策争议与仲裁
- 每季度召开决策有效性评估会议

## 2. 新增决策录入SOP

### 2.1 触发条件

以下情况发生时，必须在规定时限内完成决策记录：

| 触发类别 | 具体情形 | 填写时限 |
|----------|----------|----------|
| 会议决策 | 项目周会、专题会议、评审会议中形成的正式决策 | 会议结束后4小时内 |
| 紧急决策 | 因突发事件需立即做出的决策（如硬件故障应急方案） | 决策做出后1小时内 |
| 邮件决策 | 通过邮件沟通达成的共识性决策 | 确认共识后2小时内 |
| 即时通讯决策 | 通过企业微信、Slack等工具达成的决策 | 对话结束后1小时内 |
| 书面审批决策 | 通过正式审批流程做出的决策 | 审批完成当日 |

### 2.2 填写时限要求

- 常规决策：24小时内完成录入
- 紧急决策：4小时内完成录入
- 重大决策（需决策委员会审批）：审批完成后2小时内完成录入

## 3. 变更、撤销与版本控制流程

### 3.1 决策变更流程

#### 3.1.1 常规变更路径

1. **发起申请**：变更申请人填写《决策变更申请表》，说明变更原因、变更内容及影响分析
2. **初步审核**：审核人在2个工作日内完成初审，判断变更等级
3. **等级判定**：
   - **一级变更**（影响范围小，无需重新评估）：由审核人直接审批
   - **二级变更**（影响中等，需重新评估）：需提交决策委员会审批
   - **三级变更**（重大变更，完全撤销原决策）：需召开专题会议讨论
4. **审批通过后**：归档管理员更新决策日志，生成新版本
5. **记录变更**：在原决策记录中新增变更记录，并关联新决策编号

#### 3.1.2 紧急变更通道

当遇到以下紧急情况时，可启动紧急变更通道：
- 系统故障导致服务中断
- 安全漏洞需要立即修复
- 法律法规要求紧急调整

**紧急变更流程**：
1. 记录人电话通知审核人和归档管理员
2. 1小时内完成临时决策记录并邮件发送
3. 24小时内补充正式审批流程
4. 48小时内完成完整记录

### 3.2 决策撤销流程

1. **撤销申请**：提交《决策撤销申请》，说明撤销原因及替代方案
2. **影响评估**：决策委员会在3个工作日内完成影响评估
3. **审批**：需决策委员会全体成员2/3以上同意
4. **撤销记录**：归档管理员标记原决策为"已撤销"，并关联撤销决策编号
5. **历史保留**：原决策记录不可删除，仅可标记状态

### 3.3 版本控制策略

#### 3.3.1 版本命名规则

```
SQP-DEC-YYYYMMDD-XXX-Vn
│    │      │       │  │
│    │      │       │  └── 版本号（V1、V2...）
│    │      │       └───── 当日序列号
│    │      └───────────── 决策日期
│    └──────────────────── 决策标识
└───────────────────────── 项目代号
```

#### 3.3.2 历史快照保留策略

| 版本类型 | 保留期限 | 存储位置 | 访问权限 |
|----------|----------|----------|----------|
| 当前版本 | 永久保留 | 主存储区 | 项目全员 |
| 前3个版本 | 永久保留 | 历史存储区 | 项目核心成员 |
| 更早版本 | 项目结束后保留3年 | 归档存储区 | 归档管理员+项目经理 |
| 已撤销版本 | 项目结束后保留5年 | 归档存储区 | 归档管理员+项目经理 |

#### 3.3.3 版本更新操作规范

1. **更新触发**：任何决策内容的修改、补充或状态变更
2. **更新流程**：
   - 记录人创建新版本（版本号+1）
   - 在新版本中明确标注变更内容
   - 保留旧版本作为历史快照
   - 审核人审核新版本
3. **版本对比**：每次更新必须提供版本差异说明
4. **版本恢复**：如发现错误，可申请恢复至指定历史版本，需归档管理员和项目经理共同确认

| 外部审计人员 | 审计授权范围 | 无 | 无 | 无 | 审计授权范围 | 无 |

### 4.2 可见范围控制

- **公开决策**：项目所有成员可见，包括普通成员
- **内部决策**：仅项目核心成员（决策委员会、审核人、记录人）可见
- **保密决策**：仅决策委员会成员可见，需单独申请查看权限

### 4.3 导出限制

| 导出方式 | 允许角色 | 限制条件 | 审批要求 |
|----------|----------|----------|----------|
| 打印 | 项目全员 | 仅限非保密决策 | 无需审批 |
| PDF导出 | 项目核心成员 | 水印标注"项目内部资料" | 无需审批 |
| Excel导出 | 决策委员会+审核人 | 脱敏后导出 | 无需审批 |
| 原始数据导出 | 归档管理员 | 需记录导出日志 | 项目经理审批 |
| 批量导出（>100条） | 归档管理员 | 需记录导出日志+加密传输 | 项目经理+决策委员会审批 |

### 4.4 敏感信息脱敏规则

#### 4.4.1 脱敏等级划分

| 脱敏等级 | 数据类型 | 处理方式 | 示例 |
|----------|----------|----------|------|
| L1 | 个人姓名 | 姓氏保留，名字用*替代 | 张三 → 张* |
| L2 | 联系方式 | 中间4位用*替代 | 13812345678 → 138****5678 |
| L3 | 身份证号 | 前6位后4位保留，中间用*替代 | 110101199001011234 → 110101********1234 |
| L4 | 财务数据 | 整数部分保留，小数部分用*替代 | 50000.00 → 50000.** |
| L5 | 技术参数 | 核心参数用[已脱敏]替代 | 采样频率100Hz → 采样频率[已脱敏] |

#### 4.4.2 脱敏触发条件

- 导出给外部人员时自动触发
- 生成审计报告时自动触发
- 普通成员查看保密决策时自动触发

### 4.5 安全保密要求

1. **存储安全**：所有决策日志存储在项目专用加密服务器，使用AES-256加密
2. **传输安全**：导出或传输决策日志时，必须使用HTTPS或SFTP协议
3. **访问审计**：所有访问操作均记录日志，包括访问时间、人员、操作类型
4. **违规处理**：
   - 首次违规：警告并限制权限7天
   - 二次违规：限制权限30天并通报批评
   - 三次违规：取消项目权限并上报项目管理办公室

## 5. 定期审计与项目复盘机制

### 5.1 季度核对清单

每季度末，归档管理员需完成以下核对工作：

#### 5.1.1 完整性检查

| 检查项 | 检查标准 | 检查方法 | 完成标记 |
|--------|----------|----------|----------|
| 决策数量核对 | 实际记录数≥会议纪要中决策数 | 对比会议纪要 | □ |
| 记录时限检查 | 所有记录均在规定时限内完成 | 检查时间戳 | □ |
| 附件完整性 | 每个决策记录关联附件≥1个 | 逐个检查 | □ |
| 审批完整性 | 所有决策均有审核人确认 | 检查审批字段 | □ |
| 版本一致性 | 当前版本与最新审批版本一致 | 版本号对比 | □ |

#### 5.1.2 质量评估

| 检查项 | 评分标准（1-5分） | 实际评分 | 改进建议 |
|--------|-------------------|----------|----------|
| 记录详实度 | 是否包含决策背景、内容、过程、影响分析 |  |  |
| 格式规范性 | 是否符合模板要求，无遗漏字段 |  |  |
| 时效性 | 是否在规定时限内完成 |  |  |
| 可追溯性 | 能否通过决策编号追溯到原始讨论记录 |  |  |
| 可理解性 | 非参与人员能否准确理解决策内容 |  |  |

### 5.2 决策有效性评估

#### 5.2.1 评估周期
- 常规评估：每季度一次
- 重大决策评估：决策执行完成后30天内
- 年度综合评估：每年12月

#### 5.2.2 评估维度

| 评估维度 | 权重 | 评估标准 | 数据来源 |
|----------|------|----------|----------|
| 决策准确性 | 30% | 决策是否解决了原始问题 | 执行结果报告 |
| 决策时效性 | 20% | 决策是否在最佳时机做出 | 时间戳对比 |
| 决策成本效益 | 25% | 决策带来的收益是否大于成本 | 财务数据 |
| 决策可执行性 | 15% | 决策是否顺利执行 | 执行反馈 |
| 决策影响力 | 10% | 决策对项目整体目标的贡献 | 项目绩效报告 |

#### 5.2.3 评估结果应用

| 评估得分 | 评级 | 处理措施 |
|----------|------|----------|
| 90-100分 | A级（优秀） | 纳入最佳实践案例库，作为培训素材 |
| 75-89分 | B级（良好） | 总结经验，持续优化 |
| 60-74分 | C级（合格） | 分析改进点，制定优化计划 |
| <60分 | D级（不合格） | 启动问题分析，必要时重新决策 |

### 5.3 经验沉淀机制

#### 5.3.1 经验分类

| 类别 | 定义 | 示例 |
|------|------|------|
| 成功经验 | 决策执行后达到或超过预期效果 | 采用新算法后识别准确率提升15% |
| 失败教训 | 决策未达预期或产生负面影响 | 因未充分考虑硬件兼容性导致部署延期 |
| 优化建议 | 对决策流程或方法的改进意见 | 建议增加技术可行性预审环节 |

#### 5.3.2 经验沉淀流程

1. **识别**：在评估过程中识别可沉淀的经验
2. **提炼**：由记录人提炼成标准化的经验卡片
3. **审核**：审核人确认经验真实性和可复制性
4. **入库**：归档管理员将经验存入项目知识库
5. **推广**：在项目周会上分享，并纳入新成员培训

```mark
