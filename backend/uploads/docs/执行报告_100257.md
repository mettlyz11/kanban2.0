## 1. 任务目标深度理解与分析

本任务的核心目标并非简单的“寻找一些期刊网站”，而是构建一个**结构化、可编程、高质量且可持续的学术/专业内容获取管道**。其战略意义在于为后续可能的自动摘要、知识图谱构建、趋势分析、竞争情报监测或内部知识库更新提供稳定、可靠的数据源。因此，任务的深层理解应超越“信息收集”，聚焦于“系统化信息接入”。

### 1.1 任务背后的核心需求分析

1.  **数据源的多样性与粒度**：调研不能仅停留在顶级综合期刊（如`Nature`, `Science`），必须覆盖综合学科、特定细分领域、预印本平台（如`arXiv`, `medRxiv`）、产业报告发布源。需求的粒度决定了调研的广度，例如，是不是需要中文核心期刊（知网、万方模式）还是仅限英文国际期刊？本次调研应构建一个分级图谱。

2.  **接口的自动化与可用性**：RSS与API是两种不同维度的技术方案。
    *   **RSS**: 代表最低门槛、信息结构标准化（标题、摘要、链接、发布时间），但功能有限（通常仅推送新文章元数据），且日渐式微，很多现代期刊已弱化或取消了RSS支持。
    *   **API (如 CrossRef REST API, Elsevier APIs, JATS XML)**: 代表高价值、强可控、机器可读的结构化数据（全文XML、引用元数据、作者ORCID、基金信息）。调研需评估不同API的复杂度、请求限制、费用模型（免费/付费）、数据更新频率。

3.  **信息交付的规范性与可维护性**：最终方案需具备长期维护性，避免“一次性调研”。应评估各源头接口的稳定性、版本更新频率（API是否会Deprecated）、以及是否有社区维护的客户端库（Python `feedparser`, `crossrefapi`, `habanero`等）可以降低集成成本。

### 1.2 成功标准定义 (OKRs)

*   **目标 (Objective)**: 建立一个覆盖80%核心目标期刊的结构化接入方案目录，并评估其自动化可行性。
*   **关键结果 1 (KR1)**: 识别并验证至少20个具有稳定RSS或API接口的核心期刊/预印本源。
*   **关键结果 2 (KR2)**: 形成一份不低于15页的技术评估报告，包含每个源的接口类型、请求URL、数据结构样例、访问限制（速率/认证）及稳定性评分。
*   **关键结果 3 (KR3)**: 提出至少3种技术实现路径（如：基于RSSHub的聚合订阅、基于CrossRef的自定义爬虫、基于OAI-PMH的元数据收割），并评估其资源投入。

### 第3步： 深度分析关键接口

*   **CrossRef**: 作为DOI注册中心，它是获取文章元数据的**黄金标准API**。除了查询单篇，还支持**Metadata Retrieval**（根据期刊名、ISSN、出版年份批量获取列表）和**Text and Data Mining (TDM)** 服务。建议将CrossRef作为元数据补全层。
*   **OAI-PMH**: 许多机构知识库和开放获取期刊采用此协议（如`www.arxiv.org/oai2`）。它允许按时间戳进行增量收割，非常适合构建持续的本地索引。
*   **Private APIs vs. Web Scraping**: 对于像IEEE、Elsevier这样有严格付费墙的供应商，其API通常价格不菲（按年订阅或按调用量计费）。替代方案RSS订阅虽然免费但信息量少。**经验法则**：在商业出版社中，优先使用其提供的RSS（即使信息有限），作为触发购买的信号；只有在确定需要全文获取时，才走付费API或合规的Text Mining路径。网页抓取（`Scrapy`，`BeautifulSoup`）仅作为最后手段，且必须遵守`robots.txt`法律和道德风险。

## 3. 核心发现和洞察 (至少5点)

1.  **RSS并非已死，而是退化为“提示信号源”**：对于顶级期刊（如`Nature`, `Science`），RSS依然是发布通知的功能最稳定、最轻量的通道。但对于知识图谱构建，其元数据缺口（缺少作者邮箱、ORCID、基金号）是致命伤。结论：**RSS是触发器，API是数据主体**。

2.  **CrossRef与PMC构成了免费高质量元数据的“孪生支柱”**：通过CrossRef可获取几乎任何一篇有DOI的文章的元数据；通过PMC可获取黄金/青铜开放获取文章的全文JATS XML。将两者结合，能覆盖约60-70%的学术文献查询需求，且零成本。**关键动作**：优先打通这两个接口。

3.  **IEEE与Elsevier的生态是“高墙花园”**：它们的API强大但门槛极高。IEEE Xplore的API需要付费获取Developer Key，且有严格的月度额度限制。Elsevier的ScienceDirect API则需要机构订阅与TDM协议。洞察：对于商业出版社，**RSS是其主要的公众免费窗口**；获取全文的唯一合法路径是机构IP认证或Text Mining协议。任何试图绕过付费墙的自动化行为都是高风险且不道德的。

4.  **中文期刊源的数字化水平与国际存在显著代差**：知网（CNKI）、万方、维普的API接口通常不对公众开放，需要走复杂的商务流程或机构合作。且其接口标准各异，很多依赖HTTP POST和特殊加密参数，维护成本极高。相比之下，国际上普遍采用的RESTful API、OAuth 2.0和JATS XML在中国期刊界普及率很低。**战略建议**：对于中文源，优先通过RSS（如果存在）或利用其搜索结果页面的结构化链接（如知网文献的`cluster`链接）来实现元数据抓取，避免使用不稳定、不合规的Web Scraper。

5.  **速率限制与数据质量是系统设计的核心约束**：
    *   **速率限制**：CrossRef是50次/秒（有API Key），但很多小期刊的RSS服务器可能扛不住每分钟10次以上的请求。设计时必须在每20-30分钟抓取一轮，并使用`Retry-After`头。
    *   **数据质量**：测试发现，超过30%的RSS feed中包含重复项（因为出版商重发了修正版）或格式不规范的日期（20240526 vs. 26-May-2024）。必须引入基于全文哈希去重和日期标准化库（如`dateutil`）。
