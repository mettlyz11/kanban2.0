## 一、系统概览

### 1.1 知识大脑是什么？

OpenClaw 知识大脑是一个**类脑架构的四层知识库系统**，模仿人类大脑的工作方式，将信息分为：

| 脑区 | 功能 | 存储位置 |
|------|------|---------|
| 🧠 **海马体** — 情景记忆 | 记录"某天发生了什么"：会议、决策、任务 | `memory/*.md`、`Events/`、`wiki/logs/` |
| 🧠 **新皮层** — 语义知识 | 概念定义、论文笔记、方法说明 | `wiki/concepts/`、`wiki-papers/` |
| 🧠 **丘脑** — 检索路由 | 智能搜索、关联发现、权重调整 | `memory/graph/`、检索脚本 |
| 🧠 **小脑** — 程序技能 | 自动化流程、Agent能力注册 | `skills/`、`capabilities.json` |

### 1.2 五层知识架构

```
Layer 0 情景记忆  →  事件、日志、日记（时间线索引）
Layer 1 实体关系  →  人-机构-项目-资金（核心关系网）
Layer 2 文献概念  →  论文-概念-方法（语义网络）
Layer 3 跨域关联  →  实体↔文献↔概念↔项目（全局连接）
Layer 4 程序技能  →  Agent能力、自动化规则（技能执行）
```

### 1.3 系统规模（截至2026-04-20）

| 指标 | 当前值 |
|------|--------|
| Vault总大小 | 4.6 GB |
| 概念页面 | 1,709个（⚠️含大量垃圾待清理） |

## 二、知识库录入规范（SOP-01）

### 2.1 总原则

**三条铁律：**
1. **先建实体，再写内容** — 确保每个重要事物在知识图谱中有对应节点
2. **双向链接是灵魂** — 每条记录必须用 `[[wikilink]]` 关联相关实体
3. **标签是分类的骨架** — 所有文件必须包含规范的 frontmatter 标签

### 2.2 文件命名规范

| 文件类型 | 命名格式 | 示例 |
|---------|---------|------|
| 人物 | `中文名.md` 或 `英文名.md` | `刘宇宙.md` |
| 公司 | `公司简称.md` | `和光智成.md` |
| 项目 | `项目代号.md` | `T109.md` |
| 论文 | `年份-第一作者-关键词.md` | `2026-Zhang-SingleAtomCatalysis.md` |
| 概念 | `领域前缀:概念名.md` | `comp:DFT.md`、`ai:GNN.md` |
| 事件 | `YYYY-MM-DD 事件名.md` | `2026-04-18 北航AI实验室揭牌.md` |

### 2.3 Frontmatter 规范（必须）

所有 Markdown 文件**必须**包含 YAML frontmatter：

```markdown
---
title: "文件标题"
type: person|org|project|paper|concept|event
created: 2026-04-20
updated: 2026-04-20
tags: [一级标签/二级标签, status/active]
---
```

**各类型扩展字段：**

#### 人物 (person)
```yaml
---
title: "张三"
type: person
org: "和光智成"
role: "研究员"
email: "zhangsan@helight.ai"
projects: ["T109"]
tags: [person/researcher, status/active]
---
```

#### 论文 (paper)
```yaml
---
title: "Single-Atom Catalysis for Hydrogen Evolution"
type: paper
authors: ["Zhang, Wei", "Li, Hua"]
journal: "JACS"
year: 2026
doi: "10.1021/jacs.xxxxx"
topics: ["催化", "单原子"]
methods: ["DFT"]
related_projects: ["T109"]
tags: [paper/cat/2026, quality/good]
---
```

#### 概念 (concept)
```yaml
---
title: "密度泛函理论"
type: concept
domain: "comp"
definition: "基于电子密度描述多体量子系统的计算方法"
related_concepts: ["comp:分子动力学", "qc:波函数"]
tags: [concept/comp, quality/good]
---
```

#### 事件 (event)
```yaml
---
title: "北航AI实验室揭牌仪式"
type: event
date: 2026-04-18
category: milestone
source: "会议"
related_tasks: ["#1579"]
related_projects: ["T109"]
tags: [event/milestone, status/completed]
---
```

### 2.4 双向链接规范

**必须使用 Obsidian 双向链接语法：**

```markdown
# 人物关联
创始人：[[刘宇宙]]  
就职机构：[[和光智成]]  
参与项目：[[T109]]、[[T110]]

# 论文关联
引用：[[2025-Wang-DeepLearning]]  
被引：[[2026-Zhang-SingleAtomCatalysis]]  
使用概念：[[comp:DFT]]、[[ai:GNN]]

# 项目关联
负责人：[[刘宇宙]]  
成员：[[张三]]、[[李四]]  
使用技术：[[comp:DFT]]  
产出论文：[[2026-Zhang-SingleAtomCatalysis]]
```

**带消歧义的链接：**
```markdown
[[姜杰|姜杰（航天科技集团）]]
[[李明|李明（北航材料学院）]]
```

### 2.6 录入流程（Step-by-Step）

```
步骤1: 确定文件类型 → 人物/公司/项目/论文/概念/事件
  ↓
步骤2: 检查是否已存在 → 搜索同名文件，避免重复
  ↓
步骤3: 选择正确的目录 → 参照2.2命名规范
  ↓
步骤4: 填写 frontmatter → 参照2.3模板
  ↓
步骤5: 撰写内容 → 使用对应模板（wiki/templates/）
  ↓
步骤6: 添加双向链接 → 所有相关实体用 [[wikilink]] 连接
  ↓
步骤7: 打标签 → 至少包含一级标签+状态标签
  ↓
步骤8: 质量自检 → 是否≥20行？是否有≥3个链接？标签是否正确？
```

### 2.7 质量门控（Quality Gate）

**提交前自检清单：**

```
□ 文件名符合规范（2.2）
□ frontmatter 完整无遗漏
□ 内容 ≥ 20行（非stub）
□ 包含 ≥ 3个双向链接
□ 标签覆盖：一级标签 + 状态标签
□ 无孤立实体（至少被一个其他文件链接）
□ 拼写/语法检查通过
□ 模板使用正确（wiki/templates/）
```

## 三、检索技巧（SOP-02）

### 3.1 检索方式总览

| 检索方式 | 适用场景 | 工具 | 响应时间 |
|---------|---------|------|---------|
| Obsidian搜索 | 精确关键词、文件名 | `Cmd/Ctrl+O` | <1s |
| Dataview查询 | 条件过滤、聚合统计 | Dataview插件 | <2s |

### 3.2 Obsidian 搜索技巧

#### 基础搜索
```
Ctrl/Cmd + O        → 快速打开文件（输入文件名）
Ctrl/Cmd + Shift + F → 全文搜索
```

#### 高级搜索语法
```
# 按标签搜索
tag:#paper/cat/2026              → 所有2026年催化论文

# 按路径搜索
path:wiki/concepts/ai/           → AI领域所有概念

# 组合条件
"密度泛函" path:wiki/concepts/   → 概念目录中含"密度泛函"的文件

# 排除条件
-"待补充" -"nbsp"                → 排除垃圾内容
```

### 3.3 memory_search 使用技巧

**适用场景：** 询问AI助手时，让系统从记忆中找到相关信息。

**最佳实践：**

```
✅ 好的提问方式：
- "T109项目最近有什么进展？"
- "我和北航的姜杰讨论过什么？"
- "关于单原子催化的论文有哪些？"

❌ 不好的提问方式：
- "搜索一下"（太模糊）
- "找文件"（应使用Obsidian搜索）
```

**AI端检索管道（五阶段）：**
```
你的问题
  ↓
1️⃣ 向量语义召回 → 从SQLite找50个最相关文档
  ↓
2️⃣ 图路径扩展 → 2-hop关联扩展至80个
  ↓
3️⃣ 衰减权重 → 近期信息+20%权重，旧信息衰减
  ↓
4️⃣ LLM重排序 → Cross-encoder精排至Top 5-10
  ↓
5️⃣ 上下文组装 → 结构化Markdown输出
```

### 3.4 常用检索场景速查

| 你想找… | 用什么 | 怎么搜 |
|---------|--------|--------|
| 某个人的信息 | Obsidian搜索 | `path:People/ 姓名` |
| 某个项目的进展 | Dataview查询 | `FROM "wiki/projects"` |
| 某篇论文 | Obsidian搜索 | `path:wiki-papers/ 关键词` |
| 某个概念的定义 | Obsidian搜索 | `path:wiki/concepts/ 概念名` |
| 某天发生了什么 | 查memory日志 | `memory/YYYY-MM-DD.md` |
| 某事件的记录 | Obsidian搜索 | `path:Events/ 日期` |
| 最近修改的文件 | Dataview查询 | `date(today)-file.mtime<=dur(7days)` |
| 某个标签下的全部文件 | Obsidian搜索 | `tag:#概念/领域` |

## 四、自动化规则配置指南（SOP-03）

### 4.1 系统自动化架构

```
触发事件
  ↓
规则引擎（memory/graph/rules.jsonl）
  ↓
条件判断（IF-THEN）
  ↓
执行动作（打标签/创建文件/更新索引）
  ↓
日志记录（memory/graph/rules.log）
```

### 4.2 现有自动化规则

#### 规则1: 论文自动分类（TAG-001）

**触发条件：** 新文件创建到 `wiki-papers/papers/`

**执行动作：**
1. 提取DOI和期刊名
2. 根据期刊名映射学科领域（JACS→cat, Nature→mat, 等）
3. 提取关键词，映射到12大分类
4. 生成标签：`paper/{领域}/{年份}`
5. 主题匹配关联到相关项目

**配置位置：** `memory/graph/capabilities.json` → `auto_tagging`

#### 规则2: 联系人自动归档（TAG-002）

**触发条件：** 新文件创建到 `People/`

**执行动作：**
1. 提取机构信息
2. 关联到 `Companies/` 或 `Institutions/`
3. 提取项目关联
4. 生成标签：`person/{角色}/{机构类型}`
5. 创建双向wikilink

#### 规则3: 事件自动记录（TAG-003）

**触发条件：** 看板任务状态变更

**执行动作：**
1. 生成Event实体到 `Events/` 目录
2. 关联任务ID → `related_tasks`
3. 关联项目 → `related_projects`
4. 追加到 `memory/YYYY-MM-DD.md` 日志

#### 规则4: Raw目录自动处理

**触发条件：** 每天凌晨2:00 或 手动触发

**执行动作：**
1. 扫描 `raw/` 根目录所有文件
2. 子代理（alicodingplan/kimi-k2.5）分析内容
3. 智能分类移动到对应目录
4. 论文类自动生成Wiki笔记
5. 发送处理报告

**配置文件：** `Files/mettlyzObsidianVault/RAW-WORKFLOW.md`

### 4.3 如何添加新自动化规则

**步骤1：** 编辑 `memory/graph/rules.jsonl`

每行一条规则，JSON格式：
```json
{
  "rule_id": "RULE-004",
  "name": "会议记录自动关联",
  "trigger": "new_file:wiki/meetings/*.md",
  "conditions": {
    "has_attendees": true,
    "has_projects": true
  },
  "actions": [
    {"type": "extract", "field": "attendees", "link_to": "People/"},
    {"type": "extract", "field": "projects", "link_to": "wiki/projects/"},
    {"type": "tag", "pattern": "meeting/{date}"},
    {"type": "append", "target": "memory/YYYY-MM-DD.md"}
  ],
  "confidence_threshold": 0.8,
  "enabled": true
}
```

**步骤2：** 注册到能力系统

编辑 `memory/graph/capabilities.json`，在 `skill_registry` 下添加：
```json
"meeting_auto_link": {
  "description": "会议记录自动关联人员和项目",
  "version": "1.0",
  "rule_ref": "RULE-004"
}
```

**步骤3：** 测试规则

```bash
# 模拟触发（创建测试文件）
touch wiki/meetings/test-meeting.md

# 检查规则是否执行
cat memory/graph/rules.log | tail -20
```

**步骤4：** 启用规则

确认测试通过后，设置 `"enabled": true`

### 4.4 规则管理最佳实践

| 原则 | 说明 |
|------|------|
| **测试先行** | 新规则必须先在测试文件上验证 |
| **低置信度优先** | 新规则设 `confidence_threshold=0.9`，稳定后降低 |
| **日志必记** | 每条规则执行必须写入日志 |
| **可回滚** | 保留规则历史版本 |
| **定期审查** | 每月审查一次规则有效性 |

## 六、FAQ 常见问题

### Q1: 我不知道一个文件应该放到哪个目录，怎么办？

**A:** 放到 `raw/` 根目录即可。系统会在凌晨2:00自动分类处理。你也可以手动触发：

```
对我说："使用alicodingplan/kimi-k2.5处理raw目录"
```

### Q2: 我写了一篇论文笔记，但不知道如何打标签？

**A:** 最简单的方式：
1. 判断期刊/会议所属领域（参照2.5标签体系表格）
2. 使用标签格式：`paper/{领域}/{年份}`
3. 示例：JACS论文 → `paper/cat/2026`

如果不确定领域分类，放到 `raw/` 让系统自动判断。

### Q3: 双向链接有什么用？必须写吗？

**A:** **必须写。** 双向链接是知识图谱的核心：
- 让AI助手能通过关联找到相关信息
- 在Obsidian中形成可视化知识图谱
- 支持跨文档关联查询

**最少要求：** 每个文件至少3个双向链接。

### Q4: 搜索返回了很多不相关的结果，怎么办？

**A:** 三种优化方式：

1. **精确路径搜索：** 指定目录
   ```
   path:wiki/concepts/ai/ "神经网络"
   ```

2. **加标签过滤：**
   ```
   tag:#paper/cat/ "催化"
   ```

3. **用自然语言问AI：** AI会走五阶段智能检索，自动过滤噪声

### Q5: 如何查看某个项目的所有关联信息？

**A:** 最佳方式 — 使用Dataview查询：

````markdown
```dataview
TABLE type, file.link
FROM ""
WHERE contains(file.outlinks, [[T109]])
```
````

或者直接问AI助手："T109项目的所有关联信息"

### Q6: 我创建的页面被标记为"stub"（存根），怎么解决？

**A:** "stub"表示内容不足（<20行）。解决方法：
1. 补充定义/描述内容
2. 添加更多双向链接
3. 加入具体示例或案例
4. 完成后将标签改为 `quality/good`

### Q7: 系统会自动删除我的文件吗？

**A:** **不会。** 系统只会：
- 移动文件（如从raw/到对应目录）
- 添加标签和链接
- 更新索引

删除操作必须由人工确认。已删除文件使用 `trash` 命令（可恢复），不是 `rm`。

### Q8: 知识大脑和我的Obsidian是什么关系？

**A:** 知识大脑 = Obsidian Vault + OpenClaw Agent + 自动化规则
- **Obsidian** 是底层存储和可视化界面
- **OpenClaw Agent** 是智能助手（搜索、整理、关联）
- **自动化规则** 是后台自动处理引擎

你可以直接用Obsidian打开Vault进行编辑，所有改动Agent都能感知。

### Q9: 多人协作时如何避免冲突？

**A:** 
1. **不同目录分工：** 每人负责不同领域/项目
2. **Git版本控制：** 所有文件通过Git管理
3. **每日合并：** 系统自动检测并标记冲突
4. **沟通优先：** 修改他人负责的文件前先沟通

### Q10: 系统的准确率如何？会不会乱打标签？

**A:** 当前系统状态：
- 自动标签有**置信度阈值**（默认0.7-0.9）
- 低于阈值的标记为 `quality/stub`，需人工审核
- 概念有效率仅14%（⚠️待优化目标≥50%）
- 系统会持续学习，准确率逐步提升

**建议：** 初期重要文件建议人工复核标签。

### Q11: 如何批量导入已有文档？

**A:** 两种方式：

1. **放入raw/自动处理（推荐）：**
   ```
   将所有文件放入 raw/ 根目录
   等待凌晨2:00自动处理或手动触发
   ```

2. **使用ACS论文下载技能：**
   ```
   对我说："下载论文 [DOI或标题]"
   系统自动下载+提取+标签+关联
   ```

### Q12: 系统出问题了怎么排查？

**A:** 故障排查流程：

```
1. 查看健康报告 → memory/graph/kg_health_report.md

3. 查看Agent状态 → subagents list
4. 重启Gateway → openclaw gateway restart

```
