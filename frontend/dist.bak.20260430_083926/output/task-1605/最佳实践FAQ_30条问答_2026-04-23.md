> **适用对象：** 所有使用OpenClaw知识大脑系统的团队成员
> **维护者：** Dudu 🐕

## 📚 基础知识

### Q1: OpenClaw知识大脑是什么？
**A:** 它是一个基于LLM + Graph RAG的多层级知识管理系统，用于将碎片化研究素材（论文、微信文章、会议记录等）转化为结构化知识图谱。核心目标是解决AI加速材料发现中"模型可解释性和知识沉淀"的瓶颈问题。

### Q2: 三大知识库有什么区别？我该用哪个？
**A:** 
- **wiki** → 以实体为中心的知识图谱（人物、机构、概念、项目）
- **llmwiki** → 原始素材暂存区 + 结构化加工区
- **wiki-papers** → 论文专题库（新论文优先存这里）

简单决策：论文存 wiki-papers，人物/机构存 wiki，原始素材存 llmwiki。

### Q3: 我的工作目录和iCloud目录是什么关系？
**A:** 三大知识库在 iCloud Drive 路径下（`~/Library/Mobile Documents/com~apple~CloudDocs/Documents/`），workspace 下的 `Files/` 子目录是**副本**。**只往 iCloud 原路径写入内容**，不要往副本写。

## 📝 知识录入

### Q4: 新论文该怎么录入？
**A:** 
1. 存入 `wiki-papers/papers/` 目录
2. 文件命名：`作者_年份_关键词.md`（如 `Zhang_2026_ML-Catalyst.md`）
3. 必须包含 YAML frontmatter（title, authors, year, doi, tags）
4. 必须建立至少 1 个 `[[wikilink]]` 关联到已有实体或概念
5. 个人笔记不少于 3 句话

### Q5: 什么是 YAML frontmatter？为什么重要？
**A:** 它是 Markdown 文件开头的元数据块，用 `---` 包裹。它让系统能自动识别论文的作者、年份、DOI 等信息，是自动化处理的基础。格式如下：
```yaml
---
title: "论文标题"
authors: ["作者1", "作者2"]
year: 2026
doi: "10.xxxx/xxxxx"
tags: [标签1, 标签2]
---
```

### Q6: 录入内容前需要查重吗？
**A:** 必须查重。先用 `obsidian-cli search-content` 或语义搜索检查是否已存在相同内容，避免重复。重复条目会污染知识图谱、降低检索质量。

### Q7: 我录入的内容质量不够高怎么办？
**A:** 系统有质量门控（WIKI-QUALITY-GATE.md）。如果内容不合格（如缺少必填字段、无wikilink关联），后续 Agent 处理会受阻。建议录入时参考用户手册第3节的模板，确保一次通过。

### Q8: 如何给内容打标签（tags）？
**A:** tags 应使用一致的术语，建议参考已有笔记中的标签。常用标签类别：
- 领域：`材料科学`, `化学`, `AI`, `催化`, `电池`
- 类型：`论文`, `综述`, `会议`, `项目`, `商业`
- 状态：`已读`, `待读`, `精读`, `重要`

### Q9: 实体（人物/机构）录入有什么特殊要求？
**A:** 
- 人物实体：必须包含 `institution` 和 `role`
- 机构实体：必须包含 `category`（大学/公司/期刊/会议）
- 两者都必须建立关联（人物关联机构，机构关联人物/项目）
- 文件名为中文全称（如 `北京航空航天大学.md`）

## 🔍 检索使用

### Q10: 怎么快速找到我需要的内容？
**A:** 按场景选择检索方式：
- 模糊记忆 → 用语义搜索（`memory_search`）
- 找具体论文 → 用语义搜索 + doi
- 了解概念全貌 → 用 Graph RAG 3阶段检索
- 快速查找已知笔记 → 用 Obsidian CLI

### Q11: 什么是 Graph RAG？和普通搜索有什么区别？
**A:** Graph RAG 是"图增强检索"。普通搜索只返回关键词匹配的结果，Graph RAG 会：
1. 先用向量相似度找候选（和搜索类似）
2. 然后沿着知识图谱的关系边扩展（找到间接关联）
3. 最后用 LLM 重新排序

例如搜索"催化剂"，Graph RAG 能同时找到"某某教授"（因为该教授研究催化），而普通搜索可能找不到。

### Q12: 为什么有时候搜不到我知道存在的内容？
**A:** 可能原因：
1. 文件放在了错误的目录 → 检查内容存放决策树
2. 索引未更新 → 运行索引更新
3. 关键词不匹配 → 尝试同义词（如"ML"="机器学习"）
4. wikilink未建立 → 内容孤立，Graph RAG无法发现

### Q13: 如何做跨领域的知识发现？
**A:** 使用 Graph RAG 的图路径扩展能力。例如查询 "AI 材料 催化 最新进展"，系统会找到同时涉及这三个领域的节点及其关联路径，帮助你发现跨学科的连接点。

## 🤖 自动化与Agent

### Q14: 系统能自动处理论文吗？
**A:** 可以。配置自动化规则后，系统能：
1. 检测到新PDF → 自动提取元数据
2. 创建笔记模板 → 填充摘要、关键词
3. 抽取实体 → 关联到已有知识图谱
4. 质量检查 → 确保符合标准

但这需要预先配置规则（见用户手册第5节）。

### Q15: 微信里收到的内容能自动入知识库吗？
**A:** 可以。通过 Diary Topic SOP（7步处理流程），发到 Diary topic 的任何内容会自动：
1. 识别内容类型
2. 关联看板任务
3. 归属到项目（强制）
4. 入Vault创建笔记
5. 同步到日历（如有约见）
6. 更新看板状态
7. 处理提醒

### Q16: Agent 是什么？它们怎么工作？
**A:** Agent 是 specialized 的 AI 子代理，各有专长：
- `research` → 搜索、论文检索
- `analysis` → 数据分析、报告
- `execution` → 代码执行、文件操作
- `wiki` → 知识录入、笔记生成

调度器根据任务关键词自动路由到合适的 Agent。例如"帮我搜索AI催化剂最新论文"会路由到 research Agent。

### Q17: Agent 会自动发邮件或对外操作吗？
**A:** **不会。** 涉及对外通信（发邮件、发推等）的规则必须设置为 `review_needed` 模式，需要用户审核后才能执行。这是系统的安全红线。

## 🔧 系统维护

### Q18: 系统说"失忆"了是什么意思？
**A:** 这是指 `MEMORY.md` 文件超过了 OpenClaw 的 20KB 截断阈值，导致历史记忆丢失。**防范措施：** MEMORY.md 永远保持 < 5KB，详细内容都下沉到 `memory/` 子目录。如果文件过大，立即拆分。

### Q19: 多久需要维护一次知识库？
**A:** 
- 每日：AI助手自动写日志
- 每周：AI助手自动整理周报
- 每月：人工+AI检查概念图谱质量、合并重复实体
- 每季度：全面评估知识图谱有效性

### Q20: iCloud 同步很慢或冲突了怎么办？
**A:** 
1. 确保只有一个设备在编辑知识库
2. 批量操作后等待同步完成（检查 iCloud 状态图标）
3. 如果出现冲突文件，手动合并后删除冲突副本
4. 大量文件时可以考虑关闭部分目录的 iCloud 同步

### Q21: 知识库文件太多（14,000+），会影响性能吗？
**A:** 会有一定影响。优化建议：
1. 定期清理不再需要的临时文件
2. 将旧内容归档到 `archive/` 子目录
3. 使用语义搜索而非全文搜索
4. 控制活跃文件数量在合理范围

### Q22: 如何备份知识库？
**A:** 
1. **iCloud 自带备份：** 文件在 iCloud Drive 下，Apple 有云端备份
2. **本地 Git 版本控制：** workspace 下的文件已纳入 Git
3. **手动备份：** `cp -a ~/.openclaw/workspace ~/.openclaw/workspace.bak.$(date +%Y%m%d_%H%M%S)`
4. **iCloud 导出：** 定期导出三大知识库到外部硬盘

## 🎯 进阶使用

### Q23: 如何让知识大脑帮助我的科研？
**A:** 
1. **文献追踪：** 定期输入感兴趣的领域，让 research Agent 自动检索新论文
2. **知识关联：** 阅读新论文后，强制建立 wikilink 到已有知识
3. **趋势发现：** 用 Graph RAG 查询跨领域关联，发现研究空白
4. **写作辅助：** 让 analysis Agent 基于知识图谱生成综述草稿

### Q24: 团队多人使用时怎么避免冲突？
**A:** 
1. 每个人用不同的标签前缀区分（如 `@张三:`）
2. 使用 Git 分支管理，定期合并
3. 建立内容审核流程：新内容先入 `raw/`，审核后再入正式目录
4. 定期同步（如每周五）合并各自的笔记

### Q25: 概念图谱的"有效率"是什么意思？如何提升？
**A:** 有效率 = 高质量条目数 / 总条目数。目前 wiki 概念有效率 14%（目标 >20%），实体有效率 28%（目标 >40%）。提升方法：
1. 补充概念的定义和关联
2. 合并重复条目
3. 删除低质量/过期条目
4. 录入新内容时严格执行质量门控

### Q26: 我能自定义自动化规则吗？
**A:** 可以。步骤：
1. 在 `memory/core-principles.md` 中记录规则定义
2. 创建 cron 任务或 heartbeat 检查项
3. 在 sandbox 环境测试
4. 验证后部署
5. 更新 `HEARTBEAT.md`

⚠️ 自动化规则不得自动执行外部操作。

### Q27: 系统的数据安全如何保证？
**A:** 
1. 敏感信息（密码、API Key）存储在 `~/.openclaw/.env`，不写入文档
2. 所有脚本从环境变量读取密码，不硬编码
3. 知识库在 iCloud Drive，受 Apple 加密保护
4. 外部操作（邮件、推文）需要人工审核
5. 核心文件修改前先备份，支持回滚

### Q28: 如何将知识大脑和北航AI全自动化实验室的论文发表计划结合？
**A:** 
1. 在 `wiki/projects/` 中为每篇论文创建项目页面
2. 关联所有参考文献到 wiki-papers
3. 用 `memory/projects/` 跟踪进度
4. 让 research Agent 定期检索目标期刊的最新发表
5. 用 analysis Agent 生成投稿前的文献综述

### Q29: 新团队成员如何快速上手？
**A:** 推荐学习路径：
1. **第1天：** 阅读本 FAQ + 用户手册第1-2节（了解系统全貌）
2. **第2天：** 阅读第3节（录入规范），尝试录入1篇论文笔记
3. **第3天：** 阅读第4节（检索技巧），练习3种检索方式
4. **第4天：** 阅读第7节（Obsidian联动），学会基本CLI操作
5. **第5天：** 了解第6节（多Agent协作），体验自动化处理
