## 风险判断

当前最大问题不是已确认的 SDS 故障，而是**自动化执行链路本身不可执行**：

- cron 任务被设计为需要调用本地 shell/Python 完成健康检查与数据库回写；
- 但当前 OpenClaw 的 exec 策略在 cron 场景下不允许等待交互审批；
- 同时 allowlist 也未放行所需的本地诊断命令；
- 结果是任务会长期卡在 `in_progress`，即使调度触发正常，实际动作也无法落地。

## 建议修复路径

### 方案A：为可信本地自动化放开 cron 所需 exec 能力
适用于该类“本机巡检+数据库回写”任务。

建议检查：
- `~/.openclaw/exec-approvals.json`
- tools.exec 默认策略
- gateway 侧有效审批策略

目标是让**受控的本地只读巡检命令**和**指定 Python 数据库回写脚本**可以在 cron 中无交互运行。

### 方案B：将健康检查逻辑封装为已放行脚本
例如封装为固定脚本：
- `scripts/cron/sds_healthcheck.py`
- `scripts/cron/update_task_1694.py`

再只放行这些固定路径脚本，而不是大量散装 shell 命令。这样更安全，也更容易纳入 allowlist。

### 方案C：改为人工交互执行一次
如果短期内不调整 cron 权限，可在交互会话中执行：
- 系统日志检查
- 数据库连接实测
- 磁盘/资源检查
- 日志清理
- 报告生成
- 数据库状态回写
