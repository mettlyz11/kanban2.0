## 一、POC方案概述

### 1.1 什么是POC

POC（Proof of Concept，概念验证）是**和光智成Yun蕴算平台的标准客户验证流程**，旨在：
- 让客户在**真实业务场景**中验证Yun蕴算的计算精度和效率
- 用客户的**真实分子/反应数据**而非Demo数据做验证
- 建立**量化对比基线**，为客户决策提供数据支撑
- 降低客户从传统工具迁移的决策风险

### 2.2 阶段一：需求对齐（Week 1，3-5天）

**目标**：明确客户POC目标和验收标准

#### 2.2.1 需求调研清单

| 调研项 | 问题 | 产出 |
|--------|------|------|
| **业务场景** | 您目前用什么工具做计算？主要计算什么体系？ | 场景描述文档 |
| **精度要求** | 能垒精度要求多少？与实验值对比的MAE目标？ | 精度验收标准 |
| **规模需求** | 每月/每周需要运行多少次计算？体系大小？ | 规模需求文档 |
| **对比基线** | 目前用什么工具做对比？数据在哪里？ | 基线数据收集 |
| **决策流程** | POC通过后，谁拍板采购？预算多少？决策周期？ | 决策链路图 |
| **技术接口** | 需要与现有系统对接吗？需要什么格式？ | 接口需求文档 |
| **时间要求** | 希望POC何时完成？有无deadline？ | 时间计划 |

#### 2.2.2 输出物

1. **《POC需求调研报告》** — 记录客户场景、需求、验收标准
2. **《POC目标确认书》** — 双方签字确认的POC目标和验收标准
3. **客户测试数据集** — 客户提供3-5个真实分子/反应体系

#### 2.2.3 参与人员

| 角色 | 和光智成 | 客户方 |
|------|----------|--------|
| 项目负责人 | 销售/BD经理 | 研发主管 |
| 技术对接 | 算法工程师 | 计算化学家 |
| 决策者 | 销售VP/CEO | 部门总监/CTO |

### 2.3 阶段二：方案设计与基线建立（Week 1-2，3-5天）

**目标**：设计POC技术方案，建立对比基线

#### 2.3.1 方案设计内容

| 设计项 | 说明 | 产出 |
|--------|------|------|
| **测试体系确认** | 从客户提供的数据集中选择3-5个代表性体系 | 测试体系清单 |
| **计算方法确定** | 确定DFT泛函、基组、溶剂模型等 | 计算方法说明 |
| **对比方案设计** | 确定与传统工具的对比方案 | 对比方案文档 |
| **资源分配** | 分配计算资源、确定执行人 | 资源计划 |
| **时间计划** | 制定详细执行时间表 | POC执行甘特图 |

#### 2.3.2 基线数据收集

| 基线项 | 数据来源 | 说明 |
|--------|----------|------|
| **传统工具耗时** | 客户提供/我方复现 | 用Gaussian/ORCA等运行相同体系 |
| **传统工具精度** | 客户已有数据 | 实验值 vs 传统计算值的偏差 |
| **人工操作成本** | 客户提供 | 每次计算的人工准备/分析时间 |
| **软件成本** | 公开信息 | 竞品软件授权费用 |

#### 2.3.3 输出物

1. **《POC技术方案》** — 详细测试方案、计算方法、对比设计
2. **《基线对比报告》** — 传统工具的耗时/精度/成本数据
3. **《POC执行计划》** — 详细时间表、责任人、里程碑

### 2.5 阶段四：结果评估与报告（Week 3/4-5，3-5天）

**目标**：汇总POC结果，出具正式评估报告

#### 2.5.1 评估维度

| 维度 | 评估指标 | 验收标准 |
|------|----------|----------|
| **精度** | 能垒MAE vs 实验值 | < 3 kcal/mol |
| **效率** | 计算速度提升倍数 | ≥ 5x |
| **成本** | 单次计算成本降低 | ≥ 70% |
| **易用性** | 操作步骤简化 | ≥ 50% |
| **稳定性** | 计算成功率 | ≥ 95% |
| **可视化** | 结果呈现质量 | 客户评分 ≥ 4/5 |

#### 2.5.2 报告结构

**《Yun蕴算POC验证报告》** 标准结构：

```
1. 执行摘要（1页）
   - POC目标回顾
   - 核心结论（精度/效率/成本）
   - 建议方案

2. 测试方案（2-3页）
   - 测试体系说明
   - 计算方法
   - 对比方案

3. 精度验证（3-5页）
   - 各体系计算结果 vs 实验值
   - MAE/RMSD统计
   - 与传统工具精度对比
   - 精度分析讨论

4. 效率验证（2-3页）
   - 各体系计算耗时对比
   - 资源消耗对比
   - 人工操作对比

5. 成本分析（2-3页）
   - TCO对比（3年总拥有成本）
   - 投资回报期
   - 不同方案的ROI

6. 用户体验（1-2页）
   - 平台易用性评分
   - 客户反馈摘要

7. 建议方案（1-2页）
   - 推荐版本（标准/专业/企业）
   - 定制需求
   - 实施计划

附录：原始数据、计算参数、测试体系详情
```

1. **《Yun蕴算POC验证报告》** — 正式评估报告（PDF）

## 三、POC验收标准

### 3.1 核心验收指标

| 指标 | 标准版POC | 专业版POC | 企业版POC |
|------|-----------|-----------|-----------|
| 能垒MAE | < 3 kcal/mol | < 3 kcal/mol | < 2 kcal/mol |
| 计算速度 | ≥ 3x提升 | ≥ 5x提升 | ≥ 10x提升 |
| 成本降低 | ≥ 50% | ≥ 70% | ≥ 80% |
| 计算成功率 | ≥ 90% | ≥ 95% | ≥ 98% |
| 客户满意度 | ≥ 3.5/5 | ≥ 4/5 | ≥ 4.5/5 |

### 3.2 验收通过/不通过判定

| 条件 | 判定 | 后续动作 |
|------|------|----------|
| 所有核心指标达标 | ✅ 通过 | 进入商务转化 |
| 1-2项指标轻微偏差 | ⚠️ 有条件通过 | 针对性优化后二次验证 |
| >2项指标不达标 | ❌ 不通过 | 分析原因，改进后重新POC |
