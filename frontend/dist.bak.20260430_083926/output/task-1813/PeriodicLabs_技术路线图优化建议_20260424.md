# T109技术路线图优化建议（基于Periodic Labs拆解）

日期：2026-04-24  
任务ID：1813

## 一、路线图总原则

目标不是复制 Periodic Labs，而是借鉴其“模型—模拟—实验—反馈”闭环思想，结合 T109 已有优势，构建一条更适合和光智成的中国版路线。

## 二、12个月优化路线图

### 0-3个月：补齐闭环基础设施
1. 建立统一实验数据 schema 与数据仓；
2. 为 T109 计算结果定义标准输出接口，便于进入实验验证流程；
3. 梳理北航自动化实验室可接入的实验流程；
4. 完成 1-2 个示范型“计算→实验→反馈”案例。

### 3-6个月：把单点算法做成工作流产品
1. 将过渡态预测、反应路径搜索、候选筛选做成模块化界面；
2. 引入 agent/workflow 编排能力，让系统自动生成实验建议；
3. 建立失败样本采集机制；
4. 找 2-3 家种子客户做联合验证。

### 6-12个月：形成半闭环平台
1. 实现实验结果自动回流至模型训练/评估模块；
2. 建立客户项目模板库和行业知识库；
3. 形成可展示的“智能实验闭环 dashboard”；
4. 在一个细分赛道做出显著成功案例（如催化、前驱体筛选、新材料配方）。

## 三、技术栈优化建议

### 1. 模型层
- 从“单次预测”升级为“多步决策系统”；
- 增加文献解析与实验计划生成模块；
- 引入可追踪的 agent 行为日志。

### 2. 模拟层
- 继续强化过渡态、反应机理与反应路径优势；
- 在必要场景中补充更高保真模拟接口；
- 将模拟结果标准化，作为实验决策先验。

### 3. 实验层
- 与北航实验室建立标准 API/协议接口；
- 自动记录实验参数、过程、结果、失败；
- 明确哪些流程可先半自动化，不必一步到位全机器人化。

### 4. 数据层
- 数据资产化优先级应提升到战略级；
- 建立版本控制、元数据、质量标签与可追溯性；
- 特别重视失败实验数据与工艺偏差数据。

## 四、组织建议

### 必增角色
- 数据工程 / 科学数据平台负责人
- 实验自动化接口工程师
- 产品化负责人（把科研能力变成客户可用模块）
- 行业解决方案经理

### 必建机制
- 每月一次“模型-实验闭环复盘”
- 每季度一个闭环样板案例
- 数据、算法、实验三方共用 KPI

## 五、最终目标

一年内，T109 不一定要成为完整 autonomous lab 公司，但必须成为一个真正具备闭环雏形的平台：能提出候选、能解释机理、能对接实验、能吸收反馈、能持续变聪明。只要这五点开始成形，就已经从工具跨入平台阶段。
