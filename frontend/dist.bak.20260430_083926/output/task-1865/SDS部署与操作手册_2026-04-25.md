## 1. 系统概述

### 1.1 系统简介
SDS (Self-Driving System) 自我驱动系统是AI Agent的核心任务调度与执行引擎。v2.0版本实现了模块化升级，包含以下核心能力：

- ✅ **智能调度引擎** - 动态优先级、依赖关系自动解析
- ✅ **Tavily研究模块** - 任务执行前深度研究自动化
- ✅ **反馈闭环机制** - 子任务完成率≥90%自动标记完成
- ✅ **超时检测与重试** - 自动重试+诊断报告生成

### 1.2 系统架构
```
┌─────────────────────────────────────────┐
│         SDS v2.0 核心服务               │
├───────────┬───────────┬─────────────────┤

├───────────┴───────────┴─────────────────┤
│                                           │
│  ┌──────────┐  ┌──────────┐  ┌────────┐  │
│  │ 调度引擎  │→│ 研究模块  │→│ 执行器  │  │  ← 核心层
│  └──────────┘  └──────────┘  └────────┘  │
│       ↓           ↓           ↓         │

│  │ 评估器    │  │ 重试管理  │  │ 诊断   │  │  ← 反馈层

```

## 3. 安装部署

### 3.1 Docker 快速部署（推荐）

#### 步骤1: 克隆代码
```bash
git clone https://github.com/your-org/sds-v2.git
cd sds-v2
```

#### 步骤2: 配置环境变量
```bash
cp .env.example .env
vi .env
```

#### 步骤3: 启动服务
```bash
docker-compose up -d
```

#### 步骤4: 验证部署
```bash
# 检查容器状态
docker-compose ps

# 检查日志
docker-compose logs -f scheduler

# 健康检查
curl http://localhost:8080/health
```

### 3.2 原生部署

#### 步骤1: 安装依赖
```bash
# Ubuntu/Debian
sudo apt update && sudo apt install -y python3 python3-pip python3-venv

# CentOS/RHEL
sudo dnf install -y python3 python3-pip
```

#### 步骤2: 创建虚拟环境
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

#### 步骤3: 数据库初始化
```bash
# 创建数据库
mysql -u root -p
CREATE DATABASE sds CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# 执行schema
mysql -u root -p sds < database/schema.sql

# 执行迁移
alembic upgrade head
```

#### 步骤4: 配置服务
```bash
# 创建systemd服务
sudo cp deploy/sds-scheduler.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable sds-scheduler
sudo systemctl start sds-scheduler
```

### 3.3 Kubernetes 部署

#### 使用Helm Chart
```bash
# 添加仓库
helm repo add sds https://charts.your-org.com/sds
helm repo update

# 安装
helm install sds-v2 sds/sds \
  --namespace sds \
  --create-namespace \
  --set tavily.apiKey=your-api-key \
  --set database.url=mysql://user:pass@host:3306/sds

# 验证
kubectl get pods -n sds
kubectl get svc -n sds
```

## 4. 配置说明

### 4.1 核心配置文件

```yaml
# config/config.yaml

# 调度器配置
scheduler:
  max_concurrent: 50        # 最大并发任务数
  queue_size: 10000         # 队列最大长度
  schedule_interval: 0.1    # 调度循环间隔(秒)
  enable_priority: true     # 启用优先级调度
  enable_dependency: true   # 启用依赖解析

# 优先级配置
priority:
  urgency_weight: 1.0       # 紧急度权重
  dependency_weight: 1.0    # 依赖权重
  history_weight: 1.0       # 历史权重
  retry_penalty: 0.15       # 每次重试惩罚

# 评估器配置
evaluator:
  completion_threshold: 0.9  # 自动完成阈值
  enable_llm_assess: true    # 启用LLM评估
  llm_cache_ttl: 3600        # LLM评估缓存时间

# 重试配置
retry:
  max_retries: 3             # 最大重试次数
  backoff_factor: 2.0        # 退避因子
  initial_delay: 5            # 初始延迟(秒)
  max_delay: 300              # 最大延迟(秒)

# 超时配置
timeout:
  check_interval: 30          # 检查间隔(秒)
  default_timeout: 3600       # 默认超时时间(秒)
  min_timeout: 60             # 最小超时时间

# 研究模块配置
research:
  enabled: true               # 启用Tavily研究
  max_results: 10             # 最大结果数
  search_depth: "advanced"    # 搜索深度
  enable_cache: true          # 启用结果缓存
  cache_ttl: 86400            # 缓存TTL(秒)
```

### 6.3 告警规则

```yaml
# alertmanager.rules.yml
groups:
  - name: sds-alerts
    rules:
      # 任务失败率过高
      - alert: HighFailureRate
        expr: rate(sds_tasks_failed_total[5m]) / rate(sds_tasks_completed_total[5m]) > 0.1
        for: 2m
        labels:
          severity: warning
        annotations:
          summary: "任务失败率超过10%"

      # 队列过长
      - alert: QueueBacklog
        expr: sds_queue_size > 1000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "任务队列积压超过1000"

      # 调度延迟过高
      - alert: HighSchedulingLatency
        expr: histogram_quantile(0.95, rate(sds_scheduling_duration_seconds_bucket[5m])) > 0.5
        for: 3m
        labels:
          severity: warning
        annotations:
          summary: "P95调度延迟超过500ms"

      # 服务不可用
      - alert: ServiceDown
        expr: up{job="sds"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "SDS服务不可用"
```

## 7. 故障排查

### 7.1 常见问题排查

#### 问题1: 任务一直处于PENDING状态
**可能原因**:
- 存在未完成的依赖任务
- 任务优先级过低，队列中高优先级任务太多
- 调度器线程阻塞

**排查步骤**:
```bash
# 查看任务依赖
sds-cli show <task_id> | grep dependencies

# 检查依赖任务状态
sds-cli show <dependency_id>

# 查看调度器日志
docker-compose logs scheduler | grep ERROR

# 调整优先级（临时解决方案）
sds-cli priority <task_id> critical
```

#### 问题2: 任务频繁超时
**可能原因**:
- 超时时间设置过短
- 任务实际执行时间较长
- 系统资源不足

**排查步骤**:
```bash
# 查看任务历史执行时间
sds-cli stats --task-type <type>

# 调整超时时间
sds-cli update <task_id> --timeout 7200

# 检查系统资源
top -p $(pgrep -f sds-scheduler)
```

#### 问题3: Tavily研究失败
**可能原因**:
- API Key无效或过期
- 网络连接问题
- API配额耗尽

**排查步骤**:
```bash
# 测试API连接
curl -X POST "https://api.tavily.com/search" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TAVILY_API_KEY" \
  -d '{"query": "test"}'

# 检查配额使用情况
# 登录Tavily控制台查看

# 临时禁用研究（紧急情况）
sds-cli config set research.enabled false
```

#### 问题4: 评估器一直不通过
**可能原因**:
- 子任务完成率不足90%
- 产出文件缺失
- 日志或摘要字数不够

**排查步骤**:
```bash
# 查看详细评估结果
sds-cli show <task_id> --evaluation

# 检查子任务完成情况
sds-cli show <task_id> --subtasks

# 人工触发重新评估
sds-cli evaluate <task_id> --force
```

### 7.2 日志分析

#### 日志位置
- Docker部署: `docker-compose logs -f scheduler`
- 原生部署: `/var/log/sds/scheduler.log`
- Kubernetes: `kubectl logs -f deployment/sds-scheduler`

#### 日志级别说明
```
[TRACE] - 最详细，用于调试具体代码路径
[DEBUG] - 调试信息，开发环境使用
[INFO]  - 正常运行信息，生产环境默认
[WARN]  - 警告，需要关注但不影响运行
[ERROR] - 错误，影响单个任务
[FATAL] - 致命错误，服务无法继续
```

#### 常用日志过滤
```bash
# 只看错误
grep "ERROR\|FATAL" /var/log/sds/scheduler.log

# 追踪特定任务
grep "task-12345" /var/log/sds/scheduler.log

# 查看最近1小时的错误
awk '$1 >= "2026-04-25 00:00:00" && /ERROR/' /var/log/sds/scheduler.log
```

- ✅ 备份完整数据库
- ✅ 备份配置文件
- ✅ 确认所有关键任务已完成
- ✅ 通知相关用户维护窗口

#### 升级步骤
```bash
# 1. 停止v1.0服务
systemctl stop sds-v1

# 2. 数据库备份
mysqldump -u root -p sds > backup/sds-v1-$(date +%Y%m%d).sql

# 3. 执行schema升级
alembic upgrade head

# 4. 数据迁移
python3 scripts/migrate-v1-to-v2.py
```

### 8.2 回滚步骤

#### 触发回滚条件
- 升级后2小时内任务成功率 < 80%
- 调度延迟 > 1秒持续5分钟以上
- 数据丢失或严重不一致

#### 回滚操作
```bash

# 2. 恢复数据库

# 3. 恢复配置
cp backup/config-v1.yaml /etc/sds/config.yaml

# 4. 启动v1.0服务
systemctl start sds-v1

# 5. 通知用户回滚完成
```

## 9. 最佳实践

### 9.1 任务设计最佳实践

#### 任务粒度控制
- ✅ 单个任务执行时间: 5分钟 ~ 2小时
- ❌ 避免小于1分钟的超短任务（调度开销大于收益）
- ❌ 避免大于4小时的超长任务（失败重试成本太高）

#### 依赖关系设计
- ✅ 尽量扁平化依赖，避免过深的嵌套
- ✅ 关键路径任务设置高优先级
- ❌ 避免循环依赖（系统会检测但会浪费时间）

#### 超时时间设置
```
任务类型           建议超时    说明
───────────────────────────────────────
数据处理类         3600s      1小时
模型训练类         7200s      2小时
API调用类          600s       10分钟
报告生成类         1800s      30分钟
```

### 9.2 性能优化建议

#### 高并发场景
```yaml
scheduler:
  max_concurrent: 200        # 根据CPU核心数调整
  schedule_interval: 0.05    # 更频繁的调度

priority:
  enable_dynamic: true       # 启用动态优先级调整

research:
  enable_cache: true         # 研究结果缓存
  cache_ttl: 86400           # 缓存24小时
```

#### 低成本优化
- 关闭非必要的LLM评估功能可节省90% API成本
- 研究结果缓存可减少重复Tavily调用
- 闲时降低并发数可节省计算资源

| MTTR | Mean Time To Recovery，平均故障恢复时间 |
| TTL | Time To Live，存活时间 |
| 反馈闭环 | 执行→评估→调整→重试的完整循环 |
| 指数退避 | 每次重试延迟加倍的策略，避免请求风暴 |
