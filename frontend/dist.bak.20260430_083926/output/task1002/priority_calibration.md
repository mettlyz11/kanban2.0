# 优先级校准对照表

**文档版本**: v1.0  
**创建时间**: 2026-04-18  
**适用范围**: T1-T7全目标域优先级评估  

---

## 一、问题诊断

### 1.1 原有问题："伪均衡"现象

**症状表现**:
- 所有任务Base_Priority集中在8.9-9.9区间
- 高优先级任务占比78%，失去区分度
- 资源分散，核心目标保障不足
- 决策疲劳，选择困难

**根因分析**:
1. 缺乏明确的优先级分级标准
2. 情感因素干扰（不想承认某些任务不重要）
3. 向上社交压力（老板/同事赋予的高优先级）
4. 缺乏动态调整机制

## 二、新算法设计

### 2.1 动态权重衰减模型

```
Effective_Priority = Base_Priority × Weight_Factor × Time_Decay
```

**参数说明**:

| 参数 | 说明 | 取值范围 | 计算方式 |
|------|------|----------|----------|
| Base_Priority | 原始优先级 | 1-10 | 人工评估 |
| Weight_Factor | 目标权重系数 | 0.5-1.5 | 基于目标Weight动态计算 |
| Time_Decay | 时间衰减因子 | 0.5-2.0 | 距离截止日期的时间函数 |

### 2.2 目标权重系数表

| 目标域 | Weight | Weight_Factor | 说明 |
|--------|--------|---------------|------|
| T1 创业 | 32 | 1.5 | 核心目标，最高权重 |
| T2 生活 | 15 | 1.2 | 重要支撑目标 |
| T3 学术 | 18 | 1.1 | 重要但可调整 |
| T4 财富 | 12 | 1.0 | 标准权重 |
| T5 家庭 | 10 | 1.1 | 重要但可调整 |
| T6 社会 | 6 | 0.8 | 较低权重 |
| T7 自我 | 7 | 0.9 | 较低权重 |

### 2.3 时间衰减函数

```
Time_Decay = 1 + (Days_Until_Deadline / 7) × (-0.1)
              ↓
当 Days_Until_Deadline ≤ 3 时:
Time_Decay = 2.0 (紧急加倍)

当 Days_Until_Deadline ≥ 30 时:
Time_Decay = 0.5 (长期衰减)
```

## 三、硬性规则

### 3.1 核心规则

| 规则编号 | 规则内容 | 适用范围 |
|----------|----------|----------|
| R1 | 非核心任务不赋予>8.0的Base_Priority | T3-T7非关键任务 |
| R2 | 核心目标(T1/T2/T7)资源占比≥60% | 全局资源分配 |
| R3 | 次级目标(T3-T6)资源占比≤30% | 全局资源分配 |
| R4 | 每季度重置一次Weight_Factor | 季度复盘时 |
| R5 | 单周高优任务(≥P1)≤5个 | 周度计划时 |

### 3.2 Base_Priority评估标准

| 评分 | 标准 | 示例 |
|------|------|------|
| 10 | 战略级，影响未来3年 | 创业方向决策 |
| 9 | 关键里程碑，必须完成 | 产品上线 |
| 8 | 重要目标，有替代方案 | 市场推广活动 |
| 7 | 有价值，可延迟 | 内容更新 |
| 6 | 锦上添花，可做可不做 | 界面优化 |
| 5 | 例行事务 | 周报填写 |
| ≤4 | 低价值，考虑删除 | 无效会议 |

## 五、实施检查清单

### 5.1 实施前检查

- [ ] 完成所有Pending任务的优先级重评
- [ ] 确认T1/T2/T7资源占比≥60%
- [ ] 确认T3-T6资源占比≤30%
- [ ] 识别并移除≥20%的低ROI任务
- [ ] 设置季度权重重置提醒

### 5.2 实施中监控

- [ ] 每日检查高优任务数量（≤5个/周）
- [ ] 每周检查核心目标资源投入占比
- [ ] 每月检查任务延期率变化趋势
- [ ] 每季度执行权重系数重置

### 5.3 实施后评估

- [ ] 决策时间是否缩短至≤5分钟
- [ ] 任务完成质量是否提升
- [ ] 系统疲劳感是否降低
- [ ] 核心目标达成率是否提升

| 风险 | 可能性 | 影响 | 应对措施 |
