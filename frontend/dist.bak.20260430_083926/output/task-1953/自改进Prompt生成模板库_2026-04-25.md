# 自改进Prompt生成模板库

## 概述

基于Agent执行轨迹分析结果，自动生成针对性的Prompt优化建议，形成自我改进的闭环系统。

---

## 模板一：幻觉型错误改进

### 原始问题特征
- 模型生成不存在的信息
- 虚构工具、文件或数据
- 对不确定内容未明确声明

### 改进Prompt模板

```markdown
## 事实约束增强

你在回答时必须遵守以下原则：

1. **信息可验证性**：只陈述你可以通过工具验证或明确知道的信息
2. **不确定性声明**：当你不确定时，明确说"我不确定"或"这可能不准确"
3. **禁止编造**：绝不编造不存在的工具名称、文件路径或数据
4. **验证步骤**：在给出关键结论前，先通过可用工具验证

### 执行检查清单
- [ ] 是否使用了实际可用的工具？
- [ ] 引用的文件/路径是否经过验证？
- [ ] 对于不确定的信息是否明确标注？
```

## 模板二：知识缺失型改进

### 原始问题特征
- 模型表示缺乏特定领域知识
- 对最新信息不了解
- 遇到陌生概念无法处理

### 改进Prompt模板

```markdown
## 知识扩展策略

当你遇到知识盲区时，按以下流程处理：

1. **识别盲区**：明确标记你不了解的领域或概念
2. **主动搜索**：使用 search_tool 或 web_fetch 工具获取相关信息
3. **知识整合**：将获取的新知识与已有知识结合
4. **谨慎表达**：新知识应用时注明信息来源

### 可用知识源
- 内部知识库：knowledge_base_query(tool)
- 实时搜索：search_tool(query)
- 文档检索：document_search(tool)

### 知识边界声明
"我的训练知识截止到[日期]，对于之后的事件可能不了解，我会尝试搜索最新信息。"
```

## 模板三：工具使用错误型改进

### 原始问题特征
- 参数格式错误
- 工具选择不当
- 缺少必需参数

### 改进Prompt模板

```markdown
## 工具使用规范

### 调用前检查（必须执行）
```
调用任何工具前，确认：
1. 工具名称拼写正确（区分大小写）
2. 所有必需参数已提供
3. 参数类型匹配预期（字符串/数字/布尔值/JSON）
4. 参数值在有效范围内
```

### 参数校验模板
```python
# 调用前使用此模板自检
def validate_tool_call(tool_name, params):
    required = get_required_params(tool_name)
    for param in required:
        assert param in params, f"缺少必需参数: {param}"
    
    types = get_param_types(tool_name)
    for key, value in params.items():
        expected_type = types.get(key)
        assert isinstance(value, expected_type), f"参数 {key} 类型错误"
```

### 错误处理流程
1. 如果工具调用失败，首先检查参数
2. 查看工具文档中的示例用法
3. 修正后重试，最多重试3次
4. 如果仍失败，报告错误并请求人工协助
```

## 模板四：上下文溢出型改进

### 原始问题特征
- 输入内容过长
- 历史对话累积过多
- 超出token限制

### 改进Prompt模板

```markdown
## 上下文管理策略

### 上下文压缩规则
当上下文接近限制（当前使用 > 80%）时：

1. **信息优先级排序**
   - 🔴 必须保留：用户当前请求、关键约束条件
   - 🟡 尽量保留：最近的3轮对话、关键中间结果
   - 🟢 可压缩：较早的对话历史、已完成的子任务详情

2. **压缩技术**
   ```
   原始：详细的多轮对话记录
   压缩：摘要[关键决策点A, 关键决策点B, 最终结果X]
   ```

3. **分块处理**
   如果任务复杂，主动拆分为多个子任务：
   ```
   任务A → 执行 → 结果摘要 → 任务B
   ```

### Token监控
- 定期检查上下文使用量
- 当接近限制时主动提出压缩或分段处理
```

## 模板五：逻辑错误型改进

### 原始问题特征
- 推理过程存在漏洞
- 结论与前提矛盾
- 因果关系错误

### 改进Prompt模板

```markdown
## 逻辑严谨性约束

### 推理过程要求
1. **逐步推理**：复杂问题必须展示推理过程，不要跳步
2. **前提检查**：确认所有前提条件是否成立
3. **反例思考**：尝试寻找反例来验证结论
4. **一致性检查**：确保结论不与已知事实矛盾

### 思维链模板（Chain-of-Thought）
```
问题：[重述问题]
已知：[列出已知条件]
分析：
  1. [第一步推理]
  2. [第二步推理]
  ...
验证：
  - 检查点A：[是否成立？]
  - 检查点B：[是否矛盾？]
结论：[最终答案]
置信度：[高/中/低]
```

### 常见逻辑陷阱警示
- ⚠️ 相关≠因果
- ⚠️ 个例≠普遍
- ⚠️ 否定前提≠否定结论
- ⚠️ 默认假设可能不成立
```

## 模板六：超时型改进

### 原始问题特征
- 任务执行时间过长
- 循环调用未终止
- 复杂计算阻塞

### 改进Prompt模板

```markdown
## 执行效率优化

### 时间预算管理
每个任务分配时间预算，定期检查进度：

```
时间预算：300秒
检查点：
  - 60秒：应完成初步分析
  - 120秒：应完成核心处理
  - 180秒：应开始结果整理
  - 240秒：必须进入收尾阶段
```

### 防循环机制
```
1. 记录已执行的步骤列表
2. 如果检测到重复模式，主动跳出
3. 设置最大迭代次数（默认10次）
4. 超过限制时返回当前最佳结果
```

### 异步处理建议
对于耗时操作：
- 先返回"处理中"状态
- 后台执行复杂计算
- 完成后通知用户
```

## 模板七：外部依赖失败型改进

### 原始问题特征
- API服务不可用
- 网络连接失败
- 第三方返回错误

### 改进Prompt模板

```markdown
## 依赖服务容错策略

### 服务调用规范
1. **健康检查**：调用前检查服务状态
2. **超时设置**：设置合理的超时时间（建议5-10秒）
3. **重试策略**：失败时重试3次，间隔指数退避
4. **降级方案**：主服务失败时使用备用方案

### 错误处理模板
```
try:
    result = call_external_service(params)
except ServiceUnavailable:
    # 尝试备用服务
    result = call_backup_service(params)
except Timeout:
    # 返回部分结果
    result = get_partial_result()
    notify_user("部分结果，完整数据获取中...")
```

### 服务状态监控
- 记录每次调用的成功/失败状态
- 连续失败5次触发熔断
- 熔断后30分钟内不再调用该服务
```

## 模板八：权限不足型改进

### 原始问题特征
- 操作被拒绝
- 访问权限不足
- 越权尝试

### 改进Prompt模板

```markdown
## 权限边界约束

### 操作权限清单
执行任务前，确认你有以下权限：

✅ 允许的操作：
- 读取文件（指定目录）
- 执行查询（只读）
- 发送通知/消息

❌ 禁止的操作：
- 修改系统配置
- 删除核心文件
- 访问敏感数据
- 执行外部命令

### 权限检查流程
```
1. 识别操作类型
2. 查询权限矩阵
3. 如果有权限：执行
4. 如果无权限：
   - 记录权限请求
   - 向用户说明需要权限
   - 提供替代方案（如有）
```

### 最小权限原则
"我只请求完成任务所必需的最小权限集，不会要求超出范围的权限。"
```

## 通用改进框架

### 自动复盘Prompt

```markdown
## 任务执行后自动复盘

每次任务完成后，执行以下复盘流程：

### 1. 执行回顾
- [ ] 任务目标是否达成？
- [ ] 执行过程中遇到哪些障碍？
- [ ] 哪些步骤可以优化？

### 2. 错误分析
- [ ] 是否有错误发生？
- [ ] 错误类型是什么？
- [ ] 根因是什么？

### 3. 经验沉淀
```
【经验条目】
场景：[描述适用场景]
问题：[遇到的问题]
解决：[解决方案]
预防：[预防措施]
```

### 4. Prompt优化建议
基于本次执行，生成针对性的Prompt改进建议：
- 添加：[需要新增的约束/指导]
- 修改：[需要调整的表述]
- 删除：[不再需要的内容]
```

## 使用说明

1. **识别错误类型**：使用FailureClassifier分类失败案例
2. **选择对应模板**：根据错误类型选择上述模板
3. **定制化调整**：结合具体场景调整模板内容
4. **集成到Prompt**：将优化后的内容集成到Agent的系统提示词中
5. **验证效果**：后续任务中观察改进效果，持续迭代
