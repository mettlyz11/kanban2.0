### TPL-TOOL-003: 工具错误处理模板

```
## 鲁棒工具调用协议

### 错误处理策略

#### 策略 1：预校验
调用工具前必须：
1. 验证所有参数的存在性和格式
2. 如果参数有问题，先修复再调用
3. 不确定时，先用简单案例测试

#### 策略 2：分级重试

```
重试次数 | 延迟 | 动作
──────────────────────────────
第 1 次失败 → 1 秒 → 原样重试（可能是临时问题）
第 2 次失败 → 3 秒 → 调整参数后重试（修正可能的错误）
第 3 次失败 → 放弃 → 换用其他方案（或告知用户）
```

#### 策略 3：降级方案
每个工具调用必须有降级预案：
> 如果 [工具A] 失败，尝试 [工具B]，如果也失败，使用 [降级方案C]

#### 策略 4：错误诊断
工具失败时，按以下顺序诊断：
1. 参数是否有拼写错误？
2. 参数值是否合法？
3. 是否权限/网络问题？
4. 是否服务暂时不可用？
5. 这个工具真的适合这个任务吗？

## 附录：模板使用指南

### 模板选择决策树

```
检测到错误 → 判断错误类型
    ↓
幻觉型错误 → 使用 HALL 系列模板
    ↓
知识缺失型 → 使用 KNOW 系列模板
    ↓
工具使用错误 → 使用 TOOL 系列模板
    ↓
Prompt 问题 → 使用 PROMPT 系列模板
    ↓
上下文超限 → 使用 CTX 系列模板
    ↓
多种问题 → 使用 COMB 组合模板
```

### 模板应用流程

1. 分析失败案例，确定主要问题类型
2. 选择对应类型的基础模板
3. 填充模板变量（任务内容、上下文、约束等）
4. 根据具体场景，增删定制化内容
5. 生成完整的优化 Prompt
6. 使用测试用例验证效果
7. 部署并监控改进效果

### 版本管理

每个模板都有版本号，优化后需：
- 递增版本号
- 记录变更日志
- 关联对应的失败案例
- 记录改进效果数据
