## 执行摘要

**核心目标**: 2026年Q3（9月30日）前签约**3家付费DFT计算平台客户**，合同总金额≥50万元，建立可复制的获客流程。

**产品定位**: DFT计算平台是和光智成Yun蕴算的核心技术能力——AI加速密度泛函理论计算，覆盖过渡态搜索、反应路径分析、催化剂设计、分子性质预测。

**战略判断**: 市场空白窗口期仅12-18个月——国际竞品(Schrödinger/QCware/Rowan)尚未深耕中国市场，国内竞品(晶泰/深势)以药物发现为主、DFT垂直能力不足。2026年是建立"国产DFT平台标杆"认知的第一年。

### 3.1 定价原则

1. **对标定价**: Schrödinger企业版年费$50K-200K → Helight定价为25-40%
2. **价值定价**: 按"节省的研发成本"定价，而非"计算资源成本"
3. **阶梯定价**: 降低门槛获客 → 用量增长自然升级
4. **混合模式**: SaaS订阅 + 按量计费 + 项目制服务

## 四、POC验证流程（标准化获客引擎）

### 4.1 POC核心设计原则

```
┌──────────────────────────────────────────────────────┐
│           POC验证流程设计原则                          │
├──────────────────────────────────────────────────────┤
│ 1. 用客户真实分子/反应 — 不用Demo数据                  │
│ 2. 直接对标客户当前工具结果 — 精度对比一目了然            │
│ 3. 量化价值输出 — "节省XX小时，精度提升XX%"             │
│ 4. 最小化客户工作量 — 我们做90%，客户做10%              │
│ 5. 快速交付 — 从启动到报告 ≤ 10个工作日                 │
└──────────────────────────────────────────────────────┘
```

### 4.2 标准POC流程（10工作日）

```
Day 0:     POC启动
           ├─ 签署POC协议（保密+知识产权归属）
           ├─ 收集客户计算需求（分子结构/反应式/计算方法要求）
           └─ 分配专属技术工程师

Day 1-2:   需求确认 & 环境准备
           ├─ 确认计算方法（泛函/基组/溶剂模型）
           ├─ 准备计算输入文件
           └─ 收集客户当前工具结果（作为对标基准）

Day 3-7:   计算执行
           ├─ 并行执行标准DFT计算 + AI加速计算
           ├─ 监控计算进度，实时反馈客户
           └─ 异常处理：收敛失败自动切换策略

Day 8-9:   结果分析 & 报告生成
           ├─ 精度对比（vs 客户基准/Gold Standard）
           ├─ 速度对比（vs 客户当前工具/超算排队）
           ├─ 成本对比（vs Schrödinger/自建超算）
           └─ 生成POC验证报告（中英文双语）

Day 10:    结果汇报 & 方案报价
           ├─ 线上/线下汇报会（30分钟）
           ├─ 展示POC结果
           ├─ 提交定制化报价方案
           └─ 收集反馈，推进签约
```

### 4.3 POC验收指标（客户看到的价值证明）

| 验收维度 | 指标 | 达标标准 | 测量方法 |
|---------|------|---------|---------|
| **精度** | 能量误差 vs Gold Standard | ≤0.5 kcal/mol | 对比CCSD(T)/高精度实验值 |
| **精度** | 几何结构RMSD | ≤0.05 Å | 对比实验晶体结构 |
| **速度** | 单任务计算时间 vs 客户当前 | ≤50%时间 | 计时对比 |
| **速度** | 任务排队时间 | ≤2小时 | 平台统计 |
| **易用性** | 首次上手时间 | ≤30分钟 | 用户操作计时 |
| **稳定性** | 计算成功率 | ≥95% | 失败任务/总任务 |
| **成本** | 同等计算量成本 vs Schrödinger | ≤40%价格 | 报价对比 |
