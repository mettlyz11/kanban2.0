## 一、系统概述

### 1.1 设计目标

构建一套完整的 Agent 任务执行轨迹记录与分析系统，实现以下核心能力：

1. **全链路轨迹记录**：捕获从任务下发到最终产出的每一个步骤
2. **失败自动分类**：将失败案例按类型自动归类（幻觉/知识缺失/工具错误）
3. **自改进闭环**：基于历史失败模式自动生成优化后的 prompt 模板
4. **可回放与可审计**：支持任意任务的全步骤回放与时间线重建

### 1.2 解决的问题

- **同类错误重复发生**：子代理执行后缺乏复盘，相同错误模式反复出现
- **性能瓶颈不可见**：无法量化哪个环节耗时最长、哪个工具最不稳定
- **知识缺失难积累**：遇到知识盲区后没有沉淀为可检索的知识卡片
- **改进无据可依**：prompt 优化靠直觉而非数据驱动

### 1.3 架构定位

本系统是 OpenClaw 自我驱动架构的 **第5层基础设施**：

```
Layer 1: 任务调度 (self-driving-scheduler)
Layer 2: Agent路由 (agent_router)
Layer 3: 能力注册 (capabilities_registry)
Layer 4: 通信协议 (ACP Message)
Layer 5: 轨迹记录 + 自改进闭环  ← 本系统
```

### 2.4 FailureType 分类体系

```
failure_type (一级分类)
├── hallucination (幻觉型)
│   ├── factual_error (事实错误)
│   ├── fabricated_reference (伪造引用)
│   ├── overconfident_guess (过度自信的猜测)
│   └── logical_inconsistency (逻辑不一致)
├── knowledge_gap (知识缺失型)
│   ├── missing_domain_knowledge (缺少领域知识)
│   ├── outdated_information (信息过时)
│   ├── insufficient_context (上下文不足)
│   └── ambiguous_query (查询歧义)
└── tool_usage_error (工具使用错误型)
    ├── wrong_tool (选错工具)
    ├── wrong_parameters (参数错误)
    ├── timeout (超时)
    ├── rate_limit (频率限制)
    └── permission_denied (权限不足)
```

## 三、模块设计

### 3.1 trajectory_recorder.py — 轨迹记录器

**职责**：在任务执行的每个关键节点自动捕获并持久化轨迹数据。

**核心接口**：

```python
class TrajectoryRecorder:
    def start_trace(task_id, task_description, agent_id) -> str
    def record_step(trace_id, step_type, tool_name, input_data, output_data, status, duration_ms)
    def record_memory_op(trace_id, operation, path, query, result_count)
    def record_subagent(trace_id, action, subagent_label, task_desc, result)
    def record_error(trace_id, step_id, error_type, error_msg, context)
    def complete_trace(trace_id, final_output, deliverables, quality_score)
    def save_trace(trace_id, storage_path)
    def load_trace(trace_id) -> ExecutionTrace
```

**存储策略**：
- 实时轨迹：内存中构建，任务完成后写入 JSON 文件
- 持久化路径：`~/.openclaw/workspace/memory/traces/YYYY-MM-DD/{trace_id}.json`
- 索引文件：`~/.openclaw/workspace/memory/traces/index.jsonl`（每行一个 trace 概要）

### 3.2 failure_classifier.py — 失败分类器

**职责**：分析执行失败案例，自动分类并提取改进点。

**核心接口**：

```python
class FailureClassifier:
    def classify(error_message, step_context, tool_name, task_description) -> FailureRecord
    def classify_batch(failure_records) -> List[FailureRecord]
    def get_failure_statistics(period_days=30) -> Dict
    def get_top_failure_patterns(limit=10) -> List[Dict]
    def export_report(output_path, period_days=30)
```

**分类算法**：
1. **关键词匹配层**（快速初筛，准确率 ~85%）
2. **规则引擎层**（精确分类，准确率 ~92%）
3. **LLM辅助层**（复杂案例交由大模型分析，准确率 ~97%）

### 3.3 improvement_generator.py — 自改进模板生成器

**职责**：基于失败模式自动生成优化后的 prompt 模板。

**核心接口**：

```python
class ImprovementGenerator:
    def generate_template(failure_record) -> ImprovementTemplate
    def generate_batch(failure_records) -> List[ImprovementTemplate]
    def apply_template(prompt, template) -> str
    def get_template_for_failure(failure_type) -> List[ImprovementTemplate]
    def track_effectiveness(template_id, was_successful) 
```

**模板生成策略**：
- 从失败记录中提取 root_cause 和 learning_point
- 映射到对应的 prompt 优化模式
- 生成包含具体约束和注意事项的新模板
- 跟踪每次使用后的效果以持续优化

### 3.4 replay_engine.py — 轨迹回放引擎

**职责**：将记录的轨迹以可视化的方式回放，支持调试与审计。

**核心接口**：

```python
class ReplayEngine:
    def load_trace(trace_id) -> ExecutionTrace
    def replay_timeline(trace_id, speed=1.0) -> TimelineEvent[]
    def generate_summary(trace_id) -> str
    def compare_traces(trace_id_a, trace_id_b) -> ComparisonReport
    def export_markdown(trace_id, output_path)
```

## 四、与现有系统的集成

### 4.1 与 agent_router.py 集成

在 `AgentRouter.assign_task()` 和 `collaboration_workflow()` 中注入轨迹记录：

```python
# 修改前
result = router.assign_task(task)

# 修改后
trace_id = recorder.start_trace(task_id, task, best_agent)
try:
    result = router.assign_task(task)
    recorder.record_step(trace_id, "task_receive", "agent_router", 
                         {"task": task}, {"result": result}, "success", elapsed_ms)
    recorder.complete_trace(trace_id, result, [], quality_score)
except Exception as e:
    recorder.record_error(trace_id, "step_1", type(e).__name__, str(e), {"task": task})
    recorder.complete_trace(trace_id, None, [], 0)
```

### 4.2 与 self-driving-scheduler 集成

在调度器的任务执行前后自动开启/关闭轨迹记录。

### 4.3 与任务看板数据库集成

轨迹记录中的失败分类和改进建议可反向写入 kanban.tasks 表的 `execution_log` 和 `result_summary` 字段，形成闭环。

## 五、数据流与生命周期

```
任务开始
  │
  ▼
[TrajectoryRecorder] start_trace()
  │
  ▼
执行过程 ──── 每步 record_step() ──── 错误时 record_error()
  │                                          │
  │                                          ▼
  │                                   [FailureClassifier] classify()
  │                                          │
  │                                          ▼
  │                                   [ImprovementGenerator] generate_template()
  │                                          │
  │                                          ▼
  │                                   更新模板库 + 效果追踪
  │
  ▼
[ReplayEngine] save_trace()
  │
  ▼
更新看板数据库 + 记忆文件
```

## 六、验收标准

| 验收项 | 标准 | 验证方式 |
|--------|------|----------|
| 轨迹完整性 | 记录 prompt/中间步骤/输出/耗时/错误 5要素 | 审查 trace JSON 结构 |
| 分类准确率 | 一级分类准确率 ≥ 85% | 用 20 个已知案例测试 |
| 模板可用性 | 生成模板能直接应用于新任务 | 人工审查 + 实际使用 |
| 存储可靠性 | trace 文件不丢失、可回放 | 写入后立即可读 |
| 性能影响 | 记录开销 < 执行时间的 5% | 计时对比 |
