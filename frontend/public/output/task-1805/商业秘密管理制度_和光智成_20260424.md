# 和光智成（Helight）商业秘密管理制度

**版本**: V1.0 | **日期**: 2026-04-24 | **密级**: 内部机密

---

## 第一章 总则

### 第一条 目的与依据

为有效保护和光智成（北京）科技有限公司（以下简称"公司"）的商业秘密，维护公司核心竞争力，根据《中华人民共和国反不正当竞争法》《中华人民共和国劳动合同法》《中华人民共和国刑法》等相关法律法规，结合公司AI+材料科学行业特点和实际运营需求，制定本制度。

### 第二条 适用范围

本制度适用于：
1. **全体员工**（含试用期、实习生、劳务派遣人员）
2. **外部合作方**（顾问、咨询师、合作伙伴、兼职人员）
3. **离职人员**（离职后保密义务持续有效）
4. **所有接触公司商业秘密的相关方**

### 第三条 商业秘密定义

本制度所称商业秘密，是指不为公众所知悉、具有商业价值并经公司采取相应保密措施的技术信息、经营信息等商业信息。具体包括：

**技术信息类**：
```
┌─ AI算法与模型
│   ├── 模型架构设计、超参数配置、训练方法
│   ├── 模型权重文件、推理代码
│   ├── 多模型集成策略与工作流程
│   └── 模型性能评估方法与基准数据
├─ 软件与系统
│   ├── 源代码、目标代码、中间件代码
│   ├── 数据库结构、API接口规范
│   ├── 系统架构设计文档、开发路线图
│   └── 测试用例、调试工具、自动化脚本
├─ 数据资产
│   ├── 私有分子数据库（结构、性质、合成路径）
│   ├── 实验验证数据集（含失败实验数据）
│   ├── 标注训练集与数据增强策略
│   └── 数据清洗与处理管线
├─ 实验技术
│   ├── 实验SOP与标准操作流程
│   ├── 质量控制方法与参数标准
│   ├── 设备配置参数与校准方案
│   └── 自动化实验方案与调度算法
└─ 其他技术秘密
    ├── 技术路线图与研发规划
    ├── 技术评估报告与可行性分析
    └── 内部技术白皮书与设计文档
```

**经营信息类**：
```
┌─ 商业策略
│   ├── 市场拓展策略与客户开发计划
│   ├── 定价策略与商业模式设计
│   ├── 融资方案与投资人尽调材料
│   └── 竞争对手分析与应对策略
├─ 客户信息
│   ├── 客户名单、联系人信息、交易记录
│   ├── 客户需求分析报告与定制方案
│   └── 合同条款与商务谈判记录
├─ 财务信息
│   ├── 财务报表、预算数据、成本结构
│   ├── 投资条款、估值模型、股权结构
│   └── 审计报告与税务筹划方案
└─ 内部管理
    ├── 组织架构调整方案与人员配置
    ├── 绩效考核标准与薪酬体系
    └── 战略规划与董事会决议
```

## 第二章 商业秘密分级与标识

### 第四条 密级划分

| 密级等级 | 标识颜色 | 定义 | 知悉范围 | 典型案例 |
|:--------:|:-------:|------|---------|---------|
| **绝密 (Top Secret)** | 🔴 红色 | 核心商业秘密，泄露将导致公司核心竞争力丧失 | 创始人+核心技术负责人+指定项目组成员（≤5人） | 核心模型权重、全量分子数据库 |
| **机密 (Secret)** | 🟡 黄色 | 重要商业秘密，泄露将造成重大经济损失或声誉损害 | 相关项目组全体成员+部门负责人（≤15人） | 源代码库、实验SOP详细版 |
| **内部 (Internal)** | 🟢 绿色 | 一般商业秘密，泄露可能造成一定影响 | 全体员工（基于工作需要） | 客户名单、市场报告、组织架构 |
| **公开 (Public)** | ⚪ 白色 | 可对外公开的信息 | 所有人 | 公司简介、招聘信息、已公开专利 |

### 第五条 密级标识管理

所有商业秘密载体（纸质、电子、实物）必须在显著位置标注密级标识：

**电子文件标注规范**：
- 文件头部/页眉标注：【和光智成 绝密/机密/内部】
- 文件名格式：`{文件名}_{密级}_V{版本号}_{日期}.{扩展名}`
- 文件水印：机密及以上文件在阅读/打印时自动添加水印
  - 绝密：红字"【绝密】未经授权严禁传播"
  - 机密：黄字"【机密】仅限授权人员查阅"

**纸质文件标注规范**：
- 封面/首页右上角加盖密级印章
- 奇数页右侧页眉标注密级
- 使用不同颜色文件夹分类存放

## 第三章 源代码与算法模型保密管理

### 第六条 代码安全管理

#### 6.1 代码存储与访问控制

| 控制项 | 要求 |
|--------|------|
| 代码仓库 | 使用私有仓库（GitHub Enterprise/自建GitLab），禁止使用公共仓库 |
| 访问权限 | 基于角色最小权限原则，非开发人员不得访问代码库 |
| 分支保护 | `main`/`release` 分支强制PR审核，需要至少1人审核通过 |
| SSH密钥 | 使用公司统一管理的SSH密钥，禁止使用个人GitHub账号访问 |
| Git提交 | 提交信息中不得包含密码、Token、API Key等敏感信息 |
| 审计日志 | 所有代码仓库操作（clone/push/merge）保留6个月以上日志 |

#### 6.2 代码开发规范

```
🛡️ 禁止行为：
❌ 在公司个人设备上存储源代码副本
❌ 使用未经批准的AI编码助手（可能泄露代码至第三方）
❌ 通过即时通讯工具（微信/QQ/钉钉）发送代码片段
❌ 将代码上传至GitHub/GitLab公共仓库或个人库
❌ 在公共WiFi环境中进行远程代码操作

✅ 允许行为：
✓ 在授权的公司设备上使用Git进行版本控制
✓ 在Code Review时通过公司内部工具分享代码
✓ 使用公司批准的开发环境（Docker/Dev Container）
✓ 在内部技术分享中基于Need-to-Know原则展示代码
```

#### 6.3 模型安全管理

| 管控要点 | 具体要求 |
|---------|---------|
| 模型文件存储 | 加密存储于公司内部服务器，不保存到Git仓库中 |
| 模型访问审批 | 下载模型权重需要CTO书面审批，记录下载人+时间+用途 |
| 模型推理API | 通过内网API暴露服务，不提供模型文件下载接口 |
| 模型训练日志 | 训练过程中的Checkpoint临时保存在训练节点，训练完成后转移至加密存储 |
| 模型版本记录 | 每一轮训练的超参数、数据版本、代码版本必须完整记录 |

### 第七条 数据安全管理

#### 7.1 实验数据管理

| 环节 | 管理要求 |
|------|---------|
| 数据采集 | 自动化采集设备实时写入受控数据库，避免人工干预 |
| 数据存储 | 全量数据存储于公司加密服务器（AES-256），定期备份（异地） |
| 数据传输 | 内部传输使用HTTPS/SSH加密，禁止明文传输 |
| 数据标注 | 标注平台限制访问IP和账号，标注完成后数据自动归档 |
| 数据销毁 | 过期数据需经IP委员会审批后，使用安全擦除工具删除（不可恢复） |

#### 7.2 合作方数据隔离

```
                    ┌──────────────────┐
                    │  和光智成核心数据  │
                    │  （绝密/机密）     │
                    └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
                    │  数据脱敏/抽象层   │
                    │  - 去除客户标识    │
                    │  - 统计聚合        │
                    │  - 结果而非原始数据 │
                    └────────┬─────────┘
                             │
                    ┌────────▼─────────┐
                    │  合作方可访问数据   │
                    │  （定制化分析结果） │
                    └──────────────────┘
```

## 第四章 人员保密管理

### 第八条 入职保密管理

#### 8.1 入职签署文件清单

所有新员工在入职前必须签署以下文件（缺一不可）：
1. **《保密协议》** — 约定在职期间及离职后的保密义务
2. **《知识产权归属协议》** — 在职期间所有与公司业务相关的创作/发明归公司所有
3. **《竞业限制协议》** — 约定离职后竞业限制条款（高管/核心技术岗位）
4. **《商业秘密告知书》** — 明确告知公司商业秘密范围和保密要求
5. **《合规承诺书》** — 承诺不使用前雇主的商业秘密

#### 8.2 入职背景审查

| 审查项 | 内容 | 执行部门 |
|--------|------|---------|
| 技术背景 | 确认核心技术人员不携带前公司商业机密 | CTO/技术负责人 |
| 竞业限制 | 查询是否签署过竞业限制协议 | HR |
| 诚信记录 | 是否有商业秘密相关的法律纠纷记录 | HR/法务 |
| 知识产权 | 入职前的专利/论文/软件著作权归属 | CTO |

### 第九条 在职保密管理

#### 9.1 员工日常保密行为规范

**计算机与网络安全**：
```
✅ 必做项：
☐ 启用屏幕保护（5分钟自动锁定）+ 密码/生物识别解锁
☐ 公司设备安装统一终端安全管理软件
☐ 使用企业级密码管理器存储工作密码
☐ 定期修改系统密码（90天周期）
☐ 离开工位时按 Win+L / Cmd+Ctrl+Q 锁定屏幕

❌ 禁止项：
☐ 在公司设备上安装未经批准的软件
☐ 将公司笔记本电脑带出办公区域从事非工作活动
☐ 使用个人云盘（百度网盘/iCloud/OneDrive等）备份工作文件
☐ 将工作文件通过微信/钉钉等发送至个人设备
☐ 将工作群聊截图发送给非相关人员
```

**信息交流规范**：
| 交流方式 | 允许内容 | 禁止内容 |
|---------|---------|---------|
| 内部IM（飞书/钉钉企业版） | 日常协作沟通 | 发送完整代码、模型文件、大量原始数据 |
| 邮件（公司邮箱） | 正常工作沟通（机密以上需加密） | 外泄公司核心技术文档 |

| 技术社区（知乎/CSDN/技术博客） | 已公开技术和行业通用知识 | 公司未公开的技术方案 |

#### 9.2 员工培训体系

|---------|:----:|------|------|
| 入职保密培训 | 入职第一周 | 全体新员工 | 保密制度、分级标准、违规后果 |

| 离职保密提醒 | 离职面谈 | 离职员工 | 离职后保密义务重申、竞业限制提醒 |

### 第十条 离职保密管理

#### 10.1 离职保密流程

```
员工提交离职申请
      ↓

      ↓
脱密期（如需）：最长6个月，调离核心岗位
      ↓
离职面谈 ← 保密义务告知
      ↓
资产归还 ← 设备/文件/门禁卡/系统账号
      ↓
数据清除确认 ← IT部门出具《数据清除确认函》
      ↓
签署《离职保密承诺书》
      ↓
办理正式离职手续
```

## 第五章 保密基础设施与物理安全

### 第十一条 办公环境安全

| 区域 | 访问控制 | 管理要求 |
|------|---------|---------|
| 核心研发区 | 指纹/人脸门禁+工位磁卡 | 非本区人员需登记，禁止拍照 |
| 服务器机房 | 双因子认证（指纹+门禁卡） | 进出日志完整记录，授权人员清单 |
| 普通办公区 | 门禁卡 | 来访人员需在前台登记+全程陪同 |
| 公共区域 | 无限制 | 不得在公共区域讨论或展示机密信息 |
| 会议室 | 门禁卡+ID卡 | 会议结束后清理白板和会议材料 |

### 第十二条 信息系统安全

| 系统类型 | 安全措施 |
|---------|---------|
| 办公网络 | VPN接入（公司局域网/云上网络）、网络隔离（员工/访客/设备） |
| 服务器系统 | 防火墙+IDS/IPS+定期漏洞扫描、操作系统安全更新 |
| 数据库系统 | 加密存储（AES-256）、访问审计、敏感数据脱敏 |
| 邮件系统 | SPF/DKIM/DMARC防伪造、邮件加密、DLP（数据防泄漏） |
| 云服务 | IAM角色管理、CloudTrail审计、安全组最小开放原则 |

## 第六章 违规处理与法律责任

### 第十三条 违规行为分类

| 违规等级 | 示例行为 | 处罚措施 |
|:--------:|---------|---------|
| 🟢 轻微违规 | 未锁定屏幕、在公共区域讨论一般工作内容 | 书面警告+保密培训复训 |
| 🟡 一般违规 | 将内部文件发送到个人邮箱、在非授权设备上访问公司系统 | 通报批评+取消当月保密奖金+复训 |
| 🟠 严重违规 | 向外部人员泄露机密级信息、擅自复制模型/数据文件 | 解除劳动合同+追索经济损失 |
| 🔴 特别严重 | 向竞争对手泄露绝密信息、窃取核心算法/数据集 | 立即解除劳动合同+追究法律责任 |

### 第十四条 法律后果

根据《中华人民共和国反不正当竞争法》及相关法律：

| 违规行为 | 民事责任 | 行政/刑事责任 |
|---------|---------|-------------|
| 违反保密协议泄露商业秘密 | 赔偿实际损失+违法获利+合理维权费用 | 最高500万元行政处罚 |
| 以不正当手段获取商业秘密 | 赔偿损失+惩罚性赔偿（1-5倍） | 《刑法》第219条：最高10年有期徒刑 |
| 第三人明知仍使用非法获取的商业秘密 | 连带赔偿责任 | 同上 |

## 第七章 监督与持续改进

### 第十五条 保密审计机制

| 审计类型 | 频次 | 执行方 | 产出 |
|---------|:----:|:-----:|------|
| 权限审计 | 每月 | IT部门 | 权限清单与异常账号报告 |
| 日志审计 | 每月 | 安全负责人 | 异常访问/下载/传输行为报告 |
| 物理安全审计 | 每季度 | 行政 | 办公环境检查报告 |
| 全面保密审计 | 每半年 | 外部审计机构 | 保密体系评估报告 |
| 制度修订 | 每年 | 法务+IP委员会 | 保密制度更新版本 |

### 第十六条 举报与奖励机制

- **保密举报渠道**：confidential@helight.com（加密邮件）或直接向CEO/CTO报告
- **举报保护**：严格保护举报人身份，严禁打击报复
- **奖励措施**：举报查实的保密漏洞，给予1000-10000元奖励
