## 1. 系统架构概览

### 1.1 多代理组件关系

```
┌─────────────────────────────────────────────┐
│              Gateway Daemon                  │
│         (openclaw gateway start)             │
└──────────────┬──────────────────────────────┘
               │
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌───────┐ ┌───────┐ ┌───────┐
│ Main  │ │ Cron  │ │  ACP  │
│Agent  │ │Agent  │ │Agent  │
└───┬───┘ └───┬───┘ └───┬───┘
    │         │         │
    └────┬────┘    ┌────┘
         ▼         ▼
    ┌─────────────────────┐
    │   Subagent Runtime   │
    │  (sessions_spawn)    │
    │  mode: run/session   │
    │  runtime: subagent/acp│
    └─────────────────────┘
         │         │
         ▼         ▼
    ┌─────────────────────┐
    │  sessions_yield     │
    │  sessions_send      │
    │  sessions_list      │
    │  subagents (list/   │
    │   steer/kill)       │
    └─────────────────────┘
```

### 1.2 关键文件

| 文件 | 用途 |
|------|------|
| `~/.openclaw/subagents/runs.json` | 所有子代理运行记录 |
| `~/.openclaw/openclaw.json` | 主配置（模型/回调/fallback链） |
| `~/.openclaw/.env` | 环境变量（API Keys/DB配置） |
| `~/.openclaw/gateway.log` | Gateway运行日志 |

### 1.3 核心生命周期

```
spawn → started → running → [ok/timeout/error/killed]
  │        │        │              │
  │        │        │              └─ outcome.status
  │        │        └─ accumulatedRuntimeMs
  │        └─ startedAt - createdAt = 排队延迟
  └─ createdAt
```

## 2. 故障场景清单

### 场景 1: 子代理启动超时 (spawn-timeout)

**症状**: `sessions_spawn` 调用后，子代理长时间不进入 started 状态  
**原因**:
- Gateway 进程无响应或资源耗尽
- 模型 API 端点不可达（网络/欠费/限流）
- 沙箱初始化失败

**诊断**:
```bash
# 检查 Gateway 状态
openclaw gateway status

# 检查最近子代理运行状态
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys, time
data = json.load(sys.stdin)
runs = data.get('runs', {})
for rid, r in list(runs.items())[-5:]:
    created = r.get('createdAt', 0) / 1000
    started = r.get('startedAt', 0) / 1000
    delay = started - created if started else '未启动'
    print(f'{rid[:8]}: 排队={delay}s, outcome={r.get(\"outcome\",{})}, reason={r.get(\"endedReason\",\"?\")}')
"
```

**恢复**:
1. 检查 Gateway 健康：`openclaw gateway status`
2. 重启 Gateway：`openclaw gateway restart`
3. 检查模型 fallback 链是否正常
4. 重试 spawn 调用，增加 `runTimeoutSeconds`

---

### 场景 2: 模型 API 不可用 (model-unavailable)

**症状**: 子代理启动后立即失败，outcome.status != "ok"  
**原因**:
- 主模型 API Key 失效或欠费
- 模型端点返回 429/503
- Fallback 链全部失败

**诊断**:
```bash
# 检查 openclaw.json 中的模型配置
cat ~/.openclaw/openclaw.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
models = data.get('models', {}).get('providers', {})
for provider, cfg in models.items():
    print(f'{provider}: {cfg.get(\"baseUrl\", \"?\")}')
    for m in cfg.get('models', []):
        print(f'  - {m[\"id\"]}')
"

# 测试模型连通性（示例）
curl -s -o /dev/null -w "%{http_code}" \
  -H "Authorization: Bearer $MOONSHOT_API_KEY" \
  https://api.moonshot.cn/v1/models
```

**恢复**:
1. 检查 `.env` 中 API Key 是否有效
2. 切换 fallback 模型：在 spawn 时指定 `model` 参数
3. 使用降级模型（参考 TOOLS.md 中的 fallback 链）

---

### 场景 3: 子代理运行超时 (run-timeout)

**症状**: `runTimeoutSeconds` 到期后子代理被强制终止  
**原因**:
- 任务复杂度超出预期
- 子代理陷入死循环或长时间等待
- 外部依赖响应慢（API/DB/网络）

**诊断**:
```bash
# 查看超时记录
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
for rid, r in data.get('runs', {}).items():
    if r.get('endedReason') == 'timeout':
        timeout = r.get('runTimeoutSeconds', '?')
        runtime = r.get('accumulatedRuntimeMs', 0) / 1000
        print(f'{rid[:8]}: timeout={timeout}s, 已运行={runtime}s')
"
```

**恢复**:
1. 分析任务是否真的需要这么长时间
2. 增加 `runTimeoutSeconds`（建议：简单任务 60s，复杂任务 300s+）
3. 优化任务描述，减少不必要的工作
4. 使用 `mode: "session"` 持久会话替代一次性 run

---

### 场景 4: 通信失败 (communication-failure)

**症状**: `sessions_send` 发送消息后无响应，或 `sessions_yield` 后未收到结果  
**原因**:
- 目标会话已结束或不可见
- 消息队列积压
- 网络分区（分布式部署场景）

**诊断**:
```bash
# 列出当前可见会话
openclaw sessions list 2>/dev/null || echo "需通过 sessions_list 工具调用"

# 检查子代理活跃状态
subagents list action=list
```

**恢复**:
1. 确认目标 sessionKey 是否有效
2. 使用 `sessions_list` 刷新会话列表
3. 如果子代理已 terminated，重新 spawn
4. 设置 `timeoutSeconds` 避免无限等待

---

### 场景 5: 死锁 (deadlock)

**症状**: 两个或多个子代理互相等待，系统挂起  
**原因**:
- A spawn B, B spawn A（循环依赖）
- 多个子代理竞争同一资源（文件锁）
- sessions_yield 后没有对应的子代理完成回调

**诊断**:
```bash
# 检查是否有子代理长时间运行
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys, time
data = json.load(sys.stdin)
now = time.time() * 1000
for rid, r in data.get('runs', {}).items():
    if not r.get('endedAt'):
        elapsed = (now - r.get('createdAt', now)) / 1000
        print(f'⚠️ 运行中: {rid[:8]}, 已运行 {elapsed:.0f}s')
        print(f'   task: {r.get(\"task\", \"?\")[:80]}')
"
```

**恢复**:
1. 使用 `subagents kill` 终止死锁子代理
2. 重新设计任务依赖关系（DAG 而非循环）
3. 添加死锁检测超时（spawn 时设置较短 timeout）
4. 使用 `sessions_yield` 时必须确保有子代理会完成

---

### 场景 6: 资源不足 (resource-exhaustion)

**症状**: 新子代理无法启动，或已运行的子代理 OOM  
**原因**:
- 同时 spawn 过多子代理（并行度过高）
- 单个子代理消耗过多内存（大文件/大数据集）
- 磁盘空间不足

**诊断**:
```bash
# 检查系统资源
echo "=== CPU ===" && top -l 1 -n 0 | head -5
echo "=== Memory ===" && vm_stat | head -10
echo "=== Disk ===" && df -h / | tail -1
echo "=== OpenClaw 进程 ===" && ps aux | grep openclaw | grep -v grep
```

**恢复**:
1. 降低并发度：使用序列化 spawn（逐个等待完成）
2. 限制单个子代理的资源：使用 `sandbox: "require"`
3. 清理磁盘空间
4. 定期 kill 已完成但未清理的子代理

---

### 场景 7: 配置错误 (config-error)

**症状**: 子代理使用错误的模型、工作目录或权限  
**原因**:
- `openclaw.json` 配置语法错误
- 环境变量未设置（`.env` 文件缺失）
- workspace 路径不存在

**诊断**:
```bash
# 验证 JSON 配置
python3 -c "import json; json.load(open('$HOME/.openclaw/openclaw.json'))" && echo "✅ JSON 有效" || echo "❌ JSON 无效"

# 检查环境变量
echo "DB_HOST=${DB_HOST:-未设置}"
echo "MOONSHOT_API_KEY=${MOONSHOT_API_KEY:0:8}..."
echo "Workspace: $(ls -d ~/.openclaw/workspace 2>/dev/null && echo '✅ 存在' || echo '❌ 不存在')"
```

**恢复**:
1. 修复 JSON 语法错误
2. 补充缺失的环境变量
3. 创建缺失的目录
4. 重启 Gateway 使配置生效

---

### 场景 8: 会话隔离失败 (isolation-breach)

**症状**: 子代理访问了不该访问的数据，或与其他子代理产生冲突  
**原因**:
- 未使用 sandbox 隔离
- 共享 workspace 目录的并发写入冲突
- session 间上下文泄漏

**诊断**:
```bash
# 检查子代理的 sandbox 配置
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
for rid, r in list(data.get('runs', {}).items())[-10:]:
    sandbox = r.get('sandbox', '未设置')
    cwd = r.get('workspaceDir', '?')
    print(f'{rid[:8]}: sandbox={sandbox}, cwd={cwd}')
"
```

**恢复**:
1. 使用 `sandbox: "require"` 强制隔离
2. 为并发子代理分配独立工作目录
3. 避免共享临时文件，使用唯一文件名
4. 使用 `lightContext: true` 减少上下文暴露

---

### 场景 9: 消息队列积压 (queue-backlog)

**症状**: 大量子代理排队等待执行，延迟显著增加  
**原因**:
- 短时间 spawn 大量子代理
- 执行模型响应慢
- Gateway 处理能力有限

**诊断**:
```bash
# 分析排队延迟趋势
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
runs = list(data.get('runs', {}).items())
delays = []
for rid, r in runs:
    created = r.get('createdAt', 0)
    started = r.get('startedAt', 0)
    if started:
        delays.append((started - created) / 1000)
if delays:
    print(f'排队延迟统计:')
    print(f'  平均: {sum(delays)/len(delays):.1f}s')
    print(f'  最大: {max(delays):.1f}s')
    print(f'  最小: {min(delays):.1f}s')
    print(f'  P95:  {sorted(delays)[int(len(delays)*0.95)]:.1f}s')
"
```

**恢复**:
1. 控制 spawn 速率（令牌桶或固定延迟）
2. 使用 `mode: "run"` 一次性任务替代长会话
3. 增加 Gateway 实例（分布式部署）
4. 设置合理的 `runTimeoutSeconds` 避免长任务阻塞

---

### 场景 10: 子代理结果丢失 (result-loss)

**症状**: 子代理返回 ok 但 `frozenResultText` 为空或截断  
**原因**:
- 子代理输出过大被截断
- 捕获时机不当（输出还未完成就被捕获）
- 序列化失败（非 UTF-8 字符）

**诊断**:
```bash
# 检查结果完整性
cat ~/.openclaw/subagents/runs.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
for rid, r in list(data.get('runs', {}).items())[-5:]:
    result = r.get('frozenResultText', '')
    status = r.get('outcome', {}).get('status', '?')
    print(f'{rid[:8]}: status={status}, result_len={len(result)}')
    if len(result) == 0 and status == 'ok':
        print(f'  ⚠️ 结果为空!')
    elif len(result) > 0:
        print(f'  预览: {result[:100]}...')
"
```

**恢复**:
1. 让子代理将结果写入文件而非 stdout
2. 在 `sessions_spawn` 中指定 `attachments` 存储大输出
3. 使用 `mode: "session"` 持久会话保留完整历史
4. 检查输出是否包含非 UTF-8 字符

---

### 场景 11: ACP 代理连接失败 (acp-connection-failed)

**症状**: `runtime: "acp"` spawn 失败，无法连接到外部编码代理  
**原因**:
- ACP 代理未安装或未配置
- `agentId` 不正确
- acp.allowedAgents 白名单限制

**诊断**:
```bash
# 检查 ACP 配置
cat ~/.openclaw/openclaw.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
acp = data.get('acp', {})
if acp:
    print('ACP 配置:', json.dumps(acp, indent=2))
else:
    print('未找到 ACP 配置')
"
```

**恢复**:
1. 确认 `agentId` 在 `acp.allowedAgents` 列表中
2. 如果没有 `acp.defaultAgent`，spawn 时必须指定 `agentId`
3. 检查 ACP 代理进程是否运行
4. 使用 `runtime: "subagent"` 作为降级方案

---

### 场景 12: 心跳/定时任务中断 (heartbeat-cron-interrupted)

**症状**: Cron 任务不再执行，或心跳检查停止  
**原因**:
- Gateway 崩溃后未自动重启
- Cron 配置被修改或删除
- 系统重启后 Gateway 未自启

**诊断**:
```bash
# 检查 Gateway 运行状态
ps aux | grep "openclaw" | grep -v grep

# 检查 cron 配置
cat ~/.openclaw/openclaw.json | python3 -c "
import json, sys
data = json.load(sys.stdin)
cron = data.get('cron', {})
if cron:
    jobs = cron.get('jobs', [])
    print(f'Cron 任务数: {len(jobs)}')
    for j in jobs:
        print(f'  - {j.get(\"id\", \"?\")}: {j.get(\"schedule\", \"?\")}')
else:
    print('未找到 cron 配置')
"
```

**恢复**:
1. 重启 Gateway：`openclaw gateway restart`
2. 设置开机自启（launchd/systemd）
3. 检查 cron jobs 配置是否完整
4. 添加 Gateway 健康监控（外部 watchdog）

### 3.2 快速诊断脚本

```bash
#!/bin/bash
# openclaw-diagnose.sh - 多代理系统快速诊断
# 用法: bash openclaw-diagnose.sh

RUNS_FILE="$HOME/.openclaw/subagents/runs.json"
GATEWAY_LOG="$HOME/.openclaw/gateway.log"

echo "========================================="
echo "  OpenClaw 多代理系统诊断报告"
echo "  时间: $(date '+%Y-%m-%d %H:%M:%S')"
echo "========================================="

# 1. Gateway 状态
echo ""
echo "【1】Gateway 状态"
if openclaw gateway status 2>/dev/null; then
    echo "  ✅ Gateway 运行正常"
else
    echo "  ❌ Gateway 异常 - 建议: openclaw gateway restart"
fi

# 2. 子代理统计
echo ""
echo "【2】子代理运行统计"
if [ -f "$RUNS_FILE" ]; then
    python3 -c "
import json, time
data = json.load(open('$RUNS_FILE'))
runs = data.get('runs', {})
total = len(runs)
ok = sum(1 for r in runs.values() if r.get('outcome',{}).get('status') == 'ok')
failed = total - ok
print(f'  总运行数: {total}')
print(f'  成功: {ok} ({ok/total*100:.1f}%)' if total else '  总运行数: 0')
print(f'  失败: {failed}' if total else '')

# 最近5条运行详情
print()
print('  最近 5 条运行:')
for rid, r in list(runs.items())[-5:]:
    created = r.get('createdAt', 0) / 1000
    started = r.get('startedAt', 0) / 1000
    ended = r.get('endedAt', 0) / 1000 if r.get('endedAt') else None
    delay = f'{started - created:.1f}s' if started else '未启动'
    runtime = f'{(ended - started):.1f}s' if ended and started else '运行中'
    status = r.get('outcome', {}).get('status', '?')
    reason = r.get('endedReason', '?')
    print(f'    {rid[:8]}: 排队={delay}, 运行={runtime}, status={status}, reason={reason}')
"
else
    echo "  ⚠️ runs.json 不存在"
fi

# 3. 资源检查
echo ""
echo "【3】系统资源"
echo "  磁盘: $(df -h / | tail -1 | awk '{print $4 " 可用"}')"
echo "  进程: $(ps aux | grep openclaw | grep -v grep | wc -l) 个 OpenClaw 进程"

# 4. 模型连通性快速检查
echo ""
echo "【4】模型 API 连通性"
if [ -n "$MOONSHOT_API_KEY" ]; then
    code=$(curl -s -o /dev/null -w "%{http_code}" -H "Authorization: Bearer $MOONSHOT_API_KEY" https://api.moonshot.cn/v1/models 2>/dev/null)
    if [ "$code" = "200" ]; then
        echo "  ✅ Moonshot API 正常 (HTTP $code)"
    else
        echo "  ❌ Moonshot API 异常 (HTTP $code)"
    fi
else
    echo "  ⚠️ MOONSHOT_API_KEY 未设置"
fi

echo ""
echo "========================================="
echo "  诊断完成"
echo "========================================="
```

## 4. 自动恢复方案

### 4.1 重试策略

#### 指数退避重试（推荐）

```python
import time
import random

def spawn_with_retry(spawn_func, max_retries=3, base_delay=2, max_delay=30):
    """带指数退避的子代理 spawn 重试"""
    for attempt in range(max_retries + 1):
        try:
            result = spawn_func()
            return result  # 成功
        except Exception as e:
            if attempt == max_retries:
                raise  # 最后一次重试仍失败，抛出异常
            
            # 指数退避 + 抖动
            delay = min(base_delay * (2 ** attempt), max_delay)
            jitter = random.uniform(0, delay * 0.1)
            wait_time = delay + jitter
            
            print(f"Spawn 失败 (尝试 {attempt+1}/{max_retries+1}): {e}")
            print(f"等待 {wait_time:.1f}s 后重试...")
            time.sleep(wait_time)
```

```python
# Fallback 链（来自 TOOLS.md）
FALLBACK_MODELS = [

def spawn_with_model_fallback(task, models=None):
    """使用模型降级链 spawn 子代理"""
    models = models or FALLBACK_MODELS
    last_error = None
    
    for model in models:
        try:
            result = sessions_spawn(task=task, model=model)
            print(f"✅ 使用模型 {model} 成功 spawn")
            return result
        except Exception as e:
            print(f"⚠️ 模型 {model} 失败: {e}")
            last_error = e
            continue
    
    raise RuntimeError(f"所有 {len(models)} 个模型均失败: {last_error}")
```

### 4.2 降级策略

| 故障类型 | 降级方案 | 影响 |
|---------|---------|------|
| 主模型不可用 | 使用 fallback 链 | 可能延迟增加，功能不变 |
| 子代理超时 | 拆分任务 + 串行执行 | 总时间增加，但成功率提高 |
| 资源不足 | 降低并发度至 1 | 吞吐量降低，但稳定性提高 |
| 通信失败 | 写入文件 + 轮询检查 | 延迟增加，但数据不丢失 |
| ACP 不可用 | 降级为 runtime: "subagent" | 失去 ACP 特性，但功能保留 |
| 全部失败 | 人工介入通知 | 最后防线 |

### 4.3 告警机制

#### 基于 runs.json 的自动告警检测

```python
import json
import time
from datetime import datetime

def check_subagent_health(runs_file="~/.openclaw/subagents/runs.json", 
                          alert_window_minutes=30,
                          failure_threshold=3):
    """检查子代理健康状态，超过阈值则告警"""
    
    with open(runs_file) as f:
        data = json.load(f)
    
    runs = data.get('runs', {})
    now = time.time() * 1000
    window_ms = alert_window_minutes * 60 * 1000
    
    recent_failures = []
    recent_total = 0
    
    for rid, r in runs.items():
        created = r.get('createdAt', 0)
        if now - created > window_ms:
            continue  # 超出时间窗口
        
        recent_total += 1
        status = r.get('outcome', {}).get('status', '')
        if status != 'ok':
            recent_failures.append({
                'runId': rid[:8],
                'status': status,
                'reason': r.get('endedReason', 'unknown'),
                'task': r.get('task', '')[:50]
            })
    
    alerts = []
    
    # 告警规则 1: 失败率过高
    if recent_total > 0:
        failure_rate = len(recent_failures) / recent_total
        if failure_rate > 0.5:
            alerts.append(f"🚨 高失败率: {failure_rate:.0%} ({len(recent_failures)}/{recent_total})")
    
    # 告警规则 2: 连续失败
    if len(recent_failures) >= failure_threshold:
        alerts.append(f"🚨 连续失败: {len(recent_failures)} 次 (阈值: {failure_threshold})")
    
    # 告警规则 3: 无活动（可能 Gateway 挂了）
    if recent_total == 0 and alert_window_minutes > 5:
        alerts.append("⚠️ 无活动: 时间窗口内无子代理运行")
    
    # 告警规则 4: 排队延迟过高
    delays = []
    for rid, r in runs.items():
        created = r.get('createdAt', 0)
        started = r.get('startedAt', 0)
        if now - created < window_ms and started:
            delays.append((started - created) / 1000)
    
    if delays:
        avg_delay = sum(delays) / len(delays)
        if avg_delay > 30:
            alerts.append(f"⚠️ 高排队延迟: 平均 {avg_delay:.0f}s")
    
    return alerts

# 使用示例
alerts = check_subagent_health()
if alerts:
    print("告警:")
    for a in alerts:
        print(f"  {a}")
else:
    print("✅ 子代理系统健康")
```

## 6. 性能指标检查

### 6.1 关键指标

| 指标 | 正常范围 | 告警阈值 | 说明 |
|------|---------|---------|------|
| 排队延迟 (queue_delay) | < 5s | > 30s | spawn 到 started 的时间 |
| 运行时间 (runtime) | 取决于任务 | > timeout 的 80% | 子代理实际运行时间 |
| 成功率 (success_rate) | > 95% | < 80% | 最近 30 分钟内的成功率 |
| 并发数 (concurrency) | ≤ 10 | > 20 | 同时运行的子代理数 |
| 内存使用 | < 70% | > 85% | 系统内存使用率 |
| API 响应时间 | < 2s | > 10s | 模型 API 的响应延迟 |

### 6.2 性能监控脚本

```bash
#!/bin/bash
# openclaw-perf-check.sh - 多代理性能检查

RUNS_FILE="$HOME/.openclaw/subagents/runs.json"

python3 -c "
import json, time

data = json.load(open('$RUNS_FILE'))
runs = data.get('runs', {})
now = time.time() * 1000
window = 30 * 60 * 1000  # 30 分钟

recent = []
for rid, r in runs.items():
    if now - r.get('createdAt', 0) < window:
        recent.append(r)

if not recent:
    print('最近 30 分钟无子代理运行')
    exit()

total = len(recent)
ok = sum(1 for r in recent if r.get('outcome',{}).get('status') == 'ok')

# 排队延迟
delays = [(r.get('startedAt',0) - r.get('createdAt',0))/1000 for r in recent if r.get('startedAt')]
avg_delay = sum(delays)/len(delays) if delays else 0

# 运行时间
runtimes = [r.get('accumulatedRuntimeMs',0)/1000 for r in recent if r.get('accumulatedRuntimeMs',0) > 0]
avg_runtime = sum(runtimes)/len(runtimes) if runtimes else 0

print('=== 多代理性能指标 (最近 30 分钟) ===')
print(f'总运行数:     {total}')
print(f'成功数:       {ok} ({ok/total*100:.1f}%)')
print(f'失败数:       {total-ok}')
print(f'平均排队延迟:  {avg_delay:.1f}s {\"⚠️\" if avg_delay > 30 else \"✅\"}')
print(f'平均运行时间:  {avg_runtime:.1f}s')
print(f'成功率:       {ok/total*100:.1f}% {\"✅\" if ok/total > 0.95 else \"🚨\" if ok/total < 0.8 else \"⚠️\"}')
"
```
