## 三、核心模块部署详情

### 3.1 任务分析器 (Gap Analysis Engine)

**文件**: `sds_core_v4_4.py`

**功能**: 五维差距分析
1. **missing_tasks**: active项目但0任务 → 自动生成任务拆解
2. **stale_project**: 超过7天无新任务 → 生成进度回顾任务
3. **task_backlog**: 单目标pending>10 → 生成积压处理方案
4. **zombie_task**: in_progress超过2小时无心跳 → 自动恢复
5. **repeated_failure**: retry_count>=3 → 生成根因分析任务

**技术修复**: 修复了v4.3中`c.fetchone()[0]`的DictCursor兼容性问题，改为使用字典键访问。

### 3.2 Kanban写入器

**集成方式**: 直接SQL INSERT到tasks表
- `task_type`: `auto_generated_v4.4`
- `execution_mode`: `auto`（可自动执行）/ `review_needed`（需审核）/ `user_action`（需用户执行）
- 速率限制：每小时最多20个自动任务
- 去重机制：基于项目ID和差距类型避免重复生成

### 3.3 子代理调度

**协同工作**: SDS核心模块与`self-driving-scheduler-v4.3.py`协同
- v4.3负责：任务执行、模型调度、心跳管理、质量门控
- v4.4负责：差距发现、任务生成、自愈修复、安全审计
- 两者通过数据库状态同步，无直接进程间通信依赖

### 3.4 结果回收

**机制**: 
- 质量门控（Quality Gate）: execution_log≥200字 AND result_summary≥50字
- 心跳检查: 60分钟无心跳 → 自动恢复为pending
- 僵尸检测: 30分钟无心跳且in_progress → 自动恢复

## 四、72h无人值守测试设计

### 4.1 自动监控机制

**监控器**: `sds_72h_monitor.py`
- 每15分钟执行一次健康检查
- 监控指标：调度器进程存活、数据库连接、任务状态分布
- 记录检查点到 `sds_72h_metrics.json`

### 4.2 异常检测

| 异常类型 | 检测条件 | 自动响应 |
|----------|----------|----------|
| 调度器崩溃 | pgrep检测不到进程 | 记录告警，等待外部重启 |
| 数据库断开 | 连接失败 | 3次重试，记录失败计数 |
| 任务堆积 | pending>50 | 触发LLM加速生成 |
| 心跳超时 | last_heartbeat>60min | 恢复为pending |
| 重复失败 | retry_count>=3 | 标记failed，生成诊断任务 |

### 4.3 自愈机制

**实现**: `heal_zombie_tasks()` 方法
- 检测所有in_progress超过2小时且无心跳的任务
- 未超retry_limit → 恢复为pending，retry_count+1
- 超过retry_limit → 标记为failed，避免无限循环

## 六、安全护栏

### 6.1 高风险操作拦截

**文件**: `sds_safety_guardrails_v4_4.py`

**检测类别**:
- **destructive**: `rm -rf`, `DROP TABLE`, `DELETE FROM`, `TRUNCATE`
- **system_control**: `shutdown`, `reboot`, `systemctl stop`
- **data_exfiltration**: `curl/wget/scp` 到外网
- **privilege_escalation**: `sudo + 危险命令`, `chmod 777`

**响应策略**:
- CRITICAL级别 → 拦截，要求人工审核（status→review_needed）
- HIGH/MEDIUM级别 → 记录审计日志，允许执行但加监控

### 6.2 SQL安全检测

- 拦截 `DELETE` 无 `WHERE`
- 拦截 `DROP TABLE` / `DROP DATABASE`
- 拦截 `TRUNCATE`

### 6.3 回滚方案

**实现**: `create_rollback_point()`
- 每次状态变更前保存before_state到 `sds_rollback_manifest.json`
- 记录：时间戳、任务ID、操作类型、变更前状态
- 支持手动回滚到任意检查点
