## 1. 系统概述

### 1.1 什么是OpenClaw知识大脑？

OpenClaw知识大脑是一个**基于LLM（大语言模型）+ Graph RAG（图增强检索）的多层级知识管理系统**，旨在解决AI加速材料发现中"模型可解释性和知识沉淀"的核心瓶颈（参考：Nature Communications Materials 2026, doi:10.1038/s43246-026-01105-0）。

系统以"user-friendliness as guiding principle"（Berkeley Lab Materials Project理念）为设计原则，将**碎片化的研究素材**转化为**结构化的知识图谱**，并通过**多Agent协作**实现知识的自动采集、组织、检索和推理。

### 1.2 核心架构

```
┌─────────────────────────────────────────────────────────┐
│                    知识大脑 v2.0                          │
├─────────────────────────────────────────────────────────┤
│  输入层：微信文章/论文PDF/会议记录/网页剪藏/手动笔记         │
│       ↓                                                   │
│  处理层：LLM自动分类 → 实体抽取 → 概念关联 → 质量门控       │
│       ↓                                                   │
│  存储层：三大知识库（wiki + llmwiki + wiki-papers）         │
│       ↓                                                   │
│  检索层：3阶段Graph RAG（向量粗筛→图路径扩展→语义排序）      │
│       ↓                                                   │
│  输出层：Obsidian笔记 / 看板任务 / 记忆文件 / 研究报告       │
└─────────────────────────────────────────────────────────┘
```

## 3. 知识库录入规范

### 3.1 论文笔记录入标准

每篇论文笔记必须包含以下结构：

```markdown
---
title: "论文标题"
authors: ["作者1", "作者2"]
year: 2026
journal: "期刊名称"
doi: "10.xxxx/xxxxx"
tags: [材料科学, AI, 催化]
status: "已读|待读|精读"
rating: 1-5
---

## 摘要
[论文摘要原文或翻译]

## 核心发现
- [发现1]
- [发现2]

## 方法
[实验方法或计算方法]

## 与现有工作的关系
[[相关论文1]]、[[相关概念]]

## 个人笔记
[你的理解和思考]
```

**质量要求：**
- 必填字段：title, authors, year, doi, tags
- 必须建立至少1个 `[[wikilink]]` 关联到已有实体或概念
- 个人笔记不少于3句话

```markdown
name: "姓名"

## 基本信息

- 研究方向：XXX

## 合作关系
- 与[[某项目]]的关系
- 与[[某人]]的合作

## 备注
[互动记录、重要事项]
```

**机构实体：**

```markdown
## 基本信息
```

### 3.5 录入检查清单（Quality Gate）

录入任何内容前，必须通过以下检查：

- [ ] 文件命名符合规范（见下方命名规则）

- [ ] 建立了至少1个wikilink关联
- [ ] tags 合理且一致
- [ ] 无乱码、格式正确
- [ ] 内容已去重（搜索确认不存在重复条目）

## 4. 检索技巧与最佳实践

### 4.1 三种检索方式

#### 方式一：语义搜索（推荐）

通过 `memory_search` 工具进行语义检索：

```
# 示例：查找与催化相关的项目记忆
memory_search(query="催化 项目 进展")

# 示例：查找特定联系人
memory_search(query="张伟 北航 合作")
```

**优点：** 不依赖关键词精确匹配，能理解语义关系
**适用场景：** 模糊记忆、跨领域关联

#### 方式二：Graph RAG 3阶段检索

这是知识大脑的核心检索管道：

```
阶段1：向量粗筛
    → 使用embedding计算查询向量
    → 与知识库中所有节点计算相似度
    → 返回Top-K候选

阶段2：图路径扩展
    → 从Top-K节点出发
    → 沿关系边扩展（最多2跳）
    → 发现间接关联

阶段3：语义排序
    → 使用LLM对扩展结果重新排序
    → 返回最相关的结果
```

**脚本位置：** `scripts/graph_rag_retrieval.py`

#### 方式三：Obsidian CLI搜索

```bash
# 按标题搜索
obsidian-cli search "催化"

# 按内容搜索（全文搜索）
obsidian-cli search-content "机器学习 催化剂 筛选"
```

**适用场景：** 快速查找已知存在的笔记

### 4.2 检索最佳实践

1. **先宽后窄：** 先用语义搜索获取大范围结果，再精确定位
2. **利用标签：** 录入时打准确的tags，检索时按tag过滤
3. **建立关联：** wikilink越多，Graph RAG的效果越好
4. **使用同义词：** 搜索时考虑同义词（如"ML"="机器学习"="machine learning"）
5. **定期维护索引：** 每月检查 `memory/index.md` 确保索引准确

### 4.3 常见检索场景

| 场景 | 推荐方法 | 示例查询 |
|------|---------|---------|
| 找某篇论文 | 语义搜索 + doi | "doi:10.1038/s43246" |
| 找某人的所有合作 | 语义搜索 + 图谱 | "张伟 合作 项目" |
| 了解某个概念 | Graph RAG | "密度泛函理论 应用" |
| 找会议记录 | Obsidian CLI | obsidian-cli search "融资" |
| 找项目进展 | 语义搜索 | "和光智成 融资 进展" |
| 跨领域关联 | Graph RAG | "AI 材料 催化 最新进展" |

## 5. 自动化规则配置

### 5.1 自动化触发器

OpenClaw支持以下自动化触发器：

| 触发器 | 触发条件 | 执行动作 |
|--------|---------|---------|
| **新论文到达** | 检测到新PDF/DOI | 自动创建笔记 → 抽取实体 → 建立关联 |
| **微信文章** | Diary topic收到消息 | 7步处理流程（分类→关联→存储） |
| **每日结束** | 定时任务（heartbeat） | 整理每日日志 → 更新记忆索引 |
| **每周日** | 定时任务（cron） | 周报生成 → 记忆修剪 → 归档 |
| **新联系人** | 名片扫描/手动输入 | 创建实体 → 关联项目 → 更新contacts.md |

### 5.2 知识库录入自动化

#### 规则1：论文自动处理

```yaml
trigger: new_pdf_detected
actions:
  - extract_metadata: title, authors, year, doi
  - create_note: wiki-papers/papers/{title_slug}.md
  - extract_entities: 作者、机构、关键词
  - link_existing: 关联到已有实体和概念
  - quality_check: 通过WIKI-QUALITY-GATE.md标准
```

#### 规则2：微信内容处理（Diary Topic SOP）

```yaml
trigger: diary_topic_message
actions:
  - step1_identify: 识别内容类型（文本/图片/文件/链接）
  - step2_task_link: 关联到看板任务（更新execution_log）
  - step3_project_link: 归属到具体项目（强制）
  - step4_knowledge: 入Vault，创建结构化笔记
  - step5_calendar: 如有约见/截止日 → 三源同步
  - step6_status: 更新看板状态
  - step7_reminder: 处理提醒和跟进
```

#### 规则3：记忆自动维护

```yaml
trigger: heartbeat_or_cron
actions:
  - daily: 写入 memory/daily/YYYY-MM-DD.md
  - weekly: 整理到 memory/weekly/YYYY-WW.md
  - monthly: 归档 >3个月内容到 memory/archive/
  - periodic: 修剪 MEMORY.md，确保 < 5KB
```

### 5.3 自定义自动化规则

要添加新的自动化规则：

1. 在 `memory/core-principles.md` 中记录规则定义
2. 创建对应的cron任务或heartbeat检查项
3. 测试规则在sandbox环境中的行为
4. 验证后部署到生产环境
5. 更新 `HEARTBEAT.md` 加入新检查项

**⚠️ 安全要求：**
- 自动化规则不得自动执行外部操作（发邮件、发推等）
- 涉及对外通信的规则必须设置为 `review_needed` 模式
- 所有自动化操作必须写入日志

### 5.4 自动化规则示例：论文下载+入库

以ACS论文下载为例（参考 `skills/acs-paper-download/SKILL.md`）：

```bash
# 1. 下载论文PDF
python3 skills/acs-paper-download/download.py --doi "10.1021/xxx"

# 2. 自动解析元数据
python3 scripts/extract_metadata.py --pdf output.pdf

# 3. 创建wiki-papers笔记
# （由LLM自动完成，含摘要提取、关键词生成、实体关联）

# 4. 质量检查
# 对照 WIKI-QUALITY-GATE.md 检查完整性
```

## 6. 多Agent协作与Graph RAG

### 6.1 Agent能力注册

系统注册了4类Agent：

| Agent类型 | 能力 | 典型用途 |
|-----------|------|---------|
| **research** | 网络搜索、论文检索、数据收集 | Tavily搜索、DOI查询、文献综述 |
| **analysis** | 数据分析、报告生成、推理 | 财务分析、技术评估、差距分析 |
| **execution** | 代码执行、文件操作、部署 | 数据库更新、脚本运行、文件管理 |
| **wiki** | 知识录入、笔记生成、关联建立 | 论文笔记创建、实体关联、概念扩展 |

### 6.2 任务路由矩阵

任务根据关键词+能力匹配自动路由：

```
关键词包含"搜索/查找/论文"  → research Agent
关键词包含"分析/评估/报告"  → analysis Agent
关键词包含"执行/运行/部署"  → execution Agent
关键词包含"笔记/录入/关联"  → wiki Agent
```

### 6.3 ACP通信协议

Agent间通信使用ACP协议，支持6种消息类型：

- `task_assign` - 任务分配
- `task_result` - 任务结果返回
- `query` - 查询请求
- `response` - 查询响应
- `error` - 错误报告
- `status_update` - 状态更新

**通信模式：** 同步请求-响应、异步发布-订阅、流式传输

### 6.4 Graph RAG 概念图谱

当前概念图谱包含：

- **30个核心概念**（9个分类）
- **55个关系**（覆盖architecture/capability/memory跨域关联）
- **10条行为规则**（审核/安全/流程/工具）
- **衰减机制：** 1%/日指数衰减 + 使用加权

**关系类型示例：**
- `depends_on` - 依赖关系
- `related_to` - 关联关系
- `instance_of` - 实例关系
- `part_of` - 组成关系

### 6.5 多Agent协作示例

```
用户请求："帮我分析近3个月AI催化剂领域的最新进展"
    ↓
调度器解析 → research Agent
    ↓
research Agent:
  - Tavily搜索近3个月相关论文
  - 提取DOI列表
    ↓
wiki Agent:
  - 检查wiki-papers中是否已有笔记
  - 对新论文创建笔记
  - 建立概念关联
    ↓
analysis Agent:
  - 汇总所有相关论文
  - 生成分析报告
  - 识别趋势和空白
    ↓
返回：综合报告 + 更新的知识图谱
```

## 7. Obsidian联动操作指南

### 7.1 Obsidian CLI基础

**安装：**
```bash
brew install yakitrak/yakitrak/obsidian-cli
```

**设置默认Vault：**
```bash
obsidian-cli set-default "wiki"
obsidian-cli print-default  # 确认设置
```

### 7.2 常用命令

```bash
# 按标题搜索
obsidian-cli search "关键词"

# 全文内容搜索（含行号）
obsidian-cli search-content "关键词"

# 创建新笔记
obsidian-cli create "Folder/Note Name" --content "..." --open

# 移动/重命名笔记（自动更新wikilink）
obsidian-cli move "old/path/note" "new/path/note"

# 删除笔记
obsidian-cli delete "path/note"
```

### 7.3 多Vault管理

| Vault名称 | 路径 | 用途 |
|-----------|------|------|
| wiki | `~/Library/Mobile Documents/.../wiki/` | 实体知识图谱（主） |

### 7.4 Wikilink规范

## 8. 日常维护与版本管理

### 8.1 记忆系统维护周期

| 周期 | 任务 | 负责 |
|------|------|------|
| 每日 | 写入日志到 `memory/daily/` | AI助手自动 |
| 每周日 | 整理周报、修剪记忆 | AI助手自动 |
| 每月底 | 归档 >3个月内容 | AI助手自动 |

| 每季度 | 评估概念图谱质量 | 人工 |

### 8.2 知识库质量维护

**每月检查项：**
- [ ] wiki概念有效率是否提升（目标 > 20%）
- [ ] wiki实体有效率是否提升（目标 > 40%）
- [ ] 检查重复实体（合并重复）
- [ ] 修复断链（broken wikilinks）
- [ ] 更新 `memory/index.md`

### 8.3 版本管理

所有核心文件在Git版本控制下：

```bash
# 查看变更
git status
git log --oneline -10

# 提交变更
git add memory/
git commit -m "更新记忆系统：XXX"
git push

# 回滚
git log --oneline
git revert <commit-hash>
```

**⚠️ 重要：** 修改核心文件前必须先备份：
```bash
cp -a ~/.openclaw/workspace ~/.openclaw/workspace.bak.$(date +%Y%m%d_%H%M%S)
```

### 8.4 性能优化建议

1. **iCloud同步优化：** 三大知识库在iCloud下，大量文件时同步可能延迟，建议批量操作后等待同步完成
2. **定期清理：** 删除不再需要的临时文件，减少iCloud同步负担
3. **索引更新：** 每次大规模变更后，运行索引更新脚本
4. **内存管理：** Agent会话设置合理的上下文窗口大小，避免token浪费

## 9. 故障排查

### 9.1 常见问题速查

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 搜不到已知内容 | 索引未更新/文件在错误目录 | 检查文件实际位置，更新索引 |
| wikilink断链 | 文件被重命名或移动 | 使用Obsidian CLI `move` 而非手动 |
| 新笔记未关联 | 未建立wikilink | 录入时强制关联至少1个已有实体 |
| Agent路由错误 | 关键词匹配不准确 | 检查任务描述，调整路由规则 |
| iCloud同步冲突 | 多设备同时编辑 | 关闭一个设备，等待同步完成 |
| 记忆系统"失忆" | MEMORY.md超过20KB被截断 | 保持 < 5KB，详细内容下沉到子目录 |
