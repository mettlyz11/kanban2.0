# 线索转化率诊断分析与优化方案

## 一、转化率漏斗诊断框架

### 1.1 标准B2B线索转化漏斗（供对标）

| 阶段 | 典型转化率 | 关键指标 | 健康度阈值 |
|:---|:---|:---|:---|
| MQL（营销合格线索）→ SQL（销售合格线索） | 25-35% | SQL接受率、线索评分达标率 | <20% 为红灯 |
| SQL → 商机（Opportunity） | 40-60% | 初次会议 booked 率、BANT达标率 | <30% 为红灯 |
| 商机 → 提案（Proposal） | 60-75% | 需求确认完成率、决策者接触率 | <50% 为红灯 |
| 提案 → 成交（Closed-Won） | 25-40% | 赢单率、平均成交周期 | <20% 为红灯 |
| **端到端转化率** | **1.5-3.1%** | CAC、LTV/CAC | <1% 为红灯 |

## 二、瓶颈定位诊断清单（按优先级排序）

### 🔴 第一优先级：SQL→商机阶段（最常见瓶颈）

| 症状 | 根因假设 | 验证方法 | 快速验证问题 |
|:---|:---|:---|:---|
| SQL被销售大量退回 | 营销-销售线索标准不一致 | 抽查20条被退回SQL的拒绝理由 | 销售是否参与过MQL定义？ |
| 初次会议 booked 率低 | SDR跟进速度/话术问题 | 分析首次响应时间 vs booked率相关性 | 平均首次响应时间>5分钟？ |
| 客户无真实购买意向 | 线索来源渠道质量差 | 分渠道对比SQL→商机转化率 | 某渠道转化率低于均值50%？ |

**关键诊断动作：**
```
1. 提取过去90天所有SQL数据，按来源渠道、获客campaign、线索评分分段
2. 计算各维度的 SQL→商机转化率，识别异常低的分段
3. 访谈5-10名销售，收集SQL质量反馈的具体案例
```

### 🟡 第二优先级：商机→提案阶段

| 症状 | 根因假设 | 验证方法 |
|:---|:---|:---|
| 商机长期停滞"培育中" | 缺乏决策推进机制/多线程触达不足 | 分析商机阶段停留时长分布 |
| 需求确认后客户消失 | 价值主张未击中痛点或竞品介入 | 复盘丢单原因，统计"无决策/竞品"占比 |
| 无法接触到决策者 | 关系仅停留在执行层 | 统计商机中接触到的角色层级 |

### 🟢 第三优先级：提案→成交阶段

| 症状 | 根因假设 | 验证方法 |
|:---|:---|:---|
| 提案后客户沉默 | 提案价值量化不足或审批流程卡壳 | 分析提案→签约平均时长及催单响应 |
| 赢单率持续走低 | 价格竞争力或POC效果问题 | 分竞品/行业统计赢单率差异 |
| 成交周期过长 | 内部审批流程或客户预算周期 | 对比行业基准，识别异常长单 |

## 三、数据提取需求（供BI/数据团队）

### 3.1 核心数据表

| 数据表 | 必需字段 | 用途 |
|:---|:---|:---|
| 线索全生命周期表 | 线索ID、创建时间、来源渠道、UTM参数、MQL时间、SQL时间、商机创建时间、成交时间、金额、流失时间/阶段 | 计算各阶段转化率、周期 |
| 销售活动日志 | 线索ID、活动类型、活动时间、活动结果、销售ID | 分析跟进频率、内容、时效 |
| 线索评分历史 | 线索ID、评分模型、评分值、评分时间 | 验证评分模型有效性 |
| 销售反馈标签 | 线索ID、退回/流失原因分类、备注 | 定性分析瓶颈 |

### 3.2 关键分析视图

```sql
-- 示例：渠道质量诊断SQL（供参考）
SELECT 
    lead_source,
    COUNT(*) as total_mql,
    SUM(CASE WHEN stage >= 'SQL' THEN 1 ELSE 0 END) as sql_count,
    SUM(CASE WHEN stage >= 'Opportunity' THEN 1 ELSE 0 END) as opp_count,
    SUM(CASE WHEN stage = 'Closed-Won' THEN 1 ELSE 0 END) as won_count,
    ROUND(sql_count*100.0/total_mql,1) as mql_to_sql_rate,
    ROUND(opp_count*100.0/sql_count,1) as sql_to_opp_rate,
    AVG(DATEDIFF(day, mql_date, sql_date)) as avg_mql_to_sql_days,
    AVG(CASE WHEN stage = 'Closed-Won' THEN deal_amount END) as avg_deal_size
FROM lead_lifecycle 
WHERE mql_date >= DATEADD(month, -6, GETDATE())
GROUP BY lead_source
ORDER BY mql_to_sql_rate DESC;
```
