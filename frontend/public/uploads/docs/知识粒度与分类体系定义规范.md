# 标准架构规范文档：定义知识粒度和分类体系 [04291802]

## 1. 概述与建设目标

### 1.1 文档定位
本规范文档作为知识库架构的核心基础标准，正式定义知识粒度五级模型与五维分类体系。本规范适用于所有参与知识库系统建设、内容生产、质量审核、系统开发及运维管理的团队成员。

### 1.2 建设目标
- **统一认知基础**：消除团队内部对“知识粒度”和“知识分类”概念的理解偏差，建立精确、无歧义的术语体系。
- **指导系统架构**：为知识存储引擎、检索算法、推荐系统及内容管理后台提供明确的数学与语义约束。
- **支撑内容治理**：提供可量化的内容分级标准和分类映射规则，实现知识资产的自动化治理与生命周期管理。
- **保障扩展性**：确保模型与体系在业务规模增长、新领域引入时仍保持结构稳定和逻辑自洽。

### 1.3 适用范围
本规范适用于知识库系统中所有结构化/非结构化知识单元（包括但不限于文档、片段、实体、关系、原子事实等）的粒度标注与分类映射。

## 2. 知识粒度五级模型定义

### 2.1 模型总览
知识粒度五级模型（KG5-Layer Model）采用分层抽象原则，从信息论视角对知识单元进行层级划分。每一层对应特定的信息熵范围、概念抽象层级和语义聚合度。

### 2.2 五级粒度定义

#### Level 1：原子事实（Atomic Fact）
- **定义**：不可再分的最小知识单元，表达单一、明确的事实断言。
- **信息粒度数学表达**：设原子事实f的信息熵H(f) = -log₂P(f)，其中P(f)为事实在领域内成立的概率。标准范围：H(f) ∈ (0, 2] bits。
- **概念瓶颈分层语义**：处于概念瓶颈的最底层，仅包含主语-谓语-宾语三元组（SPO），无修饰、无上下文。
- **示例**：
  - `(地球, 是, 行星)`
  - `(Python, 发布于, 1991年)`
  - `(水的沸点, 为, 100°C)`
- **存储约束**：单一原子事实的存储大小不超过512字节。

#### Level 2：信息片段（Information Chunk）
- **定义**：由2-5个原子事实聚合而成的逻辑连贯的信息块，具备独立语义完整性。
- **信息粒度数学表达**：信息片段C由原子事实集合F = {f₁, f₂, ..., fₙ}构成，n∈[2,5]。其联合熵H(C) = H(f₁, f₂, ..., fₙ)满足：H(C) ∈ (2, 8] bits。
- **概念瓶颈分层语义**：越过第一层概念瓶颈，形成微语义单元，可独立回答问题。
- **示例**：
  - “Python由Guido van Rossum于1991年发布，是一种解释型高级编程语言。”（包含3个原子事实）
  - “地球是太阳系八大行星之一，自转周期约为24小时。”（包含2个原子事实）
- **存储约束**：单一信息片段存储大小不超过4KB。

#### Level 3：知识条目（Knowledge Item）
- **定义**：围绕单一主题组织的完整知识描述，包含多个信息片段，形成自包含的知识单元。
- **信息粒度数学表达**：知识条目I包含信息片段集合S = {C₁, C₂, ..., Cₘ}，m∈[3, 20]。其联合熵H(I) ∈ (8, 32] bits。
- **概念瓶颈分层语义**：跨越第二层概念瓶颈，形成主题级语义闭包。
- **示例**：
  - “Python编程语言”条目（包含语法特性、历史沿革、应用领域等信息片段）
  - “光合作用”条目（包含反应方程式、发生条件、意义等信息片段）
- **存储约束**：单一知识条目存储大小不超过256KB。

#### Level 4：知识模块（Knowledge Module）
- **定义**：由多个知识条目按逻辑结构（如层次、序列、因果）组织而成的专题知识集合。
- **信息粒度数学表达**：知识模块M包含知识条目集合T = {I₁, I₂, ..., Iₖ}，k∈[5, 50]。其联合熵H(M) ∈ (32, 128] bits。
- **概念瓶颈分层语义**：跨越第三层概念瓶颈，形成领域子专题级知识结构。
- **示例**：
  - “编程语言基础”模块（包含Python、Java、C++等条目及比较关系）
  - “细胞生物学”模块（包含细胞结构、细胞分裂、细胞代谢等条目）
- **存储约束**：单一知识模块存储大小不超过50MB。

#### Level 5：知识领域（Knowledge Domain）
- **定义**：完整学科或业务领域的知识总和，包含多个知识模块及其元知识（跨模块关系、方法论）。
- **信息粒度数学表达**：知识领域D包含知识模块集合Z = {M₁, M₂, ..., Mₚ}，p∈[10, ∞)。其联合熵H(D) > 128 bits。
- **概念瓶颈分层语义**：跨越最高层概念瓶颈，形成全局语义空间。
- **示例**：
  - “计算机科学”领域（包含编程语言、数据结构、算法、网络等模块）
  - “基础医学”领域（包含解剖学、生理学、病理学等模块）
- **存储约束**：单一知识领域存储大小不限，但需满足分层索引要求。

### 2.3 粒度判定规则

| 粒度层级 | 原子事实数 | 信息熵范围(bits) | 语义完整性 | 独立可发布性 |
|----------|------------|------------------|------------|--------------|
| L1       | 1          | (0, 2]           | 低         | 否           |
| L2       | 2-5        | (2, 8]           | 中低       | 否           |
| L3       | 6-100      | (8, 32]          | 中         | 是           |
| L4       | 101-500    | (32, 128]        | 高         | 是           |
| L5       | >500       | >128             | 极高       | 是           |

## 3. 五维知识分类体系构建

### 3.1 维度总览
五维分类体系从五个正交维度对知识单元进行标注，确保每个知识单元在语义空间中具有唯一坐标。

### 3.2 五维定义

#### 维度1：学科领域（Subject Domain）

- **分类标准**：依据中图分类法（CLC）一级类目，结合业务需求扩展。

| D01-03 | 工程技术         | 含计算机、机械、电子     | 不包含基础科学理论推导           |

| D05-05 | 瞬时性知识   | 实时事件、动态数据         | <30天        |

### 3.3 分类标注规范
每个知识单元必须标注完整的五维分类编码，格式为：`D01-XX|D02-XX|D03-XX|D04-XX|D05-XX`。
示例：`D01-03|D02-03|D03-03|D04-03|D05-03` 表示“工程技术-程序性知识-应用-技术文档-中期性知识”。

## 4. 粒度与分类的内在关联与解耦机制

### 4.1 关联映射原则
粒度层级与分类维度之间存在推荐映射关系，但非强制绑定：

| 粒度层级 | 推荐学科领域 | 推荐知识类型 | 推荐认知层次 |
|----------|--------------|--------------|--------------|
| L1       | 任意         | D02-01       | D03-01       |
| L2       | 任意         | D02-01/D02-02| D03-01/D03-02 |
| L3       | 任意         | 全部         | D03-02-D03-04|
| L4       | 特定子领域   | D02-03/D02-04| D03-04-D03-05|
| L5       | 完整学科     | D02-04/D02-05| D03-05-D03-06|

### 4.2 解耦机制设计
为确保系统的灵活性和扩展性，粒度与分类之间采用**松耦合**设计：

1. **独立存储**：粒度属性存储在知识单元的元数据字段中，分类标签存储在独立的多维索引表中。
2. **正交查询**：检索系统支持粒度过滤与分类过滤的独立组合，不产生交叉依赖。
3. **动态重分类**：知识单元的粒度不随分类变化而改变，反之亦然。允许同一知识单元在不同上下文中被赋予不同分类（多归属机制）。
4. **冲突解决规则**：当粒度推荐与分类标签冲突时，以分类标签为准，但系统需记录异常并触发人工审核。

### 4.3 关联查询接口规范
```python
# 伪代码示例：粒度与分类联合查询
def query_knowledge(granularity_level: int, 
                    subject_domain: str, 
                    knowledge_type: str,
                    cognitive_level: str) -> List[KnowledgeUnit]:
    """
    根据粒度层级和分类维度联合查询知识单元。
    
    Args:
        granularity_level: 粒度层级（1-5）
        subject_domain: 学科领域编码
        knowledge_type: 知识类型编码
        cognitive_level: 认知层次编码
        
    Returns:
        匹配的知识单元列表
    """
    # 1. 从粒度索引中获取指定层级的知识单元ID
    level_ids = granularity_index.get_ids(level=granularity_level)
    
    # 2. 从分类索引中获取匹配的分类条件
    category_ids = category_index.query(
        subject_domain=subject_domain,
        knowledge_type=knowledge_type,
        cognitive_level=cognitive_level
    )
    
    # 3. 取交集
    matched_ids = set(level_ids) & set(category_ids)
    
    # 4. 从存储引擎中获取完整知识单元
    return knowledge_store.batch_get(matched_ids)
```

## 5. 知识库架构集成设计原则与扩展规范

### 5.1 存储架构设计原则
1. **分层存储**：粒度层级作为存储分区的第一级键（Partition Key），分类维度作为第二级键（Sort Key）。
2. **索引冗余**：粒度索引和分类索引独立建立，支持各自的高效查询。
3. **数据隔离**：不同粒度的知识单元存储在独立的物理存储区域，便于差异化压缩和缓存策略。

### 5.3 扩展规范
1. **维度扩展**：新增分类维度需遵循本规范定义的格式标准，且需与现有维度正交性验证。
2. **粒度扩展**：禁止在现有五级之间插入新层级。如需更细粒度，可在L1下定义子层级（如L0.5），但需明确标注。
3. **版本兼容**：所有扩展不得破坏已有知识单元的粒度标注和分类映射。
