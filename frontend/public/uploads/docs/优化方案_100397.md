## 1. 对任务目标的深度理解和分析

### 1.1 表面目标 vs. 深层目标

**表面目标:** 开发一个能够从指定数据源（如网页链接列表、数据库记录、API接口）批量下载PDF文件，并按照预设规则（如按日期、项目、作者、主题等）自动归档到本地或网络存储目录的软件模块。

**深层目标分析:**
*   **提升效率，降低人工成本:** 对于需要频繁处理大量PDF文档的岗位（如法务、审计、研究、档案管理），手动下载和整理文件是极其耗时且容易出错的工作。该模块的核心价值在于将人工重复性劳动自动化，释放人力资源用于更高价值的分析、决策工作。
*   **构建结构化数据管道:** 该模块不应是一个孤立的工具，而应作为企业或项目数据管道中的关键一环。它需与上游数据源（如爬虫系统、业务数据库、OA系统）和下游处理系统（如OCR识别、文本分析、知识图谱构建、日志审计）实现无缝对接。
*   **确保数据质量与可追溯性:** 不仅仅是下载文件，更要验证文件的完整性（如MD5校验）、来源的可靠性（如HTTPS证书验证）、信息的正确性（如文件名是否符合规范）。同时，归档过程必须留下清晰的元数据记录（如下载时间、源URL、归档路径、文件大小），以满足审计和事后追踪的需求。
*   **应对复杂多变的环境:** 实际生产环境中的PDF链接来源多样，可能包含动态页面、需要登录认证的站点、有反爬机制的网站、带参链接或需要特定Header的请求。模块必须具备高度的灵活性和容错性，以应对这些不确定因素。

### 1.2 关键成功指标（KPIs）

基于上述分析，我们定义了以下关键成功指标来衡量任务的完成度：

1.  **下载成功率:** 单个任务周期内成功下载的PDF文件数 / 应该下载的PDF文件总数（目标值：> 99.5%）。
2.  **平均下载速度:** 单个PDF文件的平均下载时间（单位：秒/MB），考虑到带宽和服务器响应，目标值需根据测试环境确定。
3.  **归档错误率:** 因归档规则不匹配、路径冲突、权限问题导致归档失败的文件数 / 总下载文件数（目标值：< 0.1%）。
4.  **元数据完整率:** 归档后每份PDF文件对应的元数据记录（来源、时间、大小、校验码等）的完整程度（目标值：100%）。
5.  **模块可扩展性:** 添加新的数据源类型（比如从CSV列表改为从企业内部API获取链接）或新的归档规则所需的人天工时（目标值：< 1人天/次改动）。

    *   **When:** 何时触发？（定时任务、API调用、事件驱动）下载周期？（每日、每小时）
    *   **Where:** 模块部署在哪里？（本地服务器、AWS Lambda、Kubernetes集群）
    *   **Why:** 为什么要这么做？（解决重复劳动、构建数据孤岛、满足合规要求）
    *   **How:** 如何实现？（技术选型、架构设计）
*   **产出物:**
    *   *需求规格说明书:* 详细定义了输入源（支持URL列表文件、RESTful API接口、消息队列）、核心功能（并发下载、超时重试、断点续传）、归档规则（正则表达式、模板语法）、输出格式（本地文件系统、S3兼容存储、NFS）。
    *   *系统架构图:* 明确了模块由调度器、下载器池、校验器、归档执行器、元数据管理器、监控与告警组件六大核心模块构成。
    *   *技术选型:* Python 3.10 + `aiohttp`（异步下载）+ `watchdog`（实时监控）+ `minio`（S3存储客户端）+ `SQLite`（本地元数据库）。

### 2.2 阶段二：核心模块开发 & 单元测试（计划：5天）

*   **方法:** 采用**TDD**（测试驱动开发）。先编写失败的单元测试用例，再编写实现代码，最后重构。
*   **实现过程:**
    1.  **调度器模块:**
        *   实现一个`TaskProducer`类，负责解析数据源（如读取CSV文件、调用HTTP API）生成待下载任务队列。
        *   采用生产者-消费者模式，使用Python的`asyncio.Queue`作为任务缓冲区，支持优先级调度（如按文件大小或时间戳）。
    2.  **下载器池:**
        *   使用`aiohttp`构建异步下载客户端，利用`asyncio.Semaphore`控制并发数（缺省为10，可配置），防止对目标服务器造成过大压力。
        *   内置重试机制：自动重试3次，间隔呈指数增长（1s, 2s, 4s），并针对`HTTP 429`（Too Many Requests）和`5xx`错误进行特殊处理。
        *   实现断点续传：通过`HTTP Range`头部，支持中途中断后继续下载。
    3.  **校验器:**
        *   下载完成后，立即进行完整性校验：计算文件的MD5值，并与源站提供的（或在任务中配置的）期望值进行比对。若不一致，标记为“损坏”并触发警报。
    4.  **归档执行器:**
        *   设计灵活的路由规则引擎。支持使用Jinja2模板引擎定义归档路径。例如：`{{ type }}/{{ date.year }}/{{ date.month }}/{{ document_name}}_{{ hash_md5[:8] }}.pdf`
        *   实现多目标存储抽象层，支持本地文件系统、S3 API兼容存储（如MinIO, AWS S3）和SFTP。
