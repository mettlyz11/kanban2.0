## 第一章 范围界定

### 1.1 梳理主体明确

在执行清单梳理前，需明确以下三个维度：

**维度A：组织层级**
- 集团级：覆盖所有子公司及海外分支机构
- 部门级：仅限本部门直接管理的合作资源
- 项目级：针对特定国际项目的合作资源

**维度B：业务领域**
- 技术研发合作（联合实验室、技术引进）
- 市场拓展合作（代理协议、分销渠道）
- 供应链合作（海外供应商、物流伙伴）
- 学术交流合作（联合培养、学者互访）
- 资本合作（合资公司、股权投资）

**维度C：资源类型**
- 协议类：MOU、合作协议、框架协议
- 组织类：国际组织、行业协会、政府机构
- 人员类：外籍专家、国际顾问、海外校友
- 平台类：海外研发中心、联合实验室、创新中心

### 1.2 范围界定决策树

```
开始 → 是否为首次梳理？
  是 → 选择集团级 + 全领域 + 全类型
  否 → 是否为季度更新？
    是 → 选择部门级 + 上次更新领域 + 新增/变更资源
    否 → 是否为专项梳理？
      是 → 选择项目级 + 指定领域 + 指定类型
      否 → 执行全面复核
```

### 3.2 协议状态分级定义

| 状态级别 | 定义 | 判定标准 |
|----------|------|----------|
| 活跃 | 当前有效且正在执行 | 协议在有效期内，且有明确的执行活动记录 |
| 休眠 | 当前有效但无执行活动 | 协议在有效期内，但超过6个月无任何执行活动 |
| 即将到期 | 有效期剩余不足3个月 | 协议到期日距当前日期<90天 |
| 已过期 | 超出有效期且未续签 | 协议到期日超过当前日期，且无续签文件 |
| 已终止 | 提前终止或作废 | 有正式终止协议或双方确认函 |
| 待启动 | 已签署但未开始执行 | 协议已签署，但计划启动日在未来 |

### 3.3 信息核验机制

**第一层：自动核验（系统完成）**
1. 格式校验：检查必填字段是否完整，日期格式是否正确
2. 逻辑校验：合作起始日期不能晚于终止日期
3. 重复检测：通过资源名称+合作机构名称+起始日期判定重复

**第二层：人工核验（执行人员完成）**
1. 交叉验证：同一资源在不同数据源中的信息是否一致
2. 电话确认：对关键资源（P0级别）进行电话核实
3. 文件核对：对比原始协议/合同文件与录入信息

**第三层：专家核验（业务主管完成）**
1. 价值评估：判断资源是否具有持续合作价值
2. 风险提示：标注可能存在法律或合规风险的资源
3. 分类确认：确认资源分类是否准确

### 5.3 敏感信息脱敏规则

**脱敏等级定义**

| 等级 | 定义 | 示例 |
|------|------|------|
| Level 0 公开 | 可对外公开的信息 | 合作机构名称、合作领域 |
| Level 1 内部 | 仅限公司内部查看 | 联系人姓名、联系方式 |
| Level 2 机密 | 仅限特定岗位查看 | 合同金额、技术细节 |
| Level 3 绝密 | 仅限高管和法务查看 | 敏感条款、争议记录 |

**脱敏操作指南**

```python
# 脱敏处理示例代码
def desensitize_data(data, level):
    """
    根据敏感等级对数据进行脱敏处理
    level: 0-公开, 1-内部, 2-机密, 3-绝密
    """
    import re
    
    desensitized = data.copy()
    
    if level >= 1:
        # 联系人姓名：保留姓氏，名字用*代替
        desensitized['联系人'] = re.sub(r'(?<=[\u4e00-\u9fa5])[\u4e00-\u9fa5]', '*', data['联系人'])
        # 手机号：保留前3后4
        desensitized['电话'] = re.sub(r'(\d{3})\d{4}(\d{4})', r'\1****\2', data['电话'])
        # 邮箱：用户名部分脱敏
        desensitized['邮箱'] = re.sub(r'(^[^@]+)', lambda m: m.group(1)[:2] + '***', data['邮箱'])
    
    if level >= 2:
        # 金额：保留整数部分，小数用*代替
        desensitized['合作金额'] = re.sub(r'(\.\d+)', '.***', str(data['合作金额']))
        # 协议编号：保留前4后4
        desensitized['协议编号'] = data['协议编号'][:4] + '****' + data['协议编号'][-4:]
    
    if level >= 3:
        # 敏感条款：直接替换为【机密信息】
        desensitized['敏感条款'] = '【机密信息，需授权查看】'
        # 争议记录：直接替换为【存在争议】
        desensitized['争议记录'] = '【存在争议，需法务确认】'
    
    return desensitized
```

## 第六章 维护机制

### 6.1 动态更新频率

| 更新类型 | 触发条件 | 更新频率 | 执行人 |

### 6.3 维护流程SOP

**SOP-001：新增资源录入**

```
开始 → 业务部门签署新协议
     → 业务对接人在5个工作日内填写《新增资源录入表》
     → 提交至执行人员邮箱
     → 执行人员在2个工作日内完成格式校验
         → 格式正确：进入数据核验
         → 格式错误：退回修改
     → 执行人员完成数据核验
         → 核验通过：进入质量审核
         → 核验不通过：联系业务对接人确认
     → 质量审核员完成审核
         → 审核通过：入库并通知业务部门
         → 审核不通过：退回执行人员修改
     → 结束
```

**SOP-002：状态变更处理**

```
开始 →
